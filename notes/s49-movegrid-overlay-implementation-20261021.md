## 2. 几何推导（本轮新确立，步骤 1 的前提）

覆盖层的格子对齐关系此前只写过「一个重制格点 = 两个原版逻辑格」，但**两套网格之间的偏移从未确立**。
本轮把它推出来，并用**两个互相独立的锚点**交叉验证：

| 锚点 | 内容 |
| --- | --- |
| 原版 BG2 的滚动寄存器 | `BG2HOFS = 240`、`BG2VOFS = 24`（`artifacts/s49-original-movegrid-frame-v1/io-00.bin`）⇒ 原版逻辑列 `c` 在屏幕 x = `(16c - 240) mod 256`，逻辑行 `r` 在屏幕 y = `16r - 24` |
| 原版移动范围透镜的形状 | 布局图里族 2（高亮）的格分布在原版逻辑行 3..9、列 0..11（+列 14）；换算成重制格点后是 7 行 × 6 列，**透镜的竖轴正好是「鸣人」所在格** |
| 重制侧 S49 部署 | 鸣人在重制网格 `(6, 7)`（`generated_battle_scenario_content.h` 里 scenario 14） |

⇒ 得到**固定偏移**（写在 `battle_range_ui_style.h`）：

```
原版逻辑列 = (2 * 重制格点列 + 10) mod 16      // 左边一格永远是偶数列 ✓
原版逻辑行 = (重制格点行 - 1) mod 16
```

验证 1：重制格点列 3 ↔ 原版列 0（屏幕 x = 16），格点列 6（鸣人）↔ 原版列 6（屏幕 x = 112），
而重制侧原版的**光标橙色块实测就在屏幕 x = 112..119** ✓
验证 2：重制格点行 7（鸣人）↔ 原版行 6，而原版透镜最宽的一行正是行 6 ✓
验证 3：重制格点列 3..8 ↔ 原版列 0..11，正好是原版透镜的横向跨度 ✓

⇒ **重制侧覆盖层与原版在同一屏幕位置**（这一点也被像素证据独立确认：基线录像
`step-20-A.png` 与原版 `step-19-A.png` 在 x = 0..111 的**逐像素完全相同**），
所以「保持屏幕空间格位、只换图块来源」是安全的。

### 6.2 代理已经**交叉验证**出来的几何事实（这批结论是可靠的，保存在这里）

1. 重制格点列 3 ↔ 原版列 0（屏幕 x = 16）；重制格点列 6（鸣人）↔ 原版列 6（屏幕 x = 112）；
2. 重制格点行 7（鸣人）↔ 原版行 6；原版透镜**最宽的一行正是行 6**；
3. 重制格点列 3..8 ↔ 原版列 0..11，正好是原版透镜的横向跨度。

⇒ **重制侧覆盖层与原版在同一屏幕位置**，所以「保持屏幕空间格位、只换图块来源」这个方向是对的。
⇒ 还有一个**独立的像素证据**：基线录像 `step-20-A.png` 与原版 `step-19-A.png`
在 **x = 0..111 逐像素完全相同** ⇒ **原版在 x < 112 处没有画任何覆盖层**
⇒ ⇒ **这直接解释了 13,338 为什么爆掉**：把整张烘焙布局图铺到整个可见区，
就会在原版本来是「什么都不画」的地方画上网格/受阻区/攻击范围区 ⇒ 多出上万像素的差异。
⇒ **⇒ 下一步该查的是**：原版 BG2 在**这一屏**上到底只画了哪几格
（而不是整张 32×32 布局图），以及布局图里那些格在原版屏幕上落在什么位置。
⇒ 可用的判别手段：把原版同帧收据里 BG2 的 1024 格逐格换算到屏幕坐标，
看**非空**的格子只有哪些 ⇒ 布局图是「全图」，但**只有一部分格子在屏上被画到**
（其余格子要么被滚出屏、要么其图块是纯背景色 256）。
