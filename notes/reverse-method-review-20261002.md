# 本会话逆向方法、效率与剩余范围复盘

本记录回答用户关于推进速度、方法和剩余内容的提问。只核对现有账本与证据，
不恢复 Goal、不修改完成规则、不运行新 ROM 实验、不改正式分类或 bank 声明。
复用固定输入清单与记录×字段分母重建的脚本模式；未启动子代理。

## 判断

原始输入固定、独立解析、TDD、真实构建重读和拒绝反例是必要的正确性保障。
主要效率问题是工作包的选择和粒度：多轮局部证明及证据维护，没有足够快地转成
完整消费者、完整资源族或完整 bank 的验收。应保留验证，调整探索及批量验收策略。

98.6071% 是 ROM 字节按现有规则分类的比例，不是游戏业务语义或开发工时完成度。
“完整逆向”与本项目最终验收范围也要分别报告：后者还包含编辑器、发布重建和硬件。
不能把这些内容隐藏在最后 1.39% 字节中，也不能不经授权删掉原完成条件。

## 可核对的耗时原因

1. 动画路径从 caller、callee 保存、writer、IRQ、对象生命周期推进到完整 renderer，
   得到了有限人工状态下的真实执行结果；但长回调重工作、跨帧、多对象、全部 writer
   和自然入口仍开放。继续增加同一人工域的样本不能自动闭合这些前提。
2. 旧证据的测试源码身份变化、旧绝对路径和控制采集不足，需要恢复输入及机器验真。
   这改善可复现性，却不新增 ROM 语义；应一次处理共同依赖，避免逐样本重新封存。
3. 部分 bank 合同正确标出覆盖边界，但四个候选单元没有闭合一个完整 bank。
   样本方法稳定后，应转共享消费者的批量矩阵，减少继续做同类单样本 wrapper。
4. 正式入账采用批量门槛，所以待入账成果和 canonical 增量不同；但延迟入账本身
   不能解释全部低收益。2,721B 也只占当前未知区的一小部分。

没有完整的逐操作成本归因，本记录不虚构“多少百分比时间浪费在验证上”。
上一答复的 300–1,000 小时是低置信度排期假设，未由任务级实测校准，不能作为交期。

## 剩余内容

### 仍未知的物理字节

实时账本：87,631B / 1,763 段。17 个至少 1KiB 的段合计 42,880B；其余
44,751B 分散在 1,746 段。未知数据的真实类型仍须证明，下面是研究方向，不是分类。

- 低地址混合文本／渲染命令脚本：例如 0x578C..0x7554（7,624B）和
  0x42AB..0x542E（4,483B）；缺少部分索引域、消费者或 opcode 语义。
- AI／单位配置与动态池：例如 0x53F89C..0x541368（6,860B）；初始化、继承、
  清理、别名和索引范围尚未形成完整生命周期证明。
- 动画 descriptor／sequence 与 RAM 标签混合资源：0x45832C..0x458794、
  0x12EE10..0x12F298；部分有消费者锚点，完整自然域和边界仍未闭合。
- 协程／调度恢复及代码续段：有间接目标、动态上下文、寄存器和 SP/LR 恢复依赖。
- 无已证明消费锚点的段及小洞：例如 0x54136F..0x542204；一次扫描没有命中
  不能说明未使用，也不能据此认领填充或 free space。

两包 2,721B 已有局部验收但未入总账，不另算新的未知字节；正式接入后才扣除。

### 已有结构、仍缺完整行为证明的资源与数据

正式矩阵为 22 个有效 bank、2,954 条记录；现有声明覆盖 23 条，不能解释成其余
记录毫无结构知识。25,543 是 schema 的记录×字段验收维度，含 derived/raw/重叠视图，
不是不同物理字段总数，也不是要启动 25,543 次模拟器。

- 地图、精灵、过场、菜单：完整资源选择、加载、别名与自然画面行为。
- 单位、成长、技能、战斗配置和位置：共享索引、writer、生命周期及字段影响。
- 文本与剧情：全部记录的 parser／控制流、实际消费者及内容修改后的行为。
- 音频：全部声音 ID 的选择器、descriptor、通道及播放路径。
- 存档：有效／空／损坏槽、长度、校验、保存后冷启动恢复。

正式完整 typed bank 尚为 0；四个部分 proposal 是可复验种子，不是完整 bank。

### 工具与最终产品验收

除字节覆盖外，六组固定门共 19 case：资源 round-trip 7、编辑器 round-trip 4、
逻辑修改 2、干净重建 3、模拟器回归 2、实体硬件 1。当前正式 covered case 集合为空。
局部资源批次和单场捕获已有成果，但不能替代这些完整案例。

## 建议的执行调整

1. 下轮选一个能闭合完整分母的工作包，优先小 bank 或已经贯通构建的完整资源族；
   开始前写清输入、缺失前提、完整输出和验收条件，避免继续串联微窗口。
2. 动态难点先从可恢复自然快照捕获实际访问与写入，取得新锚点，再用静态分析和
   独立验证解释边界；没有新锚点就搁置该路线。动态命中不能证明未命中部分不存在。
3. 共同消费者、解析器和资源族批量验证；TDD 与真实 CLI 集成保留，同一输入与版本
   的重复全局审计只在既有里程碑触发，不为每个样本重复执行。
4. 四类指标分别记录：正式未知字节、完整资源族、完整 bank、最终 case。
   测试数、轨迹数、收据数作为验证证据，不作为逆向完成量。
5. 至少取得两个同类完整工作包的实测成本后再更新剩余工期；硬件等待单列。

以上是用户所问的诊断和建议，没有改变正式验收政策或恢复开发授权。
