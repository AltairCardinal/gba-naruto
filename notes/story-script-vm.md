# 剧情脚本 VM（Story Script VM）

**日期**: 2026-10-20
**工具**: `tools/decode_story_script.py`、`tools/dump_story_text.py`
**状态**: ✅ 全场景静态验证通过（55 场景，0 问题）

---

## 0. 结论

游戏用一套**字节码 VM** 驱动剧情、战斗配置与条件事件。
本仓库此前完全没有这一层——只解出了 SJIS 文本块和渲染链，
不知道"哪段对白挂在哪个场景、谁说的、条件是什么"。

现在可以：

- 把 55 个场景的脚本全部解成节点图（**6184 行可读中文对白**）
- 解析战斗胜负条件、旗帜位、回合条件
- 把条件对白作为一等公民看待（可枚举、可改写）

## 1. 四张根表

每个场景最多四个根指针（u32 ROM 指针，按场景号索引）：

| 表 | 文件偏移 | 含义 | 场景范围 |
|---|---|---|---|
| before | `0x060C74` | 战前剧情脚本 | 1..55 |
| after | `0x060D54` | 战后剧情脚本 | 1..55 |
| logic | `0x060E34` | 战场事件逻辑 | 1..46 |
| events | `0x060EF0` | 战场事件表 | 1..46 |

实测 scene 1：before `0x08009F2E` / after `0x0800AEDC` /
logic `0x0804C64E` / events `0x0804C7FB`。

场景号 1..55 为剧情，1..46 同时也是战场（battle）与场景（story）两个编号空间。

## 4. 指令语义

标注说明：
**[证]** = 由原版说明文字/数据直接证实
**[推]** = 由操作数分布与上下文推断，尚未逐条验证

### 4.1 文本与显示

| op | 语义 | 证据 |
|---|---|---|
| 0x01 | 显示一段文字 | **[证]** 5942 处 |
| 0x20 | 显示一段带说话人的对白 | **[证]** 177 处 |
| 0x05 | 选择菜单的一项文字（3 行一组） | **[证]** 42 处 |
| 0x32 | 事件表项（战斗内事件入口） | **[证]** 400 处，负载为一个 ROM 指针 |
| 0x02 | 设置对话框：**[标志, 角色ID, 表情]** | **[证]** 2135 处；第 2 字节是角色ID，分布 鸣人432/佐助340/小樱397/卡卡西206，与姓名表一致 |
| 0x08 | 设置头像图：**[头像ID]** | **[推]** 5748 处；取值 1..44+，前 21 号与角色ID重合 |
| 0x03 | 旁白（清空对话框） | **[证]** 186 处 |
| 0x04 | 选择分支设置（4 字节） | **[推]** 754 处，总是紧跟在菜单文本前 |
| 0x06 | 二选一分支（两个目标） | **[证]** 42 处，与 0x04 配对出现 |
| 0x1B | 播放音乐：**[曲目ID, 0]** | **[证]** 356 处；曲目ID 取值 4/5/13 等，与 `editor/music.js` 的 1..18 曲目范围一致 |
| 0x19 | 特殊文本指令（双段文本） | **[推]** 160 处 |
| 0x1A | 跳转下一场景：**[场景号, 0]** | **[证]** 13 处 |

### 4.2 流程控制

| op | 语义 | 证据 |
|---|---|---|

| 0x07 | 无条件跳转 | **[证]** 44 处 |

### 4.3 战斗条件（logic / events 脚本）

| op | 语义 | 证据 |
|---|---|---|
| 0x34 (52) | 回合/相位条件：**[比较器, 目标回合, 相位, 指针]** | **[证]** 374 处 |
| 0x35 (53) | 复合条件：**[a, b, c, d, 指针]** | **[推]** 196 处 |
| 0x36 (54) | 指定人物在场：**[a, 阵营, 角色ID, d, 指针]** | **[证]** 213 处 |
| 0x37 (55) | 置/清标志位：**[模式, 标志号]** | **[证]** 196 处 |
| 0x38 (56) | 测标志位：**[a, b, 标志号, 指针]** | **[证]** 204 处 |
| 0x39 (57) | 配置(sub)匹配：**[a, 指针]** | **[证]** 26 处 |

**0x34 的比较器**（由第三方编辑器实现与原版数据共同确定）：
`0`=等于、`1`=不等于、`2`=大于、`3`=大于等于、`4`=小于、`5`=小于等于、`0xFF`=恒真。

**标志位占用**：原版脚本使用 0..11 与 127；新增事件可用 12..126。
（第三方编辑器据此实现；本仓库已确认原版确实在用 0xFF 与低位段。）

## 6. 正确性验证

`tools/decode_story_script.py` 走完 55 场景 4 张根表后：

```
=== issues: 0 ===
```

自校验包含两条硬条件：

1. **未知指令数为 0** —— 长度表覆盖了本 ROM 用到的全部指令。
2. **每个分支目标都必须落在指令边界上**（`validate()`）——
   任何一处长度算错，分支就会指向指令中间而被检出。
   47 个地图条目的 terrain 长度同样做了 47/47 穷举校验。

这两条同时成立，说明长度表不是"碰巧能走通"。

## 7. 使用方式

```powershell
# 单场景节点图
python tools/decode_story_script.py --scene 1

# 带原始字节
python tools/decode_story_script.py --scene 1 --raw

# 全场景统计
python tools/decode_story_script.py --all --stats --out build/story_scripts.json

# 可读剧本（含说话人）
python tools/dump_story_text.py --all --out build/story_text.txt --json build/story_text.json
```

`build/story_text.txt` 是 6184 行可读中文对白（按场景分组、带说话人姓名、
带 ROM 地址），可直接用于比对、翻译和续作取材。

## 8. 文本编码依赖

本 VM 的所有文本指令都依赖字形码解码，见
`notes/font-encoding.md`（自定义双字节字形码，**不是** Shift-JIS）。
