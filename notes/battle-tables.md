# 战斗数据表：胜负条件、任务文字、角色槽

**日期**: 2026-10-20
**工具**: `tools/extract_battle_tables.py`
**状态**: ✅ 静态验证通过

---

## 0. 结论

本仓库原先只知道地图表 `0x53D910`、角色模板 `0x54241C`、单位 ID 表 `0x53F298`。
**战斗的三张核心表此前完全没有定位**：

| 表 | 文件偏移 | 内容 |
|---|---|---|
| rules | `0x594758` | 胜负判定条件 + 条件说明文字 |
| missionIndex | `0x348DAC` | 任务文字索引 |
| missionTables | `0x59AA5C` / `0x59D214` / `0x59E920` | 任务标题 / 说明 / 提示 |
| actors | `0x5461C4` | 每场景 3 组配置 × 12 个角色槽 + 16 个地图物件 |

其中 **missionTables 的文本此前完全无人解出过**——现在能读出
"得到宝箱！/ 练习移动。鸣人站到宝箱之上就可以得到宝箱内的东西。" 这类原文。

## 1. 胜负条件表 `0x594758`

```
entry = 0x594758 + stage * 0xCC + sub * 0x44
  +0x00  u8    回合上限（turn limit）
  +0x04  组 0：4 条条件 × 8 字节   ← 胜利条件
  +0x24  组 1：4 条条件 × 8 字节   ← 失败条件
单条条件 8 字节：type u8, a u8, b u8, c u8, 说明文字指针 u32
```

- stage 1..46，sub 0..2（同一场景的三套配置）
- **组 0 = 胜利条件，组 1 = 失败条件**
  （由原版说明文字证实：组 0 是"打败了/保护了/开了"，
  组 1 是"大家被打败了/没能保护"）
- 有内容的条目：86 个（stage/sub 组合）

### 1.1 条件类型（原版语义，由说明文字直接证实）

| type | 语义 | 参数 | 原版说明文字样例 | 条数 |
|---|---|---|---|---|
| 1 | 击破敌方全部 / 我方全灭 | a=1 胜 / a=0 负 | "打败业头・冥头了" / "大家被打败了……" | 155 |
| 2 | 指定人物达成（存活或任务） | b=角色ID | "保护了达兹纳" "打败冒牌货鸣人了" | 11 |
| 3 | 指定人物状态 | b=角色ID | "没能保护达兹纳……" | 18 |
| 6 | 获得指定道具 | a=道具序号 | "仓库的门开了" "得到宝箱了" | 8 |
| 7 | 剩余体力比较 | a=0 我方 / 1 对方 | "我方剩下的体力比对方队伍多" | 16 |
| 8 | 击杀数比较 | a=0 我方 / 1 对方 | "我方的净胜数比对方多" | 16 |
| 9 | 收集物数量比较 | a=0 我方 / 1 对方 | "挖到了很多甘薯" | 6 |

**type 0 / 4 / 5 / 10 在原版中不存在。**
其中 **type 10（"到达指定位置并结束行动"）是第三方包新增的运行时扩展**，
需要在 ROM 里加 hook 才会生效——不能当作原版能力使用。

### 1.2 条件说明文字

每条条件都带一个 u32 指针指向说明文字（游戏内 Conditions 页显示）。
文字用字形码编码，见 `notes/font-encoding.md`。

## 2. 任务文字三表

```
索引：index = rom[0x348DAC + stage] + sub      (u8 表，每场景 3 条，步进 3)
文本：table[index * 4] → u32 ROM 指针 → 字形码文本
  0x59AA5C  任务标题
  0x59D214  任务说明
  0x59E920  任务提示
```

实测 `0x348DAC` 前 48 字节：
`0, 0, 3, 6, 9, 12, 15, 18, 21, 24, 27, 30, 33, 36, 39, 42, 45, 48, …`

stage 40 的三条配置解出：

| sub | 标题 | 说明 | 提示 |
|---|---|---|---|
| 0 | 得到宝箱！ | 练习移动。<br>鸣人站到宝箱之上<br>就可以得到宝箱内的东西。 | 拿到宝箱内伊鲁卡老师给的礼物后<br>任务就算结束 |
| 1 | 使劲打木叶丸吧！ | 攻击练习。<br>用「忍者组合拳」来打木叶丸。<br>不能使用忍术和忍具。 | 使木叶丸的体力减到０后<br>战斗就算结束 |
| 2 | 打倒傀儡人偶！ | 战斗练习。<br>和一个傀儡人偶作战。 | 把傀儡人偶打倒后战斗就算结束 |

共 138 个 stage/sub 条目。

## 3. 角色槽表 `0x5461C4`

```
base = 0x5461C4 + stage * 0x1AAC + sub * 0x8E4
  +0x00 .. +0x03  头部
  +0x04 + i*0xB8  12 个角色槽（i = 0..11）
  +0x8A4          16 个地图物件 × 4 字节（type, target, x, y）
```

角色槽字段（0xB8 = 184 字节）：

| 偏移 | 含义 |
|---|---|
| +0x00 | 角色ID（0 = 空位） |
| +0x01 | 阵营（0 我方 / 1 敌方） |
| +0x02 | X |
| +0x03 | Y |
| +0x04 | 朝向 |
| +0x0F | 等级 |
| +0x10.. | 技能 / 属性模板（从角色模板 `0x54241C` 复制） |

实测 stage 40 sub 0：slot0 = 漩涡鸣人，side 0，x=4，y=4，level 1
—— 与本仓库既有结论"单位槽 1 坐标 (4,4)"一致。

有内容的 stage/sub 条目：85 个。

### 3.1 地图物件类型

`+0x8A4` 处 16 条 4 字记录：`type, target, x, y`。
type 语义（第三方编辑器给出，需我们复核）：

| type | 含义 |
|---|---|
| 0 | 空位 |
| 1 | 忍具（target → 忍具名表 `0x599634`） |
| 2 | 强化素材（target → `0x5A7E8C`） |
| 3 | 专属修行卷轴 |
| 4 | 认识卡（人物图鉴） |
| 5 | 机关宝箱 |
| 6 | 特殊机关（卷轴外观） |
| 7 | 剧情物件 |

## 4. 与既有笔记的关系

- 本仓库 `notes/battle-config-format.md` 里的"战斗场景配置表 `0x53D910`"是**地图表**，
  与这里的 rules / mission / actors 是**三张不同的表**，此前被混在一起谈。
- `0x5461C4` 本仓库已知（角色模板 / 编成），本次确认了它同时是
  **运行时战斗角色槽表**（stage×sub×12 槽），两处共用同一段数据区。
- 胜负条件表是判定"任务目标"的关键：游戏内 Conditions 页显示的文字就来自它。

## 5. 使用方式

```powershell
# 概览 + 条件类型分布
python tools/extract_battle_tables.py

# 单场景明细
python tools/extract_battle_tables.py --stage 40

# 全量 JSON
python tools/extract_battle_tables.py --json build/battle_tables.json
```

输出：`build/battle_tables.json`（rules / missions / actors 三段）。
