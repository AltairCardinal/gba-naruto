# 规格：载入 ROM 是编辑器的前置操作（第十一轮）

> 起因（用户原话）：
> **「把载入ROM做成编辑器的前置操作：需要载入ROM时，先只弹出窗口要求用户选择载入内置ROM或者上传本地ROM，
> 不允许直接关闭这个窗口或是透过窗口操作下方内容」**
>
> 方法与结果见 `notes/rom-editor-20261021.md` §6.15。

---

## 1. 现状（有据）

载入 ROM 现在是**顶栏的一个可选按钮**：

| 入口 | 代码位置 | 问题 |
|---|---|---|
| 「载入 ROM」（`<label for="rom-file">`） | `index.html:32-35` | 直接弹系统文件选择框 |
| 「载入内置 ROM」（`#btn-load-bundled`） | `index.html:36-37` | 直接开始下载 |

后果有三条：

1. **两条路径各走各的**：本地文件走 `loadRomFile()`（`app.js:410`），
   内置 ROM 走 `loadBundledRomAction()`（`app.js:641`）—— 两条代码各写了一遍
   「设 `state.rom` / 算 sha256 / 比基线 / 提示 / 重绘」。
2. **作者可以完全不看 ROM 就开始编辑**，直到点「构建 ROM」才被一句
   `toast('请先载入原版 ROM', 'error')`（`app.js:321`）挡住；
   「原始字节」域则是渲染出一句 `请先载入原版 ROM` 就结束了（`modules/raw.js:19`）。
   ⇒ **「载入 ROM」这件事发生在编辑流程的中途，而不是开头。**
3. **没有统一的选择界面**：两个按钮摆在一排，作者得自己判断哪个是自己要的。

### 1.1 为什么 ROM 值得当置

- 构建 ROM 的基底就是原版 ROM（`buildRom(state.pack, state.rom)`，`app.js:329`）；
- 「原始字节」域改的是 ROM 的字节，没有 ROM 就没有字节可改；
- 内容包的基线 sha256 记在 `pack.rom.sha256`，载入的 ROM 要跟它对得上，
  对不上就说明**基底选错了**，越晚发现越亏。

## 2. 规格

### 2.1 门禁（gate）

**载入 ROM 变成一个「门禁」**：一个**不可关闭**的窗口，编辑器在它后面待着。

| 判据 | 要求 |
|---|---|
| **出现时机** | 需要 ROM 时。启动时（内容包装好之后）必现；点「构建 ROM」而没有 ROM 时再；「原始字节」域没有 ROM 时也现 |
| **窗口里只有两个选择** | ① **载入内置 ROM**（编辑器自带的压缩副本，不走系统文件框）② **上传本地 ROM**（选一个 `.gba` 文件） |
| **不可直接关闭** | 没有 × 按钮；Esc 无效；点遮罩无效；没有「取消 / 稍后再说」 |
| **不能透过窗口操作下方内容** | 遮罩覆盖整个视口；下方的应用外壳置 `inert`（不可聚焦、不可点击、不可 Tab 进去）；焦点锁在窗口内 |
| **唯一的出路** | 成功载入一个 ROM ⇒ 窗口自动关闭，编辑器继续 |
| **失败不出戏** | 载入失败**留在窗口里**报错（不弹 toast、不关窗），两个按钮恢复可用，可以换一条路重试 |

> 「不可关闭」是**用户明确要求的**：作者不能带着「没 ROM」的编辑器干别的，
> 否则又要到构建那一步才撞墙。

### 2.2 什么时候可以关

只有一种情况窗口可以关：**ROM 已经载入了**（即「载入 ROM」不是前置操作，
而是作者主动要换一个基底）。这时窗口是可关的（Esc / 遮罩 / 取消按钮）。

判据一句话：**「需要载入 ROM 时不可关；不需要载入 ROM 时随你关。」**

### 2.3 与既有代码的关系

- 两条载入路径（内置 / 本地）**收敛成同一个门禁里的两个按钮**；
  顶栏的两个按钮合并成一个「载入 ROM」（打开门禁）。
- 载入成功的**后续动作**（设 `state.rom` / `state.baseRom` / 算 sha256 /
  比基线 / 标脏 / 重绘）合并成一个函数 `applyLoadedRom()`，两条路径共用。
- 门禁是**独立模块** `rom-editor/js/romgate.js`：
  它只管「窗口长什么样、能不能关、焦点锁不锁」，
  「ROM 从哪来」由调用方通过回调给进来（避免与 `app.js` 循环依赖）。

## 3. 门禁的实现要点（易踩的坑）

1. **`inert` 的范围**：`inert` 要加在**应用外壳**（`#app-shell`）上，
   不能加在 `<body>` 上 —— 隐藏的文件输入框（`#rom-file`）在 `<body>` 里、
   在外壳**之外**，否则 `input.click()` 会被 `inert` 吞掉，
   「上传本地 ROM」会**点不开文件选择框**。
2. **焦点**：打开时把焦点放到窗口里第一个按钮；
   监听 `focusin`，焦点一旦落到窗口外就拉回来（`inert` 之外的第二道保险，
   因为老浏览器没有 `inert`）。
3. **Esc**：不能只 `preventDefault()`，还要 `stopPropagation()` ——
   否则页面里别的 Esc 处理器（比如关面板）会被一起触发。
4. **遮罩**：遮罩是 `position: fixed; inset: 0`，点它只是落到遮罩上，
   **不会**落到下面的内容上；再叠一层 `inert` 才能连 Tab 都过不去。

### 4.1 实机（内置浏览器 + `serve.mjs`）

| 判据 | 证据 |
|---|---|
| 门禁升起、只有两个选择 | 门禁文本只有「载入 ROM / 载入内置 ROM / 上传本地 ROM」 |
| Esc 关不掉 | 按 Esc 后门禁标题仍在 |
| 外壳真的被封 | 真实 DOM 里 `#app-shell[inert] .nav-item` 命中 |
| 点不到下面的内容 | 点侧边栏「剧情与对白」，面包屑仍是「总览 / 概览」（视图没变） |
| 内置 ROM 那条路启动了 | 服务器日志出现 `content/base-rom/rom-loader.html` + `base-rom.bin.gz` |

> 这个内置浏览器每 4–5 分钟就把标签页重载一次，6 MB 的下载被反复打断，
> 所以**「下载完成 → 门禁关闭」这一步没能在实机里看到**；
> 它由 G7（无头）覆盖。这是环境的病（`verify_views.mjs` 的注释里记着同一件事），
> 不是本轮代码的问题。

### 4.3 补记（2026-10-24，第二十二轮）：门禁的契约没错，是**接线**错了

第二十二轮查出：门禁里点「载入内置 ROM」，弹窗正常关掉，
但编辑器里**没有 ROM**（`state.rom` 一直是 `null`）。

- **门禁本身没违约**：G7「载入成功 ⇒ 关窗 + 把 ROM 交回调用方」是**做到了**的 ——
  字节确实交回了 `openRomGate()` 的 promise。问题出在**调用方**：
  `app.js::requestRom()` 的两条回调里，**内置那条只取字节、忘了调 `applyRom()`**，
  而 `boot()` 里 `await requestRom(...)` 的返回值又被丢掉了 ⇒ 没有任何人写状态。
- 本规格 §2.3 早就写了「载入成功的**后续动作**……合并成一个函数，两条路径共用」，
  **实现时只接上了本地文件那条** ⇒ 规格是对的，实现漏了一半。
