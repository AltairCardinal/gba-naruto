# 规格：素材与资源域 —— 接线总表 / EWRAM 内存条带 / 载荷类型判定

> 来源：子代理 `bg_8066b4be`（素材与资源域重设计）的产出，经主代理核对后定稿。
> 本文是**实现的依据**，不是聊天记录。

## 0. 主代理的定论（规格里原本留了问号）

**载荷类型信息由内容包提供，运行时用已载入的 ROM 兜底。**
即 `tools/export_content_pack.py` 在导出时把每个指针目标的格式判定写进内容包
（结构级 `ptr_targets` 或记录级 `ptr_info`），界面直接读；
运行时若 ROM 已载入，用实时字节覆盖，并把两者不一致的情况标出来
（这本身就是「内容包过期」的信号，值得让作者看见）。
理由：编辑器的一条卖点是「不载入 ROM 也能编辑」，载荷类型属于内容包该带的语义，
不该只在运行时才有。

## 1. 今天的操作流（问题基线）

以「把某张图的指针换到别处」为例：

1. 侧边栏点「素材与资源」→ 落到 `renderAssets`（`modules/assets.js:9`）。
2. 域首页只有一张推荐卡「按指针表改 / 去改指针表」（`assets.js:42-49`），点它只进**数据指针表 A**；
   表 B、图块记录表、WRAM 分配表只能从「本域可编辑内容」表格里点那一行的小「编辑」按钮。
3. 进表后左列是指针的十六进制（`editors.js:240` → `formatHex32`），点行开右侧详情。
4. 详情里指针是一个**十进制数字框**（`fields.js:394-402` 通用分支；实测 A 表第 0 项显示 `140114312`），
   底下提示行只有「文件偏移 0x59F988」。
5. 想复制别的指针，只能从列表里逐个打开别的记录，把那一格的数字**手抄**过来；
   想确认「这个地址是哪个资源」，只能自己拿地址去「原始字节」模块用「跳转」框手输。

「看 79 条图块资源记录」今天更糟：详情是**9 个竖排指针输入框**（6 个图块 + 3 个脚本），
列表只有「图块指针0 / 脚本指针0」两列 79 行。

「改系统给某个子系统分多少内存」今天最朴素：详情两个数字框（起始地址 33697328、大小 4732），
没有地址范围校验，也看不出内存段之间是挨着的还是有空隙。

| F6 | **列表搜不到指针** | `editors.js:91-93` 搜索的是 `record.values` 的**十进制**字符串；列表显示的却是十六进制 | 作者照着列表抄 `0x0859F988` 去搜索框，命中 0 条 |
| F7 | **WRAM 地址没有任何范围校验** | 详情走 `fields.js:394-402` 的通用 u32 分支；而 `tools/import_battle_config.py:846-847` **是有**校验的（必须落在 0x02000000–0x0203FFFF） | 作者把地址填成 `0x05000000` 编辑器照单全收，构建出来的是坏 ROM，构建报告也不会报错 |
| F8 | **面板头写着「尚无写回路径」，但编辑器其实会写回** | `editors.js:119` 原样上屏 `structure.verification`；而通用构建器 `rom.js:102-121` 遍历**所有** `pack.structures` 写回 | 作者看到「尚无写回路径」会以为改了没用，干脆不改。那句文案指的是仓库里没有**专用导入工具**，不是编辑器不写回 |
| F9 | **「一览」是 129 行不可搜的十六进制平表，且折叠着** | `assets.js:20-40` | 作者想知道「哪个槽指向 0x0859F988」，得展开再一行行扫 |
| F10 | **这一域永远没有「被谁引用」** | `xref.js:33-49` 只沿 `field.relation` 反查；本域字段没有 relation | 改一个指针会影响多少处，界面一个字都不提 |

**顺带一个会改变设计的实测结论**：本域的载荷**不全是 LZ77**。
A 表 46/46 目标是非压缩原始数据，B 表 79 个非 LZ77 + 4 个 LZ77，
图块记录里 `tile_ptr_0/1/3/4` 与 `script_ptr_0/1` 是 LZ77（75/79 条），
而 `tile_ptr_2`、`tile_ptr_5`、`script_ptr_2` 指向的根本不是压缩块。
所以**不能**在界面上写一句「这些指针都指向 LZ77 载荷」——必须逐个指针现判。

**结论横幅文案（逐字）**

> **结论：改指针能换资源，载荷本身动不了。**
> 这一块的指针决定「用哪一份资源」。指向的图块、调色板、脚本是 ROM 里已经压好/排好的字节，
> 编辑器能改的只有「用哪一份」——仓库里只有纯字面量 LZ77 编码器
> （`tools/lib/lz77.py::compress_literal`），没有与原版逐字节一致的压缩器，

> 想改画面内容：去「原始字节」按字节改（那里是显式补丁，构建时按「原字节必须匹配」写回），
> 或者把指针接到另一份现成资源上。

```

  指针   [ 0x0859F988            ]  ← 十六进制框，可粘贴十进制

▾ 改成
  [ 从本表其它项复制… ▾ ]  [ 从另一张指针表复制… ▾ ]  [ 手动填地址 ]
  「从本表其它项复制…」下拉项示例：
    #12  0x0859F988 · 未压缩原始数据
    #21  0x0859FA18 · 未压缩原始数据
    #34  0x085A0044 · 未压缩原始数据

▾ 这一项改动的后果
  原来指向 0x0859F988，改成 0x0859FA18 之后，游戏会改用另一份资源；
  载荷本身一个字节都不会变。
```

点击序列：域首页点卡片① → 接线表 → 搜 `59F9` 或点行 → 右侧详情 →
「从另一张指针表复制…」→ 选一项 → 立即写入 → 指针框内容变成新值且**保持焦点**；
提示行变成「原值 0x0859F988 → 现在 0x0859FA18 · 目标 ROM 0x5A15C0」；
该行标「已改」；表尾「已改 1 条」；顶栏徽标 +1；toast「已改：数据指针表 A #12 的指针」。
填非法地址 → 当场拒绝，toast「指针必须为 0 或落在 0x08000000–0x085FFFFF 内」，输入框还原原值。

### 3.4 任务 ③：改某个子系统分到多少内存

顶部结论横幅（WRAM 版，逐字）：

> **结论：这张表决定每个子系统分到多少 EWRAM，编辑器不会替你判断对错。**
> 10 行里只有 **7 段**不同的内存：#0 / #1 / #3 是同一块（战斗状态结构 0x02022E30，4,732 字节），

## 4. 控件类型映射

| 字段 / 元素 | 类型 | 现在的控件 | 改后的控件 | 反馈与提示 |
|---|---|---|---|---|
| `ptr`（非空） | ROM 指针 | 通用十进制数字框（`fields.js:394-402`） | **十六进制指针框**（宽度 ~150px、自动大写、允许粘贴十进制）+ 目标说明行 + 「从…复制」下拉 + 「跳到原始字节」 | 行下：`ROM 0x59F988 · 未压缩原始数据`；越界当场拒绝 |
| `ptr`（值为 0） | 空指针 | 同上 | 同上 + 灰底标记 | `空指针（原版就是空的）` |
| `ptr` 目标摘要 | 派生 | 无（只给文件偏移） | 三态标签：`LZ77 块（解压后 N 字节）` / `未压缩原始数据` / `空指针`；ROM 未载入时显示「未载入原版 ROM，无法判断载荷类型」 | 见 §0 定论 |
| `wram_addr` | u32 地址 | 通用数字框，无范围校验 | **十六进制框** + 范围提示 | 越界拒绝：`EWRAM 地址必须落在 0x02000000–0x0203FFFF` |
| `alloc_size` | u32 字节数 | 通用数字框 | 数字框（十进制主、hex 副）+ **邻接/覆盖实时告警** | `⚠ 会压到 #2 的前 268 字节` |
| `tile_ptr_0..5` | 重复槽位 | 6 个竖排输入框 | **6 行槽位表**（每行：槽号 / 指针 / 目标） | 复用 `slots.js::renderArrayTable` |
| `script_ptr_0..2` | 重复槽位 | 3 个竖排输入框 | **3 行槽位表** | 同上 |
| `head` / `mid` / `raw_34` | 未解码 hex | 折叠组里的 hex 框 | 折叠的 hex 区，标题写「未解码 32 字节 · 原样保留」+ 每段单独 `↺` | 不改字节时提示「未改动的字节会原样写回」 |
| 指针表整表 | 表 | 通用记录表 | **接线表**（+ 目标列、同址列） | 目标列随指针改动实时刷新 |
| WRAM 整表 | 表 | 通用记录表 | **记录表 + EWRAM 内存条带** | 条带随改动实时重画 |
| 域首页「改法」列 | 派生 | 一律「直接改」 | 结论式三选一 | 见 §3.1 |
| `verification` 上屏 | 元数据 | 原文「尚无写回路径」 | 改为：`L1 结构已证明 · 写回：编辑器通用路径（构建时写回这条记录的 4 字节）` | 必须区分「仓库没有专用导入工具」与「编辑器不写回」 |

## 6. 验收标准（可断言）

1. 打开「素材与资源」域首页，第一屏必须出现含「改指针能换资源」与「载荷本身动不了」的结论横幅；
   页面渲染出的文本中**不得出现** `**` 字面量。
2. 在「数据指针表 A」记录 #0 的详情里，指针输入框显示的必须是 `0x0859F988`（不是 `140114312`）；
   把它改成 `0x0859FA18` 并提交后，该记录 `pack.recordBytes` 的前 4 字节必须等于 `18FA5908`（小端），
   且顶栏「已改动」计数 +1。
3. 在接线表里搜索 `0x0859F988` 必须命中 A 表 #0 一行；搜索 `140114312` 必须命中**同一行**。
4. 打开「图块/精灵资源记录表」任意一条记录，详情里的指针控件必须是**6 行 + 3 行两张表**
   （共 9 行、每行带目标摘要），而不是 9 个竖排输入框。
5. 打开「WRAM 分配表」，页面上必须出现一条 EWRAM 内存条带，条带上的**不同内存段数必须等于 7**，
   `#0 / #1 / #3` 必须被合并标注为同一段；
   把 #0 的分配大小改成 5000 时，界面必须给出「会压到 #2（从 0x020240AC 开始）的前 268 字节」的警告文本。
6. 越界必须当场拒绝且不写入：指针框输入 `0x09000000` → toast
   「指针必须为 0 或落在 0x08000000–0x085FFFFF 内」且记录值不变；
   WRAM 地址框输入 `0x05000000` → toast「EWRAM 地址必须落在 0x02000000–0x0203FFFF」且记录值不变。
