# 规格：剧情路线域 —— 一屏一关的「路线工作台」

> 来源：子代理 `bg_d0365711`（剧情路线域重设计）的产出，经主代理核对后定稿。
> 本文是**实现的依据**，不是聊天记录。

## 0. 主代理的两条定论（规格里原本留了问号）

1. **路线工作台就地改任务文本与奖励**，不做「只读汇总 + 跳转」。
   理由：写回通路已经存在（`pack.setText` / `pack.setValue` / `pack.setScriptOperand`），
   `battle.js` 里已有「关卡视图里就地改文本」的先例。作者在一屏内改完，
   不用跳去别的域再自己算下标。
2. **`0x16` 操作数显示为 `0 · 场景 0`**（保守文案）。
   仓库只证明了它「切到 after 表并把场景号写进 `state[0x1A]`」
   （`notes/story-vm-opcodes-20261020.md:134`），**没有证明 `0` 等于「留在本关」**。
   说明行必须写「48 处里 47 处是 0」，不得替仓库下结论。

## 1. 今天的操作流（问题基线）

侧边栏「剧情路线」→ 域首页（一张「按关卡改 / 46 关的完整一环」卡片 + 关卡下拉）
→ `#route/stage/40/0` 一屏从上到下依次是：

**剧情脚本**指针表 → **剧情路线（脚本里的「下一场景」）** 全游戏 63 行 → **本关剧情脚本里可改的操作数** →
**任务文本** 3 行只读 → **本关奖励** 3 行只读。

改任务标题要回域首页 → 「任务标题表」→ 通用文本表编辑器（112 行，第一列写「条目 103」）→
靠搜索或翻页找到那一行 → 点行 → 右侧详情文本域 → 改 → 失焦保存。

改本关奖励要去侧边栏「道具」→ 奖励表 → 通用结构表编辑器（112 行，按金币/强化点/等级门槛三列）→
翻到第 103 行 → 右侧详情改 24 字节里的字段。

## 3. 重设计后的布局（第 N 关的「路线工作台」）

```
┌ 面包屑：总览 / 剧情路线 / 第 40 关 ──────────────────────────────────┐
│ [← 上一关]  第 40 关 ▾(1–46)  [下一关 →]   缩略：●─●─●─◆─●   [整条路线总览] │
│ 本关已改 3 处（任务 1 · 奖励 2 · 下一场景 1）                            │
├───────────────────────────────────────────────────────────────────────┤
│ ① 路线走向                                                              │
│   出边：本关的 2 条  | 来源剧本 | 指令 | 走向 | 目标(可点) | 相位 | ROM  │
│   入边：谁会跳到本关                                                     │
│   「本关的下一场景」：下拉（不是裸数字框）                               │
│   ▸ 一览（全部 63 条路线边，默认折叠）                                   │
├───────────────────────────────────────────────────────────────────────┤
│ ② 任务文案（标题 / 说明 / 提示）                                         │
│   子任务 | 标题 | 说明 | 提示   —— 三列都是可直接改的输入框               │
│   行脚注：文本表下标 #103 · 同时是第 41 关子 1 · 这段字被 28 处共用        │
├───────────────────────────────────────────────────────────────────────┤
│ ③ 本关奖励 │
│   子奖励 | 金币 | 强化点 | 等级门槛 | 掉落(8 位 × 类别/物品)              │
│   行脚注：奖励表 #103 · 同时是第 41 关子 1 [在道具域打开这一条]      │
└───────────────────────────────────────────────────────────────────────┘
```

### 3.1 文案

- **域首页主卡**：标签「按关卡改」；标题「46 关的完整一环」；
  说明「一屏看全：战前剧情 → 战场 → 战后剧情、任务文案、奖励。」按钮「打开第 1 关」；
  第二张卡「整条路线总览」按钮「看整条路线」。
- **关卡条**：`← 上一关` / `下一关 →` / `整条路线总览`；计数区「本关已改 3 处」；未改时「本关还没改过」。
- **① 区标题**「路线走向（剧情脚本里的「下一场景」）」；说明行
  「0x16 = 转到 after 剧本并记住下一场景；0x1A = 直接推进路线游标。这些操作数是定宽的，改它们不会移动任何字节。」
  ——**不许写「路线不在任何表里」这种自夸句**，改成「路线边不在表里，它们是剧情脚本里的两条指令」。
- **出边表格头**：`来源剧本 | 指令 | 走向 | 目标 | 相位标志 | ROM 地址`。
  「走向」取值：`0x16` → 「转到 after 剧本」；`0x1A` → 「推进路线游标」。
  「目标」取值：`第 2 关 · after 剧本` / `第 45 关 · after 剧本`，**可点，跳到那个关卡**；
  目标场景没有 after 剧本时写「第 N 关 · 无 after 剧本」。
- **「本关的下一场景」下拉**：标签「下一场景 id」；选项 `0 · 场景 0`、`2 · 第 2 关 · after 剧本`…
  （只列 `story_after_root` 里指针非空且落在 1..55 的场景，按关卡号升序）；
  当前值不在表内时补一项 `N · 当前值（该场景没有 after 剧本）`。
- **相位标志下拉**（`0x1A` 第二个操作数）：`0 · 普通推进` / `非 0 · 带相位（state[0x18] = 标志+1）`。
- **② 区标题**「任务文案（标题 / 说明 / 提示）」；说明行
  「每关 3 个子任务，文本表下标 = 任务索引表[关卡] + 子编号。文本由指针表驱动，改长会在构建时重定位并改写指针。」
- **空值文案**：槽位是全角空格时显示 `（全角空格）`，不是空白格。
- **③ 区标题**「本关奖励」；说明行
  「任务索引表给出该关三个奖励在奖励表里的下标起点。奖励表每条 24 字节：金币、强化点、等级门槛，以及 8 个掉落位（类别 + 物品 id，0 表示列表结束）。」
- **错误文案**：越界场景号 → 「场景号只能是 0–55，第 56 号没有剧本。」；
  字库缺字 → 「字库里没有这些字：X」；
  共用字节 → toast 追加「这段字被 28 处共用，已一起改」；
  任务索引表改动前 → 二次确认「改这一格，第 40 关就会改用 #104 的文案和奖励。要继续吗？」。
- **入边区空状态**：「还没有别的关卡跳到本关——本关靠顺序推进到达。」

## 4. 控件类型映射

| 字段 / 东西 | 数据类型 | 控件 | 校验与反馈 |
|---|---|---|---|
| 下一场景 id（`0x16` / `0x1A` 操作数） | u8 场景号 | **下拉**：选项 `N · 第 N 关 · after 剧本`（只列有 after 剧本的场景）+ 当前值兜底项 | 越界提示「场景号只能是 0–55」；改后立即写回 + toast 带 ROM 地址 |
| 相位标志（`0x1A` 第 2 操作数） | u8 | **下拉**：`0 · 普通推进` / `非 0 · 带相位` | 同上 |
| 路线边的目标 | 只读 | 表格里的**链接**（`.xref-link` 同款） | 点击跳 `#route/stage/N` |
| 任务标题 / 说明 / 提示 | 文本（指针表驱动，可变长） | **单行输入框** `.text-input-inline`（沿用 `battle.js:547`） | 缺字拦截、字节计数、可变长提示；共用时行脚注写明「被 N 处共用」 |
| 文本槽位归属 | 只读 | 行脚注「文本表下标 #103 · 同时是第 41 关子 1」 | 由 `xref.js::missionIndexOwners` 计算 |
| 奖励 金币 / 强化点 / 等级门槛 | u16 | 数字输入框 | 按 `fields.js::valueRange` 校验 0–65535，越界 toast 不截断 |
| 奖励 掉落位 × 8 | `array=slots`（category + item_id） | **两张小表并排**：复用 `slots.js::renderArrayTable`；类别=下拉、物品=下拉（`field.relation kind=by_category`，显示名字） | 改类别后物品下拉须重绘（需要 refresh 钩子） |
| 奖励行归属 | 只读 | 行脚注「奖励表 #103 · 同时是第 41 关子 1」+ 按钮「在道具域打开这一条」 | 跳 `#items/structure/reward_table/103` |
| 任务索引表 `value` | u8 | 数字输入框 + **改前二次确认** | 确认文案写清「本关会改用哪个槽位」 |
| 全游戏 63 条路线边 | 只读 | 折叠区 `<details>`「一览（全部 63 条路线边）」 | 默认折叠 |

## 5. 要改哪些文件

- `rom-editor/js/modules/route.js` — **主改**。`renderStage` 重写成「路线工作台」：
  ① 关卡条（上一关/下一关/关卡下拉/缩略路线/本关已改计数/整条路线总览按钮）；
  ② 路线走向区拆成「本关出边」「谁会跳到本关」两张表 + 全局一览折叠；
  ③ 「下一场景」「相位标志」改下拉；
  ④ 任务文案区改成 3 行 × 3 列可编辑表 + 归属/共用脚注；
  ⑤ 本关奖励区改成就地可编表（金币/强化点/门槛 + 复用 `slots.js::renderArrayTable` 的 8 个掉落位）+「在道具域打开这一条」；
  ⑥ 新增 `renderRouteGraph(container, ctx)`（`#route/graph` 整条路线总览）；
  ⑦ 键盘监听；⑧ 删掉 `route.js:129-132`、`152-155` 里那些自夸式说明句。
- `rom-editor/js/routing.js` — 支持 `#route/graph`（`parseHash` 加 `parts[1] === 'graph'`、
  `hashFor` 加 `kind === 'graph'`）；修 `routing.js:34` 的 `Number(parts[2]) || 1` →
  `Number.isFinite` 判断，让 `#route/stage/0` 正确解析为 0。
- `rom-editor/js/modules/common.js` — 把 `battle.js:445-452` 的 `openInTable` 与

  `common.js:144` 的「长度策略」列对结构表给真值（定宽写回 / 字节可改 / 文本可重定位），别再一律 `'—'`。

## 6. 验收标准（可机器核对）

1. **路线边按关卡过滤**：第 40 关的工作台里「本关出边」表只出现 `scene=40` 的边、
   「谁会跳到本关」只出现跳到 40 的边，两表每行都有可点的「目标」列；
   全游戏 63 条边收在默认折叠的 `<details>` 里。
2. **「下一场景」是下拉而不是裸数字**：第 40 关的控件是 `<select>`，
   至少有一个选项文案同时含场景号与关卡名（如 `2 · 第 2 关 · after 剧本`），
   且页面上**不存在**该操作数对应的 `<input type="text">`。
3. **任务文案就地可改且只改本槽**：把标题输入框（槽位 #103）改成任意文本并失焦后，
   `pack.textTable('mission_titles').records[103].text` 变为新文本，
   `records[104].text` **不变**，`pack.changedCount()` +1。
4. **奖励可就地改、且与道具域是同一份数据**：把子奖励 1 的金币改成 250 后，
   `pack.structure('reward_table').records[103].values.gold === 250`，
   且该记录与道具域打开的第 103 条是**同一个对象**；
   行尾「在道具域打开这一条」跳到 `#items/structure/reward_table/103`。
5. **跨关共用必须显式告知**：任务文案行与奖励行都必须出现「同时是第 41 关子 1」字样
   （由 `xref.js::missionIndexOwners` 计算）；被共用的那段字必须出现「被 N 处共用」提示。
6. **键盘与撤销**：焦点在关卡视图时按 `]` → URL 变为 `#route/stage/41/0`；按 `g` → `#route/graph`；
   改一次「下一场景」后按 `Ctrl+Z`，该操作数恢复原值且 `pack.changedPatchCount()` 回落。

## 7. 键盘表

| 键 | 行为 |
|---|---|
| `]` / `→`（焦点不在输入框时） | 下一关 |
| `[` / `←`（焦点不在输入框时） | 上一关 |
| `1` / `2` / `3` | 聚焦第 1/2/3 个子任务的「标题」输入框 |
| `g` | 打开整条路线总览（`#route/graph`） |
| `Esc` | 返回剧情路线域首页 |
| `Ctrl+Z` | 撤销（全局已绑定） |

实现方式：在 `route.js` 的关卡视图容器上自己注册 `keydown`（`tabindex="-1"` + 聚焦时生效），
**不改 `app.js`**，避免与全局流程那一块撞车。
