# 规格：说人话 + 卡片纵排（第十轮）

> 起因（用户原话，附截图）：
> 1. **「看不懂，改成用户能看懂的说法解释清楚，先设计好再改。别处也彻查一遍」**
> 2. **「不要用页签了，改成同一个滚动页面中纵向排列的的卡片」**
>
> 截图是忍术视图的「成长」那一页（`#ninjutsu/jutsu`）。它有两处毛病：
> - **版式**：页签把其余类别的内容藏起来了，作者看不到「这个忍术一共有几类可改的东西」。
> - **措辞**：「成长目标1 / 字节 +0x04: 随等级成长的初值；由下面的「成长目标」字段选中
>   （1..6 指到这里）」—— 这句话只有逆向者读得懂，作者不知道这东西在游戏里是什么。
>
> 前一轮（第九轮）做的是页签；这一轮**推翻页签，改成卡片纵排**，
> 并把全包字段说明改成人话。方法与结果见 `notes/rom-editor-20261021.md` §6.14。

## 1. 问题诊断（有据）

### 1.1 说明写成了「证据日志」，不是「解释」

仓库自己的规则是「元数据落在内容包，界面只渲染不硬编码」，
所以**说明的唯一真相在 `tools/export_content_pack.py`**。
第九轮之后全包 1,006 个字段的说明里：

| 打标 | 字段数 | 例子 |
|---|---:|---|
| **说明里塞了 ROM 地址** | **117** | 「…超了就不让选（0x080713B4 / 0x08071548，tag=1 时只取低字节）」 |
| label 带裸编号 | 10 | 「成长目标1」…「成长目标6」 |
| 偏移当主语 | 8 | 「字节 +0x04：随等级成长的初值」 |
| 交叉引用 | 6 | 「由下面的「成长目标」字段选中」 |
| 说明过长（>160 字） | 4 | |
| 裸公式 | 1 | 「值 = (类别−1)×4+20（0x08078F08 / 0x080953A4）」 |

审计工具：`tools/audit_field_wording.py`（新）→ `build/field-wording.md`。

**关键冗余**：界面上每个字段右边**已经**显示了 `+0x04`（`field-offset`），
说明里再写一遍偏移是纯噪音；地址更是只在笔记里有意义。

### 1.2 措辞上的四条硬伤

| 硬伤 | 表现 | 为什么作者读不懂 |
|---|---|---|
| **主语是 ROM 的对象** | 「字节 +0x04：……」 | 作者心里想的是「这个忍术给角色加什么」，不是「第 4 个字节」 |
| **交叉引用** | 「由下面的「成长目标」字段选中」 | 作者得在页面里上下找那个字段，再自己拼出关系 |
| **裸公式** | 「值 = (等级−1) × 本值」 | 没说这个值是什么、算出来干什么用 |
| **只说「未解」** | 「没有原生读者读它」 | 说清了「没证明」，却没说这个值在游戏里是干嘛的 |

### 1.3 版式上，页签把内容藏起来了

第九轮把右侧面板做成页签（战斗 5 页 / 角色 7 页 / 任务 5 页 …）。
作者的反馈是：**不要用页签**。

页签的问题不是「分页」本身，而是：
- 看到「成长」这一页时，**不知道还有几类东西没看**；
- 「胜负条件」「剧情触发」这些**互不相关**的东西被塞进同一组页签，
  和「战场物件」这种同属一件事的类别混在一起；
- 切页签会**丢掉滚动位置**，来回比对很烦。

## 2. 改成什么：卡片纵排

### 2.1 版式

右侧面板改成**一个滚动页面**，每一类配置是一张**卡片**：

```
┌──────────────────────────────────────────┐
│ 战场布置                        已改 0 处 │  ← 卡片头：类别名 + 改动数
│ 这张战场多大、剧情底图是哪一张…            │
│  地图  地图表第 40 条 · 9 × 22 格         │
│  剧情底图  [底图 1 ▾]                    │
│  …                                      │
└──────────────────────────────────────────┘
┌──────────────────────────────────────────┐
│ 战场物件                        已改 2 处 │
│  槽  类别  内容  X  Y  ↗                │
│  #1  空    …                          │
│  …                                      │
└──────────────────────────────────────────┘
┌──────────────────────────────────────────┐
│ 角色出生点                      已改 0 处 │
│  …                                      │
└──────────────────────────────────────────┘
```

三条规则：

1. **所有卡片都在同一个页面里**，往下滚就是全部 —— 不藏内容。
2. **卡片头 = 类别名 + 改动数**（角标从页签条挪到卡片头）。
3. **主界面不变**：左边还是能看见东西的那个（地图 / 角色卡 / 任务 / 场景）。

### 2.2 卡片 = 第九轮的页签，去掉「切换」

第九轮的页签已经算好了「一件东西分几个类别」——
这一版**保留分类，去掉切换**：类别还是分类（卡片），但不互斥、不隐藏。

**保留下来的**：
- 分类（卡片头就是类别名）
- 角标（这一类改了几处，按字节判定）
- 主界面 + 右侧收纳配置的结构

**去掉的**：
- 页签条、当前页高亮、记住上次停在哪（卡片没有「当前」）
- 懒渲染（卡片全都渲染出来 —— 右侧面板本来就在滚动）

### 2.3 通用机制

`rom-editor/js/cards.js`（新）导出 `CardStack`：

```js
import { CardStack } from '../cards.js';

this.cards = new CardStack([
  {
    id: 'setup',
    label: '战场布置',       // 卡片头的标题
    hint: '这张地图的尺寸、底图与资源指针',  // 卡片头下的一行说明（可选）
    badge: () => '2',        // 这一类改了几处（可选）
    render: () => this.renderSetup(),
  },
  ...
]);
host.appendChild(this.cards.element);
```

- `cards.refresh()` —— 重建全部卡片（改完数据后调）
- `cards.setBadge(id, text)` —— 单独改某一类的角标
- 规格形状与第九轮的 `TabPanel` **完全一样**（`{id, label, hint, badge, render}`），
  各域的改动只有「`TabPanel` → `CardStack`」「`label` 保持」这一类机械替换。

`rom-editor/js/tabs.js` **删除**（页签不用了）。

## 3. 说明怎么写：说人话的三条规则

### 3.1 模板

每条说明按这个顺序写，**≤ 80 字**：

| 顺序 | 写什么 | 例子 |
|---|---|---|
| ① **这是什么** | 主语是**作者关心的东西**，不是 ROM 的对象 | 「这个忍术加的第 1 项属性」而不是「字节 +0x04」 |
| ② **怎么用** | 取值含义 / 公式，用日常话 | 「角色每升 1 级，这项就多「每级成长量」这么多」 |
| ③ **改它会怎样** | 影响什么 | 「改大了，这个忍术在战斗里就变强」 |
| ④ **证据等级** | 只说「已证明 / 还没证明」 | 「这一项对应角色的哪个能力，仓库还没证明」 |

### 3.2 禁止清单

| 禁止 | 原因 |
|---|---|
| 说明里出现 ROM 地址（`0x08xxxxxx`） | 那是**证据**，该待在 `notes/` 里；界面上有偏移就够了 |
| 主语是「字节 +0xNN」「记录」「字段」 | 那是逆向者的视角 |
| 交叉引用（「由下面的 X 字段选中」） | 作者得自己拼关系；同一张卡片里要直接说清 |
| 只说「未解」却不说这个值干嘛 | 「没证明」不等于「没用」 |
| 超过 80 字 | 说明作者自己还没想清楚 |

### 3.3 例子：忍术的「成长」这一组

**现在**（作者看不懂）：

```
成长目标1   +0x4   [0]
字节 +0x04: 随等级成长的初值；由下面的「成长目标」字段选中（1..6 指到这里）
...
成长目标   +0xC   [成长目标4（+0x07）]
0/7 = 不成长；1..6 指向上面的成长目标1..6
每级成长量  +0xE  [1]
值 =（等级−1）× 本值; 实测 87 条记录中 +0x0F 恒为 0，所以本字段是单字节（…）
```

**改后**（卡片标题：随等级成长的属性）：

```
卡片头：随等级成长的属性
卡片说明：这个忍术在角色身上加六项属性。其中一项会跟着角色等级一起长 ——
         每升 1 级，长的那项就多「每级成长量」这么多（实际加成 =（等级 − 1）× 每级成长量）。

属性加成 1  [0]   这个忍术加的第 1 项属性。
属性加成 2  [1]   这个忍术加的第 2 项属性。
…
属性加成 6  [0]   这个忍术加的第 6 项属性。
        —— 这六项分别对应角色的哪项能力（攻击力 / 防御力 / …），仓库**还没证明**；
           已证明的是：六项各是一个初值，且其中一项会被下面那一格挑出来随等级长。

会成长的属性  [属性加成 4（+0x07）]
        挑哪一项会跟着等级长。选「不成长」就六项都不长。

每级成长量  [1]
        每升 1 级，会长大的那一项就多这么多。实际加成 =（等级 − 1）× 本值。
```

**为什么这么写**：
- 「属性加成 1..6」比「成长目标1..6」好懂：它是**这个忍术加的属性**，
  不是「目标」——「目标」这个词在游戏里另有所指（任务目标），反而误导。
- 「会成长的属性」是**动作**，「成长目标」是**名词**；作者改的是「哪一项会长」，
  动作词更贴。
- 「哪一项对应攻击力/防御力」**没证明就说没证明**（仓库规则：静态推定必须标「推定」，
  不成立的说法要诚实标出来）。六项对应哪六项能力，仓库只查到了
  第三方把某条记录的 +0x04 叫「基础攻击力」，那是**项目配置**，不是字段语义
  （`notes/character-template-format-20261020.md` §7 的未解项 11）。

### 3.4 措辞不与事实冲突

- 「已证明」的部分照旧写（例如「成长量 =（等级 − 1）× 每级成长量」是证明过的）。
- 没证明的部分**说没证明**，不编。
- 偏移（`+0x04`）**由界面自己显示**（`field-offset`），说明里不重复。

## 6. 验收

1. **没有页签了**：`grep -r "TabPanel\|tab-bar\|tab-btn" rom-editor/js` 为空；
   `rom-editor/tools/verify_cards.mjs`（替代 `verify_tabs.mjs`）断言
   **每个域的右侧有卡片、卡片标题是预期的那几个、每张卡片的内容都在 DOM 里**。
2. **说明说人话**：`tools/audit_field_wording.py` 的命中数从 129 降到 **0**
   （「说明里塞了 ROM 地址」「偏移当主语」「交叉引用」「裸公式」四条全清）。
3. **既有门禁不许降级**：verify_views / verify_pack / verify_sources / verify_labels /
   verify_battle_map / verify_route_workbench / verify_character_view /
   verify_item_view / verify_scene_view / verify_audio_workbench / verify_script_text /
   verify_syntax / 单测 / 内容包往返 —— 全过。
4. **页面文本里不许出现字面 `**`**，不许出现 ROM 地址（`0x08xxxxxx`）。

## 7. 明确不做

- 不改任何写回通路（一律 `pack.setValue` / `pack.setText` / `pack.setScriptOperand`）。
- 不引新框架、不改构建步骤。
- 不把「未证明」的东西说成已证明 —— 这一轮只改**措辞**，不改**结论**。
  要改结论得先做逆向，那不是这一轮的事。
- 卡片不做折叠 / 拖动排序 / 多开一页。
