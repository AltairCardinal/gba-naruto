# `cutscene-scripts`（`0x0853DF70`）的运行时证据（2026-10-22）

## 1. 这个表是什么

`fn 0x08072EDC(index)` 把 `0x0853DF70` 当作 **8 字节/条**的表读：

```
0x08072F0C: ldr  r4, [pc, #0x2c]   ; r4 = 0x0853DF70
0x08072F0E: movs r0, r8            ; r8 = index
0x08072F10: lsls r5, r0, #3        ; index * 8
0x08072F12: adds r0, r5, r4
0x08072F14: ldr  r0, [r0]          ; 条目 word0
0x08072F16: ldr  r1, [pc, #0x28]   ; r1 = 0x06016000
0x08072F18: bl   0x0809C0E8        ; 传送到 VRAM 0x06016000
0x08072F1C: adds r4, #4
0x08072F1E: adds r5, r5, r4
0x08072F20: ldr  r0, [r5]          ; 条目 word1
0x08072F22: ldr  r1, [pc, #0x20]   ; r1 = 0x05000380
0x08072F24: bl   0x0809C0E8        ; 传送到 0x05000380
```

每条 = **(源地址, 长度)**，分别传送到两个固定地址。

## 2. 旧结论的错处

旧笔记写：

> 表基址加载点 `0x08072F0E`（`fn 0x08072EDC` 读 `0x0853DF70`，
> 前提是 `*(0x02026A80) == 0`），调用点 `0x0807363A` 在剧情战斗事件
> switch 的 case `0x08073638` 里 ⇒ 需**特定事件 id**；48 个战斗组都没出现

逐指令核对后：

* **表读取是无条件的** —— `0x08072EEE`–`0x08072EFA` 那个
  `cmp r2,#0 / beq 0x08072F0C` 只是决定**要不要顺手置一个标志**，
  `beq` 直接跳到装载指令，所以 `0x08072F0C` 两条路径都会走到。
  「前提是 `*(0x02026A80) == 0`」是误读。
* 调用点不止一个：`fn 0x08072EDC` 有 **4 个**调用者
  （`0x08073100` / `0x0807314A` / `0x08073196` / `0x0807363A`），
  旧笔记只押了最后一个。

## 3. 真正的路线：相位 `0x0118`

状态机的相位分派（`0x0808F752` 起）里：

```
0x0808F754: movs  r0, #0x8c
0x0808F756: lsls  r0, r0, #1      ; r0 = 0x118
0x0808F758: cmp   r1, r0
0x0808F75A: bne   0x0808F75E
0x0808F75C: b     0x0808F94A      ; ← 相位 0x0118
```

`0x0808F94A` 的处理：

```
0x0808F94A: movs  r0, #1
0x0808F94C: movs  r1, #0x7f
0x0808F94E: bl    0x0808A490      ; 置战斗标志（bit id&0x1F = 1）
0x0808F952: bl    0x080732B4      ; ★ 剧情战斗
0x0808F956: bl    0x08062560
0x0808F95A: movs  r0, #0
0x0808F95C: movs  r1, #0x7f
0x0808F95E: bl    0x0808A490      ; 清同一个标志
```

**相位 `0x0118` 就是「带这个标志跑剧情战斗」** ——
`fn 0x080732B4` 正是过场链所在的函数。

  （`0x0812D9E4` / `0x0812DEE4` / `0x0812DF4C` / `0x0812E42C` …）。

**⇒ `cutscene-scripts` 的 evidence 缺口闭合。**
