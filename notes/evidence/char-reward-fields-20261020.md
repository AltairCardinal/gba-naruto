## 1. 方法

1. **不写死地址**：用 `tools/consumer_locate.py` 建全 ROM 字面量索引，
   找出**每一个**读 `0x0854241C` / `0x08545458` / `0x0859EAE0` 的原生消费者。
   索引结果见 `notes/evidence/consumer-evidence.json`（**本轮没有重新生成该文件**）。
2. **定点反汇编**：对每个消费者用 `tools/disasm_thumb.py`
   （capstone，Thumb 模式）定点反汇编，不做全 ROM 线性扫（会漂）。
3. **调用点用 capstone 解码**：找「谁调用了这段代码」时，
   先用原始半字预筛 BL 指令（`hw1 & 0xF800 == 0xF000` 且 `hw2 & 0xC000 == 0xC000`），
   再让 **capstone 自己**解出分支目标。
   > 手写 Thumb BL 位域解码在本次工作中出过错（`J1/J2` 位置与符号扩展写错），
   > 导致「`0x080899EC` 没有调用者」的假结论；**改用 capstone 后立刻找到
   > `0x08089B7E`**。这条方法教训一并记在这里。
4. **数据侧交叉核对**：把代码读出的偏移语义与 ROM 数据对齐
   （名字表容量、id 取值域、记录条数、几何首尾相接）。
5. **每个结论配一个可证伪检验**（见 §5），并把结论写进机器可检的工具里
   （字节级布局守卫 + 数据级断言），不靠散文维持。

## 2. 角色模板 `0x54241C` 的原生读者（4 个）

`tools/consumer_locate.py` 在 `notes/evidence/consumer-evidence.json` 里
给 `0x0854241C` 列了 **4 个** reader（旧笔记只承认 2 个）：

| reader | 所属函数 | 模式 | 用途 |
|---|---|---|---|
| `0x0806D4D2` | `0x0806D4A0` | thumb | 建立实例：把模板搬进 `0x02022E34` 池 |
| `0x0806D984` | `0x0806D964` | thumb | 属性初始化：模板头 → 实例属性 |
| `0x08089A00` | `0x080899EC` | thumb | **等级解锁扫描**（本轮新定位） |
| `0x080926D8` | `0x08092694` | thumb | **战斗配置 → 实例搬运**（本轮新定位） |

### 2.1 `0x080899EC` —— 解锁扫描（核心证据）

调用点：`0x08089B7E`（在升级函数 `0x08089AE0` 内，`0x08089B6C` 把新等级写进
实例 `+0x01` 之后立刻调用）。

```
0x08089A00  ldr  r0,[pc,#0xd4]   ; 字面量池 0x08089AD8 = 0x0854241C
0x08089A02  adds r1,r1,r0        ; r1 = &模板[id]
0x08089A04  mov  r8,r1           ; r8 = 模板基址
...
0x08089A0C  ldrb r2,[r1,#0x14]   ; 实例[0x14+4i] = 忍术 id
0x08089A10  cmp  r2,#0
0x08089A12  beq  0x8089a60      ; id == 0 -> 跳过
0x08089A14  ldrb r0,[r1,#0x15]   ; 实例[0x15+4i] = 档位值
0x08089A16  cmp  r0,#0xff
0x08089A18  bne  0x8089a60      ; 已习得 -> 跳过
0x08089A32  mov  r1,r8
0x08089A34  adds r0,r1,r3        ; r3 = i*4
0x08089A36  ldrb r1,[r0,#0xe]    ; 模板[0x0E+4i] = 解锁等级
0x08089A38  cmp  r1,#0
0x08089A3A  beq  0x8089a60      ; 0 -> 永不自动解锁
0x08089A3C  ldrb r0,[r6,#1]      ; 实例[1] = 角色等级
0x08089A3E  cmp  r0,r1
0x08089A40  blo  0x8089a60      ; 等级 < 解锁等级 -> 未解锁
0x08089A48  strb r0,[r2,#0x15]   ; 档位值 0xFF -> 0（已习得）
0x08089A52  ldrb r0,[r2,#0x14]   ; 取出 id
0x08089A54  strb r0,[r1]         ; 追加到「本次解锁列表」
```

技术段（`i = 0..23`）同构，追加前置最高位：

```
0x08089AA2  ldrb r1,[r4]         ; 技术 id
0x08089AA4  movs r2,#0x80
0x08089AA6  orrs r1,r2           ; id | 0x80
0x08089AA8  strb r1,[r0]         ; 追加
```

> `0x08089AA8` 的原始半字是 `0x7001` = `strb r1,[r0,#0]`。
> capstone 5.0.7 在这一处把操作数打印反了（打印成 `strb r0,[r1]`），
> **以原始半字为准**。

### 2.2 升级界面把解锁列表翻成名字（这才是「id 是什么」的证据）

`0x08089AE0` 的 `0x08089DB8` 起：

```
0x08089DBE  ldrb r0,[r4]         ; 列表字节
0x08089DC0  cmp  r0,#0xff        ; 0xFF = 列表结束
0x08089DCE  ldrb r2,[r4]         ; r2 = 列表字节
0x08089DD2  ldrsb r0,[r4,#0]     ; 有符号扩展
0x08089DD4  cmp  r0,#0
0x08089DD6  blt  0x08089df0      ; 负数(=带 0x80) -> 技术表
0x08089DD8  ldr  r0,[pc,#0x10]    ; 字面量池 0x08089DEC = 0x0859937C（忍术名表）
0x08089DDA  ldrb r1,[r4]
0x08089DDC  lsls r1,r1,#2
0x08089DDE  adds r1,r1,r0
0x08089DE0  ldr  r1,[r1]          ; 忍术名
...
0x08089DF0  ldr  r0,[pc,#0x30]    ; 字面量池 0x08089E24 = 0x085A7060（技术名表）
0x08089DF4  ands r1,r2,#0x7f      ; 去掉 0x80 标记
```

**名字表内容抽样**（`tools/text_codec.py` 解码）：

| `0x0859937C`（忍术名，87 条） | `0x085A7060`（技术名，45 条） |

| 0 没有 / 1 分身术 / 2 瞬身术 / 3 变身术 / 4 变化术 / 5 忍者组合拳 / 6 工资 / 7 影分身术 / 8 色诱术 / 9 多重影分身术 | 0 锻炼 / 1 锻炼 / 2 修炼 / 3 锻炼肌肉 / 4 守势 / 5 动作训练 / 6 跑步练习 / 7 忍具整备 / 8 爬树 / 9 实践练习 / 10 体术理论 / 11 忍术理论 / 12 投掷练习 / 13 药物知识 / 14 精神统一 / 15 休养 / 16 忍术心得 / 17 连打 / 18 迅速结印 / 19 速击 / 20 突袭 / 21 水上行走 / 22 树上行走 / 23 跳远 / 24 九尾的查克拉 / 25 咒印暴走 |

### 2.3 `0x08092694` —— 战斗配置 → 实例搬运

```
0x080926D8  ldr  r0,[pc,#0x30]   ; 字面量池 0x0809270C = 0x0854241C
0x080926DA  adds r1,r1,r0        ; r1 = &模板[id]
0x080926DC  mov  r8,r1
...
0x08092722  ldr  r1,[pc,#0x14]
0x08092724  mov  r0,sl
0x08092726  add  r0,sb
0x08092728  ldrb r0,[r0,#7]      ; 配置项 [7] = 段内槽号
0x0809272A  lsls r0,r0,#2
0x0809272C  add  r0,r8
0x0809272E  adds r0,#0x4a        ; 模板[0x48+4*槽+2] = 技术段的解锁等级
0x08092730  ldrb r0,[r0]
0x0809273C  ldr  r0,[pc,#0x18]   ; 字面量池 0x08092758 = 0x0859937C（忍术名表）
0x0809273E  ldrb r1,[r2,#6]      ; 配置项 [6] = 忍术 id
0x08092740  lsls r1,r1,#2
0x08092742  adds r0,r1,r0
0x08092744  ldr  r3,[r0]         ; 忍术名
```

这条路径同时证明：**忍术 id 既是 `0x0859937C` 的下标，也是 `0x545458` 记录表的下标**
（见 §3.2）。

### 2.4 忍具槽的 id 空间

```
0x0806D590  ldrb r0,[r4]         ; 模板[0xA8+i] = 忍具 id
0x0806D594  beq  skip            ; 0 = 空
0x0806D596  bl   #0x0808FA34      ; 「入背包 + 可用性」
0x0806D59C  bne  skip            ; 返回非 0 = 背包满
```

`0x0808FA34` 同时被奖励类别 0（忍具）使用：

```
0x0809736E  bl   #0x0808FA34      ; 奖励类别 0 的 arm
```

而 `0x0808FA34` 内部把 per-id 计数放在 `0x02022E30 + 0x11A5 + id`、
总件数上限 0x62（98）放在 `0x02022E30 + 0x11A4`：

```
0x0808FA3A  ldr  r1,[pc,#0x20]   ; =0x02022E30
0x0808FA3C  ldr  r0,[pc,#0x20]   ; =0x000011A4
0x0808FA40  ldrb r0,[r2]         ; 总件数
0x0808FA42  cmp  r0,#0x62        ; > 98 = 满
0x0808FA46  ldr  r4,[pc,#0x1c]   ; =0x000011A5
0x0808FA4A  adds r0,r1,r4
0x0808FA4C  adds r0,r3,r0        ; &counter[id]
```

**结论**：忍具槽的 id 与奖励类别 0 的 id 是**同一个 id 空间**
（名表 `0x08599634`，94 条）。

## 4. 明确未解的字段（不做命名）

| 字段 | 已知边界 | 还差什么 |
|---|---|---|
| 模板 `+0x00` | 恒 1；4 个消费者都不读 | 一条读 `0x0854241C + id*0xB4 + 0` 的指令 |
| 模板 `+0x07` | 恒 0；4 个消费者都不读 | 同上，读偏移 7 |
| 条目第 4 字节（pad） | 模板里恒 0；无任何已定位的读路径 | 读 `实例+0x17+4*i` / `实例+0x53+4*i` 的指令 |
| 档位值 `1` vs `3` | 是 u8 档位；技术侧参与 `base + growth*(B-1)` | 标出它在战斗里的作用 |
| 记录 `+0x00` / `+0x01` | 被搬到「已习得忍术」表项 `+0x04` / `+0x05` | 追该表项的消费者 |
| 记录 `+0x02` 的其余位 | 只证明 `& 0x1800 >> 5` | 读 `+0x02` 其余位的代码 |
| 记录 `+0x03/+0x0A/+0x0B/+0x0D/+0x0F` | 无 | 逐个消费者反汇编（已定位 7 个消费者函数） |
| 奖励 `+0x16` / `+0x17` | 全部 112 条为 0，无消费者 | 任何读它们的指令 |
| 类别 3 的取值域 | 代码支持、名字表 45 条，但**本 ROM 数据里 0 次出现** | 一条真正使用类别 3 的奖励数据 |

## 5. 可证伪检验

| # | 结论 | 证伪方法 | 观察到什么就说明我错了 |
|---|---|---|---|
| F1 | 条目第 3 字节 = **解锁等级** | 把鸣人（id 1）的「变身术」解锁等级从 4 改成 1 | 若升级到 2 级时**没有**解锁变身术 → 结论错 |
| F2 | 条目第 2 字节 `0xFF` = **未习得** | 把「变身术」的档位值从 `0xFF` 改成 `1` | 若升级时它仍然被当作「未习得」而不进列表 → 结论错 |
| F3 | 忍术表第 1 字节 = **忍术 id** | 把鸣人「变身术」的 id 从 3 改成 23（心转身术） | 若升级提示显示的仍是「变身术」→ 结论错 |
| F4 | 技术表第 1 字节 = **技术 id** | 把鸣人「锻炼」（id 1）的 id 改成 6（跑步练习） | 若升级提示显示的仍是「锻炼」→ 结论错 |
| F5 | 忍具槽是 **忍具 id** | 把某角色的忍具 id 从 1 改成 2（八方手里剑） | 若游戏里拿到的道具仍是十字手里剑 → 结论错 |
| F6 | `0x545458` 下标 = **忍术 id** | 把某角色「变身术」（id 3）的记录 `0x545458+3*16` 的 `+0x04` 改大 | 若战斗数值毫无变化 → 记录与忍术 id 无关，结论错 |
| F7 | 奖励尾部**低字节 = 类别** | 把 stage 1 sub 0 槽位 0 的低字节由 `0x00` 改成 `0x01` | 若提示仍是「忍具 + 忍具名」→ 结论错 |
| F8 | 奖励尾部**高字节 = 物品 id** | 把同一槽位的高字节由 `1` 改成 `2` | 若提示仍是「十字手里剑」→ 结论错 |
| F9 | 奖励表 **112 条** | 把 `MISSION_INDEX` 的某字节改大，使下标越过 112 | 若仍显示正常奖励 → 条数或下标公式错 |
| F10 | 类别 → 名字表由 `0x59F5E0` 决定 | 把 `0x59F5E0[0]` 改成 `0x085A7E8C` | 若「忍具」提示变成素材名 → 映射错 |
| F11 | 奖励**每类 id 落在名字表容量内** | 把类别 0 的某 id 改成 `>= 94` | 若仍显示正常忍具名 → 说明 id 不是名字表下标，结论错 |
| F12 | 模板 `+0x00` / `+0x07` 语义未知 | — | 无法证伪（无消费者）；只能等找到消费者 |
