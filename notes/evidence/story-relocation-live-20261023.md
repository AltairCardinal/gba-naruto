# 剧本搬迁的**真机验收**（无头 mGBA，2026-10-23）

> 这份笔记是**动态证据**：不是静态推断，是**跑起来的游戏**。
>
> 结论：**对白变长 → 整个剧本搬到空闲区 → 游戏照常跑，且屏幕上就是新正文。**
>
> 工具：`tools/mgba_probe/relocation_acceptance.py`（一次跑完全部检查）
> 　　　`tools/build_reloc_test_rom.mjs`（造测试 ROM）
> 宿主：`build/mgba-probe/mgba-probe.exe`（仓库自带的无头 mGBA，C API + mGBA 自己的调试器）
>
> 前置：`notes/evidence/story-script-relocation-20261022.md`（静态考证）

---

## 0. 一句话

**四件动态证据**：① 游戏跟着改过的根表指针走；② 跑中的剧本里就是变长后的新正文；
③ 改过的那句之后脚本继续往下跑（分支重基对了）；④ 画面只在对白那一行变。

## 1. 怎么造的测试 ROM

`tools/build_reloc_test_rom.mjs`：

1. 载入原版 ROM 与内容包；
2. 把**场景 54 的第 5 句对白**改长 —— 那正是 L3 证据
   `notes/evidence/story-scene-l3.png` 里屏幕上显示的那一句，
   导航序列是 `START` + `A`×4（正常按键，没改写任何内存）；
3. 构建 ROM —— 变长触发**剧本搬迁**：整个剧本搬到空闲区、内部绝对地址全部重基、
   根表指针改掉。

构建报告：

```
场景 54 第 5 句
  原文：“是啊，是我这个班主任所承认的嘛！”
  改成：“是啊，是我这个班主任所承认的嘛！”          测试测试
  字节：48 → 56（+8）
  会搬动剧本：true
构建报告：
  搬迁 0x49E76
    0x49E76 → 0x5DFBEC

    入口 0x49E76 → 0x5DFBEC
    新正文 @0x5DFD3C：816795c4889f814395c497cf9bac8cf388de9c6294cb96988a6e94cc8b6291ec…
```

> **改指针 2 个** —— 场景 54 的 `before` 与 `after` **共用同一个剧本**
> （那 12 个共用根之一），所以**两个槽都要改**。漏一个就有一场戏走丢了。

## 2. L1：游戏跟着改过的根表指针走

在**剧情 VM 入口 `0x080977B8`** 断住，读 r0（VM 的第一个参数 = 剧本首地址）：

| ROM | VM 入口的 r0 |
|---|---|
| 原版 `rom/base.gba` | `0x08049E76`（= `before_root[54]`，与 L3 证据一致） |
| 搬迁后的 `build/reloc-test.gba` | **`0x085DFBEC`**（= 搬迁后的新地址） |

⇒ **游戏自己**从改过的根表里读出了新地址，并且从那里开始跑剧本 ✓✓
（这一条直接证明「根表指针改对了」—— 不是我们在算，是游戏在用。）

工具：`tools/mgba_probe/story_vm_capture.py`（本轮给它加了 `--script-bytes`）。

---

## 3. L2：跑中的剧本里就是变长后的新正文

在**「显示文本」handler `0x080978DC`** 断住，读**正在执行的指令流**字节
（r7 = 当前指令地址），再按字库解码：

```
script=0x085DFC34 => 呜哇！果然还是一乐的拉面最好吃呀！！”
script=0x085DFC8B => 鸣人……一听到是我请客
script=0x085DFCE2 => 老师！老师！…从今天起我就是个真正的忍者了！！”
script=0x085DFD3B => 是啊，是我这个班主任所承认的嘛！”          测试测试   ← 被改的那句
script=0x085DFD77 => 你已经从忍者学校毕业，…成了木叶村里优秀的忍者了！！”
script=0x085DFDEE => 伊鲁卡老师！我有一个请求……”
script=0x085DFE25 => 是什么？”
```

* 全部 7 次命中都在**搬迁后的地址**（`0x085DFxxx`）✓
* 第 4 次命中 `0x085DFD3B` 正是被改的那条指令（正文在 `0x085DFD3C`），
  跑的内容**就是变长之后的新正文**（末尾多了「测试测试」）✓✓
* **控制码**（`0x01` 换行）在跑中的字节里也原样保留 ✓

---

## 4. L3：改过的那句之后，脚本继续往下跑

第 4 句之后还有 3 句（你已经…／伊鲁卡老师…／是什么？）**照样出现** ✓

⇒ 剧本没有跑飞 ⇒ **分支目标的重基是对的**（那 5 处重基包括 `0x06` 二选一分支
与 `0x32` 事件链）。

---

## 5. L4：画面只在对白那一行变

两个 ROM 各截一张 mGBA 自己的画面（`rawshot` ⇒ 240×160 RGBA），逐像素比：

| 项 | 值 |
|---|---|
| 不同像素 | **446 / 38,400 = 1.16 %** |
| 差异包围盒 | x 0..239，**y 120..143**（就是对白正文那一行） |
| 逐行差异 | y=120..136 是正文行；y=137..143 是新字那几行 |

⇒ **背景、立绘、名牌、对白框一个像素都没动** ✓ —— 只有正文变了，
而且变的正是新加的那几个字。

> **顺带一条实测结论**：游戏的对白框**不自动换行** ——
> 变长的正文会**横向溢出屏幕**（本例最后两个字被切掉了）。
> 一行放得下约 16 个汉字（12 px 一个）。要换行得作者自己插 `0x01` 控制码。
> 这是游戏本身的行为，不是搬迁造成的。
