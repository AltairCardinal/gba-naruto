# 剧情剧本的搬迁与绝对地址重基（2026-10-22）

> 这份笔记记录的是：**剧情脚本里的对白为什么曾经「必须等长」，现在为什么不用了**，
> 以及「不等长」这条路到底怎么走通、靠什么证据说它是对的。
>
> 用户需求原文：「修改时必须等长的要求太麻烦了，我希望能解决，特别是对于对白文本。
> 当然别处的文本也一样。」
>
> 测量脚本：`tools/probe_story_relocation.mjs`（一次跑出本文所有数字，
> 结果落在 `build/story-relocation-probe.txt`）
> 门禁：`rom-editor/tools/verify_script_relocation.mjs`（搬迁本身，14 条）
> 　　　`rom-editor/tools/verify_variable_text.mjs`（写回通路端到端，72 条）

---

## 0. 一句话结论

**对白正文现在可以任意长度**：等长的直接原地改写；变长 / 变短的，
**构建时把整个剧本（连同与它字节重叠的剧本）搬到 ROM 空闲区**，
把它内部的绝对地址**全部重基**，再改根表里指向它的指针。

旧结论（「等长是硬约束」）不是被**推翻**，而是被**绕过**：
「正文内联、分支目标是绝对地址」这两条**结构事实仍然成立**，变的是**应对手段**。

---

## 1. 为什么以前「必须等长」

剧情脚本的正文是**内联在指令字节流里**的（不是指针），而脚本里的分支目标
是**绝对 ROM 地址**（`0x08xxxxxx`）。所以在原地改一个字长：

* 后面的指令**全部移位**；
* 所有指向它后面的分支目标**全部指歪** ⇒ 分支跳到指令中间 ⇒ 脚本跑飞。

这条约束是**结构性的**，不是编辑器偷懒 —— 见 `notes/story-dialogue-editing-20261022.md` §2.1。

---

## 2. 为什么现在可以不等长

因为「绝对地址」这件事**可以被搬迁消掉**：

1. 把剧本的字节搬到 ROM 的**空闲区**（`0x5DFBEC` 起，132,116 字节）；
2. 把剧本内部**每一个**指向自己内部的绝对地址**重基**成新地址；
3. 改根表里指向它的指针，让游戏从新地址进来。

搬完之后，剧本内部所有「绝对地址」都变成了一组**自洽的**新地址 ——
分支照旧跳，只是跳到新地址上。

**前提**：这段正文必须属于某个剧本。不属于任何剧本的字节（孤儿代码）
后面没有任何东西能给它让位，仍然只能等长。

**旧位置不回收** —— 回收会把「未改动的内容包重建出来逐字节相同」这条不变量弄丢
（旧位置一被回收，未改动的包重建出来的 ROM 就不一样了）。回收是后面的事。

## 3. 事实测量

### 3.1 剧本的物理布局

| 项 | 值 |
|---|---|
| 剧本个数（四张根表扫出来） | **202** |
| 不同的剧本（按起始地址去重） | **190** |
| 剧本字节合计（各段相加） | 410,610 字节 |
| 剧本区跨度 | `0x9F2E..0x5CD40` —— 339,474 字节 |
| 分成多段的剧本 | **19** 个（`before` 与 `after` **物理交错**） |
| 段与段之间的缝隙 | 24 处、299,422 字节，其中 0xFF 只有 91 个字节 |
| **整段都是 0xFF 的缝隙** | **0 处** |
| 最大的剧本 | `before.50` —— 42,413 字节（分 2 段） |

> 「19 个剧本分多段」是搬迁方案的关键：剧本**不是**一段连续的字节。
> 搬的时候要**按段搬**，段与段之间靠分支相连 —— 每段都以 `0x00`（结束脚本）收尾，
> 终止符跟着一起搬，分支目标重基过之后照样连得上。

### 3.2 必须重基的地址槽（白名单）

判据必须是「**操作码 + 槽在指令内的偏移**」，**不能**用「值落在 `[A, A+L)` 就 `+= Δ`」：

> 实测那种数值判据会误伤 **30 处**（指令内部）与 **1,119 处**（原生代码里
> `12 xx xx xx` 这类操作数字节凑出来的 `0x08xxxxxx` 巧合值）。

白名单（`storyvm.js::ADDRESS_SLOTS`，由 `BRANCH` + `SINGLE_TARGET` + `0x06` 派生，
不是手抄的 —— 少一个就漏一处重基，多一个就误伤）：

| 操作码 | 槽偏移 | 本 ROM 出现次数 |
|---|---|---|
| `0x06`（二选一分支） | +1、+5 | 102 |
| `0x07`（无条件跳转） | +1 | 54 |
| `0x0B`（标记为真则跳转） | +2 | 17 |
| `0x0C`（标记为假则跳转） | +2 | 28 |
| `0x0D`（调用子脚本） | +1 | **0**（本 ROM 不用） |
| `0x15`（比较跳转） | +4 | 81 |
| `0x32`（事件链选择） | +1 | 421 |
| `0x34`（回合条件） | +4 | 374 |
| `0x35`（复合条件） | +5 | 196 |
| `0x36`（指定角色在场） | +4 | 213 |
| `0x38`（测试战斗标志） | +3 | 204 |
| `0x39`（子配置匹配） | +2 | 26 |

* 全 ROM 一共 **1,716** 处地址槽要重基。
* **指向本剧本之外的：0 处** ⇒ 每个剧本都是**自包含**的 ⇒ 搬一个剧本不影响别的剧本。
* `0x0D`（调用子脚本）本 ROM **一次都没用** ⇒ 没有跨剧本调用。
* `0x32` 的载荷是**同剧本内**的段首地址（421/421 都在本剧本内）。

### 3.3 根表指向：两组「共享」，必须一起处理

**（a）12 个根被 before / after 同时指向**（同一份剧本，两个槽）：

```
0x30F55 ← before.32、after.32      0x361D9 ← before.48、after.48
0x30F72 ← before.33、after.33      0x361F6 ← before.49、after.49
0x30F8F ← before.34、after.34      0x36213 ← before.50、after.50
0x30FAC ← before.35、after.35      0x49E76 ← before.54、after.54
0x30FC9 ← before.36、after.36      0x4C616 ← before.55、after.55
0x30FE6 ← before.37、after.37
0x31003 ← before.38、after.38
```

⇒ 搬迁时**两个槽都要改**，漏一个就有一场戏走丢了。
`applyScriptRelocations` 扫**全部四张根表**找「值等于旧地址」的槽，共用槽天然都会被改到。

**（b）11 对剧本的字节互相重叠** —— 这一条是**后补的**，
第一版方案漏了它，改出来会「改了一边、另一边不变」：

| 重叠的两段 | 重叠字节 | 共享段里的正文段数 |
|---|---|---|
| `before.4` / `after.4` | 2,729 | 108 |
| `before.20` / `after.20` | 3,201 | 108 |
| `before.51` / `after.51` | 7,317 | 248 |
| `before.53` / `after.53` | 7,987 | 141（两个剧本合计扫到 282 次） |
| `logic.32`..`logic.38` / `events.32`..`events.38` | 每对 106 | 每对 6 |

**成因**：`after` 剧本常常是 `before` 剧本的**后缀** ——
`after.53` 就是 `before.53` 去掉第一条指令（`0x47f40` 的「载入地图 0x1E」）：

```
before.53 根 0x47F40：0x1E 载入地图 → 0x1B 播放音乐 → 0x02 … → 0x01 显示文本 …
after.53  根 0x47F42：              0x1B 播放音乐 → 0x02 … → 0x01 显示文本 …
```

⇒ **共享的那段字节只能搬一份**。只搬 `before.53` 的话，`after.53` 还指着旧地址，
共享段里的对白改了，`after.53` 看到的还是原文。

⇒ 搬迁必须**按字节重叠分组**（`storyvm.js::scriptComponents`，并查集），
一组里的剧本**当作一个整体**搬：合并后的字节只写一份
（`storyvm.js::mergeFragments`，指令按偏移去重），
每个入口各自记下自己的新地址，根表里对应的槽**逐个**改。

### 3.4 空闲区

| 项 | 值 |
|---|---|
| 全 ROM **唯一**一段 ≥4KB 的 0xFF | `0x5DFBEC..0x600000` —— 132,116 字节 |
| `notes/free-space.md` 原来记的 Size | 「~131,092 字节」—— **过时了，已订正** |
| 编辑器实际用的上界 | `0x5FFFFE`（`rom-editor/js/rom.js::FREE_SPACE_END`） |

实测那段 0xFF 确实连到 ROM 末尾 `0x600000`；编辑器按 `notes/free-space.md` 的边界收口
（两条链路边界一致）。

⚠️ **`tools/import_dialogue_var.py` 与 `rom-editor/js/rom.js::allocate` 是两个
互不知情的分配器，共用同一段空闲区。** 谁先谁后都会踩到对方 —— 混用两条链路
必须人工协调。详见 `notes/free-space.md` 的「与编辑器的关系」。

## 4. 实现落点

| 文件 | 东西 |
|---|---|
| `rom-editor/js/storyvm.js` | `ADDRESS_SLOTS`（重基白名单）、`scriptFragments`（拆连续段）、`mergeFragments`（合并重叠段、指令去重）、`scriptComponents`（按字节重叠分组）、`planRelocation`（**纯函数**：规划搬迁 + 重基） |
| `rom-editor/js/rom.js` | `applyScriptRelocations()`（构建时搬迁 + 改根指针 + 折叠剧本内补丁）、`FREE_SPACE_END` |
| `rom-editor/js/scripttext.js` | `commitSegment`（不再拒绝不等长，返回值多了 `relocated`）、`segmentBudget`（报 `delta`）、`scriptOwner`（这段正文属于哪个剧本） |
| `rom-editor/js/pack.js` | `patchOriginalExtent`（补丁的**原始范围**）、`textSlotKind`（文本表三种形态） |

**构建顺序变了**：结构 → 文本 → **剧本搬迁** → 补丁最后写。
剧本搬迁必须排在补丁**前面** —— 补丁的 `offset` 说的是**原版**里的位置，
搬迁之后它就失效了，所以搬迁时要把剧本内部的**所有补丁折进**搬走的那份字节里，
折进去的补丁由 `applyPatches` 跳过（不重复写）。

**补丁的 `before_hex` 必须是原版的字节** —— 搬迁按原版布局算偏移。
所以 `patchOriginalExtent` 按 `before_hex` 的长度算「这段补丁占多大地方」，
不用 `after_hex` 的长度（变长的补丁写回去之后，后面的字节全右移，
但后面那条补丁的 `offset` 说的是原版里的位置）。

## 5. 界面上怎么说（结论变了，界面必须跟着变）

| 情况 | 界面（`rom-editor/js/modules/scriptview.js` / `dialogueview.js`） |
|---|---|
| 字节数相等 | 绿色「等长，失焦即保存」 |
| 多了 N 字节 | 琥珀色「**变长 N 字节：构建时整个剧本会搬到空闲区**」 |
| 少了 N 字节 | 琥珀色「**变短 N 字节：构建时整个剧本会搬到空闲区**」 |
| 字库缺字 | 变红，仍旧拒收（绝不默默丢掉那个字） |
| **不属于任何剧本**（孤儿代码） | 变红拒收，并说清「它不在任何能搬迁的剧本里（后面没有东西能给它让位），只能等长改写」 |

## 6. 别的文本表：9 张可变长、2 张结构上就变不了

判定：`pack.js::textSlotKind(table, record)` → `pointer` / `fixed` / `absolute`。

| 形态 | 表 | 变长 |
|---|---|---|
| `pointer`（指针表驱动） | **9 张**：`character_names` / `training_names` / `jutsu_names` / `ninjutsu_names` / `material_names` / `mission_titles` / `mission_descriptions` / `mission_hints` / `quiz_questions` | **能** —— 正文搬到空闲区、指针改掉（这条能力早就有，本轮补了**逐表**验收） |
| `fixed`（定长内联槽，12 字节一条写死在表里） | `speaker_names`（说话人名表） | **不能** —— 没有指针可以改 |
| `absolute`（绝对地址引用，地址在代码里写死） | `battle_objectives`（战斗目标说明文字） | **不能** —— 改地址就得改代码 |

界面上现在会把**后两类的原因分别说出来**
（「这条是定长内联槽，槽的大小写死在表里」/「这条的地址在代码里写死，搬不动」）
—— 不再只说一句「只能等长」。见 `rom-editor/js/editors.js::slotReason`。

## 8. 已知未闭合 / 风险

| 项 | 说明 |
|---|---|
| **真机没跑过** | 搬迁后的 ROM 只做过**静态回扫**（`scanScript` 指令数、目标落点），**没有在 mGBA / 模拟器里真机跑过**。这是最大的缺口。 |
| 只有根表能进剧本 | 静态证明「只有四张根表能进剧本」；缺**动态确认**（没有跟着 `0x080977B8` 的 VM 入口逐条走）。 |
| 孤儿代码来历不明 | 剧本区里有**不属于任何剧本**的字节（2,145 字节），来历没查清。它们不能变长（无处可搬）。 |
| 两个分配器抢同一段空闲区 | `tools/import_dialogue_var.py` 与编辑器的 `allocate` 互不知情。 |
| 旧位置不回收 | 每次搬迁都在空闲区里多占一份；搬多了会不够。空闲区 132KB，最大剧本 42KB。 |
| 加分支 / 加新对白 | 那要改的是**控制流**（新增分支目标 / 新增指令），不只是搬字节 —— 仍然做不了。 |
| 控制码本身 | 只能**原位保留**，不能新增 / 删除 / 挪位置（要改请用「原始字节」模块按字节改）。 |
