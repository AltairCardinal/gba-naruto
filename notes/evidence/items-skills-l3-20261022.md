# `items` / `skills`（`0x08545BE4`）的运行时证据（2026-10-22）

## 1. 表的读法

读者 `fn 0x0806D910`：

```
0x0806D916: lsls r0, r0, #0x18
0x0806D918: lsrs r0, r0, #0x14    ; r0 = (id & 0xFF) * 16
0x0806D91A: ldr  r1, [pc, #0x44]   ; r1 = 0x08545BE4
0x0806D91C: adds r0, r0, r1       ; 记录 = 表 + (id & 0xFF) * 16
0x0806D924: ldrb r1, [r0]         ; 记录[0]
0x0806D928: ldrh r1, [r0, #2]     ; 记录[2..3]
...
```

⇒ **16 字节/条**（与旧笔记一致，但下标公式此前没钉死）。
读者把它展开成一个 12 字节的输出结构：
`out[0] = 5`（类型标记）、`out[1] = 记录[0]`、`out[2..3] = 记录[2..3]`、
`out[4..9] = 记录[4..9]`，`out[0xA..0xF]` 清零。

## 2. 路线：剧情战斗 → 单位扫描 → `fn 0x080833A8`

`fn 0x080732B4`（剧情战斗）里有一段**单位扫描**：

```
0x0807421E: cmp  r0, #0        ; 单位 id != 0
0x08074228: cmp  r0, #0        ; unit[0xCC] == 0
0x08074236: cmp  r0, #0        ; unit[0xC0] & 0x70 == 0
0x08074240: cmp  r0, #0xFF     ; unit[0xCD] != 0xFF
0x08074244: cmp  r0, #0        ; unit[0xCD] != 0
0x0807425A: bl   fn 0x080851F8
```

`fn 0x080851F8` 按 `unit[0xC0]` 的 **bit 0** 分岔：

```
0x080852B4: ldr  r0, [r2]      ; unit[0xC0]
0x080852B8: ands r0, r1        ; r1 = 1
0x080852BE: bne  0x080852F4
0x080852C4: bl   fn 0x080833A8 (unit, 4)
0x080852F8: bl   fn 0x080833A8 (unit, 6)
```

`fn 0x080833A8` 里才是真正的读表点：

```
0x080837C4: adds  r1, r3, r0    ; r1 = 0x0202D4CD + r4*6
0x080837C6: ldrb  r2, [r1]
0x080837C8: movs  r0, #0x80
0x080837CA: ands  r0, r2
0x080837CE: bne  0x08083804    ; ★ bit7 置位 -> 走读者
...
0x08083804: movs  r0, #0x7F
0x08083806: ands  r0, r2        ; id = 字节 & 0x7F
0x08083808: mov   r1, sb
0x0808380A: ldr   r6, [pc, #0x84]  ; 0x0202D228
0x0808380C: movs  r7, #0xED
0x0808380E: lsls  r7, r7, #6
0x08083810: adds  r2, r6, r7
0x08083812: bl    fn 0x0806D910  ; ★ 读者
```

**⇒ 完整门控**：
单位 `id != 0`、`unit[0xCC] == 0`、`unit[0xC0] & 0x70 == 0`、
`unit[0xCD] ∉ {0, 0xFF}`、`unit[0xC0]` 的 bit 0 决定走哪条臂，
以及每条道具记录的 **标志字节（`0x0202D4CD + r4*6`）的 bit 7 必须置位**。

## 3. 运行时读数

`build/probe_items2.py`（按场景顺序推进，相位 `0x0110`，场景 10）：

```
[item flag byte 0x0202D4CD: 0x01 -> 0x81]
[item flag byte 0x0202D4D9: 0x4A -> 0xCA]
[item flag byte 0x0202D4DF: 0x05 -> 0x85]

{"hit": "0x08083812", "r0": "0x00000001"}   ; 道具 id 1
{"hit": "0x0806D91A", "r0": "0x00000010"}   ; ★ 读者：r0 = id * 16
{"hit": "0x08083812", "r0": "0x0000004A"}   ; 道具 id 74
{"hit": "0x0806D91A", "r0": "0x000004A0"}   ; ★ r0 = 0x4A * 16
{"hit": "0x08083812", "r0": "0x00000005"}   ; 道具 id 5
{"hit": "0x0806D91A", "r0": "0x00000050"}   ; ★ r0 = 5 * 16
```

**寄存器对应关系逐条可算**：`r0 = (id & 0xFF) × 16` = **表内字节偏移**；
`r1` = 记录指针（`0x020249E4`，输出结构）；`r2` = 第三个参数。
下一次指令 `0x0806D91A: ldr r1,[pc,#0x44]` 装的就是表基址 `0x08545BE4`。

**⇒ `items` 与 `skills`（同一张表 `0x08545BE4`）拿到运行时读数。**

## 4. 干预说明

两处**单字节/单比特**的 WRAM 干预，都打印了改前改后的值：

1. **`unit[0xC0]` 的 bit 0**（`0x0807425A` 处写入，单位槽 4）：
   `0x00000080 → 0x00000081`，让 `fn 0x080851F8` 走 `(unit, 6)` 那一臂。
   上游过滤只要求 `unit[0xC0] & 0x70 == 0`，bit 0 是空的。
2. **道具标志字节的 bit 7**（`0x080837C6` 处写入，地址 `0x0202D4CD + r4*6`）：
   `0x01 → 0x81`、`0x4A → 0xCA`、`0x05 → 0x85`，
   让 `fn 0x080833A8` 的分岔走进读者那一臂。

改的都是**游戏自己的字段**，代码未动；战斗照常按正常按键推进。

## 5. 判死检验

| 检验 | 期望 | 实际 |
|---|---|---|
| 记录步长 | `r0 = id × 16` | ✅ 0x10 / 0x4A0 / 0x50 对应 id 1 / 0x4A / 5 |
| 单位过滤 | `unit[0xCD] ∉ {0,0xFF}` 等 | ✅ `0x0807425A` 命中即已过筛 |
| 标志字节 bit7 | 置位才走读者 | ✅ 置位前 `0x08083812` 不命中 |
| 不同道具 | 同一条路径读多个 id | ✅ 3 次命中，3 个不同 id |
| 表基址 | `0x08545BE4` | ✅ `0x0806D91A` 下一条指令装载 |
