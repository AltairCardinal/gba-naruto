# 对白指针表 `0x08461CE8` 的 L2/L3 证据（2026-10-22）

> 配套：`notes/evidence/callback-dispatch-runtime-20261021.md`（回调派发与四个工装 bug）、
> `notes/evidence/level-mode-l3-20261022.md`（关卡模式）、
> `notes/evidence/m4a-songheader-l3-20261022.md`（音频方向）。
> 这一份是**对白文本**方向的证据，也是当前缺口里价值最高的一条
> （L3 价值 5 / 难度 2，另有同结构的 L2 缺口）。

---

## 1. 机制：相位 `0x0210` 是这张表的唯一入口

`fn 0x080914D8` 是对白指针表的**唯一读表准备函数**，而它**只有两个调用者**，
都在**状态机的相位分派**里：

```
0x0808F9E2: movs r0,#3 ; movs r1,#1 ; bl 0x080914D8
0x0808F9EC: movs r0,#3 ; movs r1,#0 ; bl 0x080914D8
0x0808F9F4: movs r0,#0x30 ; strh r0,[r4,#0x12]     ; 相位回到 0x30
```

而相位 `0x0210` 正是**章节交接**在**目标场景为 52（0x34）**时设置的：

```
0x0808F910: ldrb r0,[r4,#0x16]     ; state[0x16] = 场景
0x0808F912: cmp  r0,#0x34           ; 场景 52？
0x0808F914: bne 0x0808F91E
0x0808F916: movs r0,#0x84
0x0808F918: lsls r0,#2              ; 0x210
0x0808F91A: strh r0,[r4,#0x12]      ; 相位 = 0x210
```

**所以这张表既没有字面量读者，也不在剧情脚本的对话路径上** ——
它在**状态机的相位 `0x0210`** 处理器里被读。
（早期笔记「对话指针表 `0x461CE8`」只记了地址，没有读者；
`probe_lit32.py 0x08461CE8` 也是 0 命中 —— 因为基址是被算出来的。）

## 2. 复现命令

```
python tools/mgba_probe/text_table_probe.py rom/base.gba \
    --presses 40 --json build/text-table.json
```

工具做的事只有三件写内存（与 L4 战斗矩阵「三个内存写」的请求模型同型）：

* `state[0x12] = 0x0210`（请求这个相位）；
* 之后按 A 键，让状态机分派该相位。

**没有任何 ROM 改动，也没有对被观测结构的写入。**

## 3. 运行时读数

| 断点 | 命中时寄存器 | 说明 |
|---|---|---|
| `0x0808F9EC` | 相位 = `0x0210` | 状态机确实进了 `0x0210` 处理器 |
| `0x080917B0` | **`r2 = 0x08461CE4`** | **游戏自己的指令把对白指针表的基址装进 r2** |
| `0x0809AACC`（对照） | `r1 = 0x08465B70`、`r2 = 0x08465B40` | 同一帧里音效表也被读了（对照组） |

命中瞬间 dump 出的表内容（`0x08461CE4` 起 48 字节）：

```
00 00 00 00  14 94 45 08  64 94 45 08  70 94 45 08  7c 94 45 08
00 00 00 00  88 94 45 08  e8 94 45 08  f4 94 45 08  fc 94 45 08
00 00 00 00  08 95 45 08
```

**每 4 字节一个 u32 文本块指针**（`0x08459414` / `0x08459464` / `0x08459470` /
`0x0845947C` / 0 / `0x08459488` / `0x084594E8` / `0x084594F4` / `0x084594FC` /
0 / `0x08459508`）—— 与「对白指针表」的结构描述一致。

**可见行为**：命中后游戏自己把 `state[0x16]` 设成了 **`0x36`（场景 54）**，
并显示该场景的对白 —— 也就是说**屏幕上出现的文字正是从这张表里取的**。

## 4. 判死检验

| 检验 | 期望 | 实际 |
|---|---|---|
| 不 poke 相位 | `0x080917B0` 不命中 | ✅（55 场剧情 sweep 全部 0 命中） |
| poke `state[0x12] = 0x0210` | `0x080917B0` 命中，`r2 = 0x08461CE4` | ✅ 命中，`r2 = 0x08461CE4` |
| 表的内容是不是真的对白指针 | 每项是 ROM 内的文本块地址 | ✅ `0x084594xx` 段 |
| 读到的表是不是**对白**表 | 相位 `0x0210` 只有这一处会读它 | ✅ 全 ROM 只有 `0x080914D8` 读它，且只有相位 `0x0210` 调它 |

> **边界声明**：进入这条路径需要 **poke 相位 `0x0210`**（等价于「请求这一相位」，
> 与 L4 战斗矩阵请求一场战斗的三次内存写同型）。相位 `0x0210` 在**自然流程**里
> 由「章节交接且目标场景为 52」产生 —— 也就是说**游戏自己在那个条件下会走这条路**，
> 本次只是把那个请求直接写进去，省掉重跑整条剧情。
> 因此本条证据证明的是「**游戏自己的读表指令执行了**」，
> **不**宣称「任意一场战斗都会读这张表」。
