# 忍具记录表 `0x08545BE4` 的 16 字节字段（2026-10-22 定案）

> 这份笔记是**逐字节**的：忍具记录表那 16 个字节，以前在编辑器里是
> 16 格「未解字节 +0xNN」。这里给出每一格的**作用**（哪段原生代码读它、
> 读成什么宽度、读完之后拿它做什么），以及还差什么才能给出业务名。
>
> 工具：`tools/item_record_fields.py`（**对不上就 exit 1**）
> 证据：本文；内容包字段表：`tools/export_content_pack.py::item_fields`

```powershell
python tools\item_record_fields.py rom\base.gba
python tools\item_record_fields.py rom\base.gba --json build\item-fields.json
```

## 0. 结论摘要

| 偏移 | 标签 | 原生代码怎么用它 | 证据 | 等级 |
|---|---|---|---|---|
| `+0x00` | 忍具类别 | `(类别−1)×4+20` 索引每类自己的表；`0x0806FE96` 按它分岔 | `0x08078F16` / `0x080953B4` / `0x0806FE96` | L1 |
| `+0x01` | 保留 | **没有任何原生读者读它**；94 条恒为 0 | 普查（§4） | L1（证明未用） |
| `+0x02` | 效果 id | 与 `+0x03` 合成 u16 被整个读走；低字节 = 忍具族 id，`0x40` 位 = 毒属性 | `0x0806D928` | L1 |
| `+0x03` | 效果类别 | u16 的高字节：0=烟弹/火弹、1=丸/弹/牌、2=投掷类、4=卷轴 | `0x0806D928` | L1 |
| `+0x04` | 效果数值 | 6 个数值里**唯一会被成长改写并夹在 ≤99** 的那一个 | `0x0806D732` / `0x0806D744` | L1 |
| `+0x05` | 投掷数量（推定） | 被搬进 16 字节槽位的第 2 个数值 | `0x0806D932` | 分布推定 |
| `+0x06` | 命中率 %（推定） | 槽位第 3 个数值 | `0x0806D936` | 分布推定 |
| `+0x07` | 动画 id | 槽位第 4 个数值（投掷类 130..134，其余 1..4） | `0x0806D93A` | 分布推定 |
| `+0x08` | 变体号（推定） | 槽位第 5 个数值 | `0x0806D93E` | 分布推定 |
| `+0x09` | 效果标记（推定） | 槽位第 6 个数值 | `0x0806D942` | 分布推定 |
| `+0x0A` | 特效分类 id | **逐条比对这张表**来挑记录 | `0x0808FF7C` | L1 |
| `+0x0B` | 特效槽键 | 拿它去 4 字节节点表里找同键的槽位 | `0x0808FF88` | L1 |
| `+0x0C` | 分类匹配字节（高） | 逐字节比对来定位记录（0/2/13/19） | `0x0808FC2E` | L1 |
| `+0x0D` | 分类匹配字节（低） | 同上（0/21） | `0x0808FC44` | L1 |
| `+0x0E` | 保留 | **没有任何原生读者读它**；94 条恒为 0 | 普查（§4） | L1（证明未用） |
| `+0x0F` | 保留 | **没有任何原生读者读它**；94 条恒为 0 | 普查（§4） | L1（证明未用） |

**「推定」的四格为什么还是推定**：它们在数据上高度自洽（手里剑 3 枚、飞镖 1 枚、
千本 5 枚；命中率 85/90/95/100 全是 5 的倍数且封顶 100；变体号在烟弹一系是
普通/强力/超 = 1/2/3），但**没有任何一条原生指令单独读它们**做某个可观察的
运算 —— 读者只把它们整段搬进槽位。要定案需要 §7 列的那条证据。

## 1. 表的几何与 id 空间

| 项 | 值 | 证据 |
|---|---|---|
| 基址 | `0x08545BE4` | 7 处字面量装载（§3） |
| 步长 | 16 字节 | `0x0806D918: lsrs r0,r0,#0x14`（`id<<4`） |
| 条数 | 94 | `0x545BE4 + 94×16 = 0x5461C4`（正好接战斗编成矩阵） |

名表与记录表逐条对齐已核对：id 1 = 十字手里剑、id 93 = 超万能丸。

## 2. 记录被搬进「16 字节槽位」的方式

`fn 0x0806D910`（忍具记录读取器）把记录摊成 16 字节：

```
0x0806D920: movs r1, #5
0x0806D922: strb r1, [r4]        ; 槽[0] = 5   ← 常量标记：这条是「忍具」
0x0806D924: ldrb r1, [r0]        ; 槽[1] = 记录[0x00]
0x0806D928: ldrh r1, [r0, #2]    ; 槽[2..3] = 记录[0x02..0x03]
0x0806D92E: ldrb r1, [r0, #4]    ; 槽[4] = 记录[0x04]
0x0806D932: ldrb r1, [r0, #5]    ; 槽[5] = 记录[0x05]
0x0806D936: ldrb r1, [r0, #6]    ; 槽[6] = 记录[0x06]
0x0806D93A: ldrb r1, [r0, #7]    ; 槽[7] = 记录[0x07]
0x0806D93E: ldrb r1, [r0, #8]    ; 槽[8] = 记录[0x08]
0x0806D942: ldrb r0, [r0, #9]    ; 槽[9] = 记录[0x09]
0x0806D946: strh r2, [r4, #0xa]  ; 槽[0x0A..0x0F] = 0
```

⇒ **记录的第 1、10..15 字节不参与搬运**；被搬进槽位的是
`0x00` 与 `0x02..0x09`。

**这个槽位是带标签的联合体**：忍术记录表 `0x08545458` 的读取器
`fn 0x0806D85C` 是把 16 字节**原样**搬进同一个槽位（`ldm/stm` + 一条 `ldr`），
所以：

* 槽[0] = 5 ⇒ 忍具；
* 槽[0] ≠ 5 ⇒ 忍术（槽[0] 就是忍术记录的类型字节）。

战斗里读槽位的代码按槽[0] 分岔（`0x08071542` 读槽[0]，等于 2 走一条、
等于 1 走另一条），所以**同一套槽位布局对忍术与忍具各有各的含义** ——
这也是为什么忍具记录表的 `+0x0C` 不是忍术那边的「成长目标」：
忍具的 `+0x0C` 取值是 0/2/13/19，而忍术的成长目标只能是 0..7。

## 3. 七个原生读者

工具用**位模式**扫全 ROM 的 `ldr Rt,[pc,#imm]`（`01001`），把字面量解析出来：

| 装载指令 | 所属函数 | 读什么 |
|---|---|---|
| `0x0806D91A` | `fn 0x0806D910`（忍具记录读取器） | `+0x00`、`+0x02..+0x09`（§2） |
| `0x08078EF8` | `fn 0x08078E..`（剧情战斗选招） | `+0x00`（配合 `0x08078F16`） |
| `0x08078F08` | 同上 | `+0x00`（另一条臂） |
| `0x0808FC28` | `fn 0x0808FC20`（按分类找记录） | `+0x0C` / `+0x0D` |
| `0x0808FF78` | `fn 0x0808FF24`（按特效挑记录） | `+0x0A` / `+0x0B` |
| `0x08095394` | `fn 0x080953..`（另一套战斗流程） | `+0x00`（配合 `0x080953B4`） |
| `0x080953A4` | 同上 | `+0x00`（另一条臂） |

> **踩过的坑（写下来免得再踩）**：16 位 Thumb 的 `LDR(literal)` 在寄存器是
> `r1..r7`（字长）时，**imm8 要乘 4**。不乘 4 就会把字面量池地址算错 4 倍，
> 普查会得出「0 处读者」这种假结论。工具里写死了这条规则。

## 4. 「没有原生读者」的三格 —— 怎么证明的

把 §3 的 7 个读者逐条拆开，列出它们**实际读到的偏移**：

| 读者 | 读到的偏移 |
|---|---|
| `fn 0x0806D910` | `00`、`02`、`03`、`04`、`05`、`06`、`07`、`08`、`09` |
| `fn 0x08078E..` / `fn 0x080953..` | `00` |
| `fn 0x0808FC20` | `0C`、`0D` |
| `fn 0x0808FF24` | `0A`、`0B` |

并集 = `{00, 02..0B, 0C, 0D}`。**缺的三格 = `+0x01`、`+0x0E`、`+0x0F`**，
且这三格在 94 条记录里**恒为 0**。

⇒ 这三格是**保留字节**：不是「还没查到」，而是**原生代码不读**。
内容包里它们标「保留」并置 `not_read`（界面降级为只读），
免得作者白改一个没人读的字段。

工具的核对方式是**直接解码那两字节 Thumb 指令**（`ldrb/ldrh` 的立即数偏移、
`adds rX,#imm8`、`cmp rX,#imm8`），任何一条对不上就 `exit 1`。
其中 `0x0808FC44` 是「寄存器 + 常量」型：`+0x0C` 是加在基址上的常量，
循环变量再逐次 +1，所以同一段代码扫过 `+0x0C` 与 `+0x0D` ——
这一条当初差点被记成「只读 `+0x0C`」，是工具自己核对出来的。

## 5. 逐字段的证据

### 5.1 `+0x00` 忍具类别（1 / 3 / 5）

```
0x08078F16: ldrb r7, [r1]        ; r7 = 记录[0]
0x08078F20: subs r0, r7, #1
0x08078F2C: lsrs r0, r0, #0xe    ; r0 = (类别−1)×4
0x08078F2E: ldrh r2, [r5, #0xa]  ; + 战斗结构里的一个 u16
0x08078F34: lsls r1, r4, #2      ; + 20
0x08078F38: strh r0, [r6, #0x10]
```

⇒ 类别决定**索引哪一张每类自己的表**（1 = 投掷类、3 = 烟弹/火弹、5 = 卷轴/弹/牌/丸）。
`0x0806FE96` 另有一处按类别分岔（类别 3 单独走一条臂）。

### 5.2 `+0x04` 效果数值（0..100）

`fn 0x0806D6B8`（技术成长结算）会改写槽位的 `+0x04`：

```
0x0806D732: ldrb r4, [r5, #4]    ; 槽[4]
0x0806D736: muls r0, r2, r0      ; × 成长量
0x0806D73A: bl   0x0809C14C      ; ÷ 100
0x0806D744: cmp  r0, #0x63       ; 99
0x0806D74A: subs r0, r0, r4      ; 夹在 0..99
0x0806D752: strb r0, [r5, #4]
```

⇒ 槽[4] 是**会随成长变化、上限 99** 的那一个数值。
数据侧也自洽：兵粮丸 40/70/100（回复量）、查克拉丸 3/5/8、强壮丸 10/30/50（提升量）、
手里剑 6/10/14（威力）—— 同一格里「回复量 / 提升量 / 威力」共用一个量纲，
所以标签写中性名「效果数值」。

### 5.3 `+0x0A` / `+0x0B`（特效分类 id / 特效槽键）

`fn 0x0808FF24` 扫全表挑记录：

```
0x0808FF7C: ldrb r1, [r2, #0xa]  ; 记录[0x0A]
0x0808FF80: cmp  r1, sl          ; 与目标值比
0x0808FF88: ldrb r6, [r2, #0xb]  ; 记录[0x0B]
0x0808FFA4: ldrb r0, [r0]        ; 节点表的键
0x0808FFA6: cmp  r0, r6
0x0808FFB0: strb r1, [r0]       ; 把记录下标写进节点
```

⇒ `+0x0A` 是**匹配用的分类**（挑记录），`+0x0B` 是**节点表的键**（找槽位）。

### 5.4 `+0x0C` / `+0x0D`（分类匹配字节）

`fn 0x0808FC20` 按这两个字节找记录：

```
0x0808FC2E: ldrb r0, [r0, #0xc]  ; 记录[0x0C]
0x0808FC3E: adds r3, #0xc        ; 循环里基址加常量
0x0808FC44: ldrb r0, [r0]        ; 记录[0x0C + 循环变量]
0x0808FC50: cmp  r2, #1          ; 变量 0..1 ⇒ 扫过 +0x0C 与 +0x0D
```

⇒ 这两格是**成对的分类标记**：无限手里剑一系 `+0x0C` = 13，
千本一系 `+0x0C` = 19、`+0x0D` = 21。

### 5.5 四个「推定」格的取值分布

| 偏移 | 取值集合 | 分布线索 |
|---|---|---|
| `+0x05` | 0,1,3,4,5 | 手里剑 3 / 飞镖 1 / 千本 5 / 铝手里剑 4→5 / 其余 1 |
| `+0x06` | 0,85,90,95,100 | 手里剑 90 / 飞镖 95 / 千本 85 / 其余 100 |
| `+0x07` | 0,1,2,3,4,130..133 | 投掷类 130..134，弹/丸/卷轴 1..4 |
| `+0x08` | 0,1,2 | 烟弹/火弹的普通/强力/超 = 1/2/3，投掷类固定 1 |
| `+0x09` | 0,1,2,4 | 软气弹/粘着弹/钝足弹一系 = 4 |

## 6. 与忍术记录表 `0x545458` 的关系

两张表**记录长度相同**（16 字节），但**不是同一种结构**：

* 忍术记录表（87 条，下标 = 忍术 id，`0x0859937C` 同空间）的字段语义已定案
  （见 `notes/character-template-format-20261020.md` §7）：
  `+0x02` 位域、`+0x04..+0x09` 六个成长目标、`+0x0C` 成长目标、`+0x0E` 每级成长量。
* 忍具记录表（94 条）的 `+0x0C` 取值 0/2/13/19，**落在「成长目标 0..7」之外**，
  而且 `fn 0x0806D85C`（忍术读取器）**根本不碰忍具表**。
* 两者的 `+0x00` 与 `+0x02..+0x09` 被搬进**同一个槽位**，所以槽位布局共用；
  但 `+0x0A` 之后各说各话。

⇒ **不要把忍术的字段名套到忍具表上**（`+0x0E` 在忍术表是「每级成长量」，
在忍具表是保留字节）。

## 7. 还差什么才能给那四格定名

| 格 | 需要的证据 | 找它的入口 |
|---|---|---|
| `+0x05` 投掷数量 | 一条**单独**读槽[5] 并拿它做乘法/计数的指令（例如「一次投 N 个」） | 战斗里使用忍具的流程：`0x08078E..`、`0x080953..` 的下游 |
| `+0x06` 命中率 % | 一条把槽[6] 与 0..100 的量纲联系起来的运算（命中判定） | 命中判定代码 |
| `+0x07` 动画 id | 一条把槽[7] 索引进精灵/动画表的指令 | 精灵动作表读者（`0x08596CCC` 一族） |
| `+0x08` / `+0x09` | 一条单独读槽[8] / 槽[9] 的指令 | 同上 |

**L2 取证路线**（本轮没做）：`tools/mgba_probe/` 的断点机制可以在
`0x0806D944`（槽位填好）处停下并读出 16 字节，再改 ROM 里的一个字节，
看战斗里的**伤害数字 / 投出个数 / 是否命中**有没有变 ——
那才是从「分布」升级到「指令 + 观测」的证据。

## 9. 对续作写回的意义

* 这张表现在**可以按字段改**（编辑器构建线 `rom.js::applyStructures` 会原样写回）。
* 改 `+0x04`（效果数值）时注意：它会经过成长结算并被夹在 0..99；
  写 100 及以上在战斗里会被截成 99。
* 改 `+0x0A` / `+0x0B` 时注意：这两个值决定**原生代码挑不挑得到这条记录**
  （`fn 0x0808FF24`）以及**挂不挂得上特效槽**（`fn 0x0808FF24` 的节点表）。
  改坏了，忍具可能变成「用得出来但没有特效」。
* 改 `+0x0C` / `+0x0D`（分类）时注意：`fn 0x0808FC20` 靠它们找记录。
* 三格「保留」改了不起作用（原生代码不读），写回也是白写。
