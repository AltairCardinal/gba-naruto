## 1. 两张表的关系

### 1.1 内存布局（文字版）

                │  id 63    = 「没有」                        │

`id 1` 才开始出现在 `0x085A5F77`（与全名表 id 63 的**最后一个填充字节**重叠 1 字节）。

| 身份 | 地址 | 步长 | 备注 |
|---|---|---|---|
| 简称表 id 63 | `0x085A5AB8` | 12 | 与「全名 id 0」同址 |
| 全名表 id 0 | `0x085A5AB8` | 19 | 与「简称 id 63」同址 |
| 地点名表 id 0 | `0x085A5F65` | 18 | 与「全名 id 63」同址 |

## 3. 全名表那 3 个读者读来干什么

### 3.0 先说方法：步长是**机器验证**的，不是看出来的

三处访问都是「`ldr rX,[pc,#imm]` 取基址 + 若干条 `lsls/adds/subs` 算偏移」。
探针里写了一个**符号求值器**（`tools/probe_speaker_id63.py::detect_stride`）：
把每个寄存器当作线性表达式 `a·X + b`（有理数）向前重放，
在「基址被加进去」的那条 `adds` 处读出系数 `a` ⇒ **步长**。

- ROM 没有乘法指令，步长只可能是 `lsls/adds/lsls`（`(2^k+1)·2^m`）或再加一条 `subs`（`−1`）。
- 求值器在 **16 个已知站点上全部复现了人工结论**（12 个简称读者 = 12、3 个全名读者 = 19、地点名 = 18），0 失配。

### 3.1 读者 ① `0x08077EE2` —— 画「全名」的 UI 路径

```
0x08077DB8  ldr  r0, [pc, #0x28c]   ; -> 0x08599280  ★人物名指针表（步长 4）
0x08077DBA  ldr  r1, [sp, #0x38]    ; r1 = 角色 id
0x08077DBC  lsls r1, r1, #2         ; id*4
0x08077DBE  mov  sl, r1             ; sl = id*4
0x08077DC0  add  r0, sl
0x08077DC2  ldr  r0, [r0]           ; r0 = 指针表[id]  → 另一份名字
0x08077DC4  ...
0x08077DC8  bl   #0x80667A0         ; 把那份名字画进对象

0x08077ED8  ldr  r0, [sp, #0x38]    ; r0 = 角色 id（同一个 id）
0x08077EDA  add  r0, sl             ; sl 还是 id*4
0x08077EDC  lsls r0, r0, #2         ; (id + id*4)*4 = id*20
0x08077EDE  ldr  r3, [sp, #0x38]    ; r3 = id
0x08077EE0  subs r0, r0, r3         ; id*20 - id = id*19
0x08077EE2  ldr  r1, [pc, #0x19c]   ; -> 0x085A5AB8  ★全名表基址
0x08077EE4  adds r0, r0, r1         ; 0x085A5AB8 + id*19
0x08077EE6  mov  r1, sb
0x08077EE8  str  r1, [sp]
0x08077EEA  movs r1, #0
0x08077EEC  adds r2, r7, #0
0x08077EEE  movs r3, #0xd
0x08077EF0  bl   #0x8066758         ; ★把「全名」画进文本框
```

**判定**：base = `0x085A5AB8`，**步长 = 19** ⇒ 读的是**全名表的第 id 条**。
id 来自函数入参（`[sp,#0x38]`），**同一个 id 还被拿去索引 `0x08599280` 的人物名指针表**。
用途：**把「全名」画进文本框**（同一个 id 同时用来取头像/名字）。
（具体是哪个界面**没有追**，只确认了它画的是「全名」而不是「简称」。）

### 3.2 读者 ② `0x0808B036` —— 画「全名」的 UI 路径

```
0x0808B014  ldr  r1, [pc, #0x68]    ; -> 0x08599280  ★人物名指针表
0x0808B016  ldrb r0, [r6, #1]       ; r0 = 记录里的角色 id
0x0808B018  lsls r0, r0, #2
0x0808B01A  adds r0, r0, r1
0x0808B01C  ldr  r0, [r0]           ; 指针表[id]
0x0808B028  bl   #0x8066758         ; 画出去

0x0808B02C  ldrb r1, [r6, #1]       ; r1 = 同一个 id
0x0808B02E  lsls r0, r1, #2          ; id*4
0x0808B030  adds r0, r0, r1          ; id*5
0x0808B032  lsls r0, r0, #2          ; id*20
0x0808B034  subs r0, r0, r1          ; id*19
0x0808B036  ldr  r1, [pc, #0x4c]    ; -> 0x085A5AB8  ★全名表基址
0x0808B038  adds r0, r0, r1          ; 0x085A5AB8 + id*19
0x0808B044  bl   #0x8066758         ; ★把「全名」画出去
```

**判定**：base = `0x085A5AB8`，**步长 = 19** ⇒ **全名表的第 id 条**。
id 来自一条**记录的第 2 个字节**（`[r6,#1]`），同一个 id 也去索引 `0x08599280` 的人物名指针表。
用途：**把「角色的全名」画在头像/名字旁边**（具体界面**没有追**）。

### 3.3 读者 ③ `0x080939D6` —— 画「全名」的 UI 路径

```
0x080939CA  mov  r0, sl             ; sl → 指向一个字节
0x080939CC  ldrb r1, [r0]           ; r1 = 角色 id
0x080939CE  lsls r0, r1, #2          ; id*4
0x080939D0  adds r0, r0, r1          ; id*5
0x080939D2  lsls r0, r0, #2          ; id*20
0x080939D4  subs r0, r0, r1          ; id*19
0x080939D6  ldr  r1, [pc, #0x280]   ; -> 0x085A5AB8  ★全名表基址
0x080939D8  adds r0, r0, r1          ; 0x085A5AB8 + id*19
0x080939DA  str  r5, [sp]
0x080939DC  movs r1, #0
0x080939DE  adds r2, r7, #0
0x080939E0  movs r3, #0xd
0x080939E2  bl   #0x8066758         ; ★把「全名」画出去
```

**判定**：base = `0x085A5AB8`，**步长 = 19** ⇒ **全名表的第 id 条**。
（该函数在 `0x080938BC` 也用 `0x08599280` 的人物名指针表，index 同源。）

### 3.4 三者的共同点与差别

| | base 字面量 | 步长 | id 来源 | 用途 |
|---|---|---|---|---|
| ① `0x08077EE2` | `0x085A5AB8` | **19** | 函数入参 `[sp,#0x38]` | 画**全名**（同 id 也查 `0x08599280` 人物名指针表） |
| ② `0x0808B036` | `0x085A5AB8` | **19** | 记录字节 `[r6,#1]` | 画**全名**（同 id 也查 `0x08599280`） |
| ③ `0x080939D6` | `0x085A5AB8` | **19** | 指针指向的字节 `[sl]` | 画**全名**（同 id 也查 `0x08599280`） |

**三者读的都是「全名表」，不是「简称表 id 63」。**
它们的 id **不来自剧情脚本**，而来自**角色/队伍记录**（同一个 id 也用来查 `0x08599280` 的人物名指针表）。
⇒ 即使这些界面某天请求了 id 63，它们拿到的也是**全名表第 63 条**，仍然是「没有」。

（三处的**具体界面没有追**；已确认的是「它们画的是全名、id 来自角色记录而非剧情脚本」——这两点才是 U4 需要的。）

### 3.5 顺带发现的**第 4 处**落在这个区域里的引用（不是全名读者）

全 ROM 扫 `ldr [pc,#imm]` 字面量时，除 12 + 3 处基址外，还有一处指向区域内部的。
扫描范围取 `0x085A57C4..0x085A6342`（**三张表全在内**：简称表 + 全名表 + 地点名表），
命中**恰好 16 处**：12 个简称基址 + 3 个全名基址 + 下面这 1 处。

```
0x0808CD86  ldrb r0, [r4]            ; 地图记录里的地图 id
0x0808CD88  lsls r1, r0, #3          ; id*8
0x0808CD8A  adds r1, r1, r0          ; id*9
0x0808CD8C  lsls r1, r1, #1          ; id*18      ← 步长 18，不是 19
0x0808CD8E  ldr  r0, [pc, #0xa0]     ; -> 0x085A5F65
0x0808CD90  adds r1, r1, r0          ; 0x085A5F65 + id*18
0x0808CD92  mov  r0, sl
0x0808CD94  bl   #0x809C4DC           ; strcpy(缓冲, 地点名)
```

**步长 = 18 ⇒ 这是一张「地点名表」（地图地名），不是全名表。**
`0x085A5F65 + 18·i` 解出来是：

```
id 0  '没有'      id 1  '村边的森林'  id 2  '入口之森'    id 3  '木叶村'
id 4  '修炼之森'  id 5  '达兹纳的家'  id 6  '桥的入口'    id 7  '桥上'
…                                                    id 54 '一乐拉面'
（55 条，id 0..54，占 0x085A5F65..0x085A6342）
```

它的 **id 0「没有」又和全名表的 id 63 同址** —— 这是同一个「没有」字节块的**第三种身份**。

## 4. 转换（指针表 + 变长串池）与这张表的空间关系

| 项 | 地址/大小 | 与转换是否冲突 |
|---|---|---|
| 新指针表（64 × 4） | `0x085A57C4 .. 0x085A58C3` | — |
| 原简称表区（id 0..62） | `0x085A57C4 .. 0x085A5AB7` | 指针表只覆盖前 256 B；后面的旧字形码残留（这是 **U1** 的问题，不是 U4） |
| 全名表（id 0..63） | `0x085A5AB8 .. 0x085A5F77` | **不冲突**：指针表末尾 `0x085A58C3` 距全名表起点还有 **500 字节** |
| 地点名表（id 0..54） | `0x085A5F65 .. 0x085A6342` | **不冲突**：转换只写 `0x085A57C4..0x085A58C3` + 尾部空闲区 |

**指针相等性检查**：全 ROM 里只有 3 个字面量指向 `0x085A5AB8`，而且这 3 处**都是当基址用**（`adds rX, rX, r1`），
**没有任何代码拿名字指针去和 `0x085A5AB8` 做相等比较** ⇒ 转换后「简称 id 63 的字节被搬到别处」这件事**无法被任何代码观测到**。

**可达性穷举**：把扫描范围扩到 `0x085A57C4..0x085A6342`（三张表全在内），
全 ROM 命中**恰好 16 处** pc 相对字面量：12 个简称基址（步长 12）、3 个全名基址（步长 19）、1 个地点名基址（步长 18）。
**没有第 17 处** ⇒ 除这 16 处外，没有任何代码路径能碰到这三张表里的任何一条记录。

**转换前后的语义对照（id 63）**

| | 转换前 | 转换后 |
|---|---|---|
| 简称路径 id 63 | `0x085A57C4 + 63×12 = 0x085A5AB8` → 字节 `92 59 9a 9a 00` → 字符串「没有」 | 指针表 `[63]` → 串池里的一份「没有」→ 字符串「没有」 |
| 全名路径 id 0 | `0x085A5AB8` → 「没有」 | **一个字节都没动** → 「没有」 |
| 全名路径 id 63 | `0x085A5F65` → 「没有」 | **一个字节都没动** → 「没有」 |
| 地点名路径 id 0 | `0x085A5F65` → 「没有」 | **一个字节都没动** → 「没有」 |

⇒ **四条路径给出的字符串完全一致，只有地址变了。**

## 5. 最终判定

### **U4 证伪**

> 台账判据：「所有用到 id 63 的地方都只关心『没有』这一个字符串 ⇒ U4 证伪」

逐条落实：

1. **剧情 VM 从不请求 id 63**。`op 0x08` 用过的 49 个 id 全在 `1..61`，`op 0x0E` 只用 `{1,2,3,25,26}`；
   ROM 全量走查与内容包 202 条剧本两路数据源**id 集合逐位相同**。（§2）
2. **读 `0x085A5AB8` 的 3 个读者读的是「全名表第 id 条」，不是「简称表 id 63」**——
   步长 **19** 由符号求值器机器验证（3/3）。它们的 id 来自角色/队伍记录，不是剧情脚本。（§3）
3. **区域内部第 4 处引用（`0x0808CD8E`）步长是 18**，是**地点名表**，同样不是全名读者。
   把扫描范围扩到三张表全体后，全 ROM **只有 16 处** pc 相对字面量落在这片区域（12+3+1）。（§3.5）
4. **转换不会改写全名表任何一个字节**，指针表与全名表之间有 500 字节空隙。（§4）
5. **没有任何代码比较名字指针与 `0x085A5AB8`**，所以「简称 id 63 的字节搬到串池」这件事无法被观测。（§4）
6. **地址重合是 ROM 刻意的存储别名**：同一个「没有」字节块同时扮演「简称 id 63」「全名 id 0」「地点名 id 0」，
   三者的**字符串内容本来就完全一样**，转换没有改变任何一处的内容语义。

⇒ **不存在「某处依赖 id 63 的全名语义」的代码；转换后 id 63 的语义与转换前逐字节等价。假设 U4 证伪。**

### 顺带产出的两条新事实（不是 U4 的结论，但值得进台账）

| # | 事实 | 影响 |
|---|---|---|
| N1 | **`0x085A5F65` 起是第三张表：地点名表，步长 18 字节/条，55 条（id 0..54），`0x085A5F65..0x085A6342`**；它的 id 0「没有」与全名表 id 63 同址 | 项目「保护区 `0x085A5AB8..0x085A5F78`」只覆盖了**全名表**；地点名表的 id 1..54 在保护区之外。转换不写那里 ⇒ **无风险**，但保护区的推导依据要补一句 |
| N2 | **地点名表与全名表都还没登记进 `tools/table_registry.py` 和内容包**（`table_registry.py` 里 `0x5A5AB8`/`0x5A5F65` 都不存在；内容包 116 张结构表里也没有步长 18 的表） | 内容包缺口。**本次未改**（按分工，`rom-editor/` 与 `tools/table_registry.py` 不在可动范围内） |

## 6. 方法

### 6.1 探针

`tools/probe_speaker_id63.py`（只读，不写 ROM），一次跑完四段：

| 段 | 内容 | 关键输出 |
|---|---|---|
| A | `op 0x08` / `op 0x0E` 的 id 直方图（ROM 走查 + 内容包 202 条剧本，交叉校验） | id 集合、最大值、≥63 的 id |
| B | 两张表逐条解码 + 索引对齐统计 | 64 行对照表、全名表边界探测 |
| C | 3 个全名读者的 ±0x40 反汇编 + 字面量解析 + **步长机器验证** | 每处的 base 与步长 |
| D | 转换足迹 + **全 ROM `ldr [pc,#imm]` 字面量扫描**（范围 `0x085A57C4..0x085A6342`） | 16 处命中：12 简称（步长 12）+ 3 全名（步长 19）+ 1 地点名（步长 18） |
| E | 地点名表（18 B）解码与别名关系 | 55 条、id 0 = 全名 id 63 |

### 6.2 判定动作（都是一次得出是/否）

1. **id ≥63 有没有出现过？** → 枚举两个数据源的全部 `op 0x08`/`0x0E` 操作数字节 → **没有**。
2. **`0x085A5AB8` 被读成什么？** → 反汇编 3 个读者 + 符号求值器算步长 → **步长 19 = 全名表**。
3. **还有没有别的路径能落到这块区域？** → 全 ROM 扫 `ldr [pc,#imm]` 字面量（Thumb-1 编码 `01001 Rt imm8`）→ **只有 1 处**（步长 18，地点名表）。
4. **转换会不会改到全名表？** → 算指针表与全名表的地址区间 → **不重叠，差 500 字节**。

### 6.3 踩过的坑（留给下一个接手的人）

| 坑 | 现象 | 正确做法 |
|---|---|---|
| **Thumb `ldr [pc,#imm]` 的 imm 是已缩放的** | 第一次按 `imm*4` 又乘了一次，得到 `0x46491840` 之类的垃圾 | 目标地址 = `((insn_addr + 4) & ~3) + imm`（capstone 打印的 imm 已经乘过 4） |
| **capstone 的 `disasm` 遇到解不出的半字就停** | 长窗口只解出前几条指令，求值器拿不到链尾 | 开 `md.skipdata = True`（`tools/probe_speaker_id63.py::_md_skipdata`） |
| **`op_str.split(",")` 会被内存操作数里的逗号切坏** | `ldr r1, [pc, #0x50]` 被切成 3 段，解析器以为有 3 个寄存器 | 先把 `[` 之后的部分整体切出来（`_split_ops`） |
| **Thumb 的两操作数 `add rD, rS`** | `add r0, sl` 只有 2 个操作数，被当成「不认识」跳过 ⇒ 求值器算出步长 3 而不是 19 | 两操作数 `add/adds` 视作 `adds rD, rD, rS` |
| **符号求值器要在「加基址」那一刻取值** | 在整窗口跑完后才查寄存器 ⇒ 拿到的是被后续指令改过的值 | 在 `ldr_addr + 2` 那条 `adds` 处就地取值 |
| **符号求值器把 `ldr rX,[pc,#imm]` 当成了索引** | 步长算成 13 | pc 相对载入是**常量**（系数 0），其它载入才是索引变量 |
| **`lsrs` 是逻辑右移，系数要按 2 的幂精确除** | 用整数会丢精度 | 用 `fractions.Fraction` 精确保存有理系数，最后再取整 |

## 7. 局限与未查实的部分

1. **没有做真机验证**。本次是**纯静态**考证：没有跑 mGBA、没有改 ROM、没有对比画面。
   「转换后 id 63 仍然输出「没有」」是由「转换只改指针表 + 串池、保护区逐字节未动」
   （台账 F6，已验证）+「字符串内容相同」推出来的，不是实测。
2. **11 个非 VM 的简称读者，其 id 的取值上界没有逐个证明**。
   本次只证明了它们的 id 来源是「记录里的一个字节」（`[rX,#N]`），没有逐个枚举这些记录的取值域。
   但这对 U4 不构成影响：**即使某个界面真的请求了 id 63，转换前后拿到的字符串都是「没有」**。
3. **3 个全名读者各自是哪个 UI 界面，没有追**（只确认了它们画的是「全名」、id 来自角色记录）。
   U4 不需要这个信息，但下一轮做 U1/U5 时可能需要。
4. **地点名表（18 B）的完整语义没有追**（它是不是「地图 id → 地名」的有序表、55 条之外还有没有别的消费者），
   本次只做到「它不是全名表读者、转换碰不到它」。
5. **全 ROM 的 `ldr [pc,#imm]` 扫描只覆盖 Thumb-1 的 T1 编码**（`01001 Rt imm8`）。
   ARM 模式（`ldr rX,[pc,#imm]` 的 ARM 变体）没有单独扫；
   已知 `0x083FC9A6` 附近那段 ROM 尾部解不出合法指令（见前一份笔记），但**没有穷尽 ARM 代码**。
6. **没有检查内容包之外的数据文件**（例如 `.sav`、外部剧情脚本）会不会引用 id 63。
   本次只覆盖了 ROM 内嵌的 55 个场景 × 4 个根，以及内容包导出的 202 条剧本。
7. **保护区边界的依据需要更新**：现在知道了 `0x085A5F65` 起的地点名表，
   「保护区 = 全名表 64 条」这个说法要补一句「地点名表 id 0 与全名 id 63 同址」；
   地点名表 id 1..54（`0x085A5F77..0x085A6342`）在保护区之外，转换不写那里。
8. **假设台账 `notes/evidence/speaker-names-hypothesis-ledger.md` 本次没有改**
   （按分工，该文件不属于本次可动范围）。**U4 的状态应回填为「已证伪」**，
   并把本报告 §5 的六条理由与 N1/N2 两条新事实一并写进去。
