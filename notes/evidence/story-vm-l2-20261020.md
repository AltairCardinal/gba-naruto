# 剧情脚本根表：L2 原生定点证据（2026-10-20）

**等级**: L2（原生代码定点 —— 断点真实命中，命中上下文里记录了 PC / LR / 寄存器，
且运行时值与结构字段有唯一对应）
**结构**: 剧情脚本 VM 四根表 `0x060C74` / `0x060D54` / `0x060E34` / `0x060EF0`
**采集工具**: `tools/mgba_probe/runtime_probe.py`（宿主 `tools/mgba_probe/host_main.c`）
**关联**: `notes/story-vm-opcodes-20261020.md`（指令语义）、
`notes/story-script-vm.md`（VM 总览）、
`notes/mgba-probe-runtime-20261020.md`（探针能力与两个坑）、
`notes/runtime-verification-gates-20260710.md`（分级定义）

## 1. 复现命令

```powershell
$env:PYTHONIOENCODING='utf-8'
python tools/mgba_probe/runtime_probe.py rom/base.gba \
    --boot-frames 1500 --press START --press A --press A --press A --press A \
    --breakpoint 0x0808F5D0 --breakpoint 0x080977B8 --settle-frames 90 \
    --json notes/evidence/story-vm-l2-capture.json

# 命中剧情调度器入口（r0 = 场景号）
python tools/mgba_probe/runtime_probe.py rom/base.gba \
    --boot-frames 1500 --press START --press A --press A --press A --press A \
    --breakpoint 0x0808F544 --breakpoint 0x080977B8 --breakpoint 0x0806D4A0 \
    --settle-frames 90 --json build/runtime-trace.json
```

> **触发时机敏感**：两条命令的触发点都是**第 3 次 A**。
> 挂着的断点集合不同，游戏的帧时序就不同，同一串按键会落到不同代码路径。
> 复现时请用上面的完整命令，不要缩短。
> 原始采样已冻结在 `notes/evidence/story-vm-l2-capture.json`。

## 2. 命中的消费者

### 2.1 VM 解释器入口 `0x080977B8`（主证据）

| 项 | 值 |
|---|---|
| 断点地址 | `0x080977B8` |
| 命中时的 PC | **`0x080977BA`**（`push {r4,r5,r6,r7,lr}` 的下一条） |
| 命中时的 LR | `0x00000000` |
| 命中的按键序列 | `START` → `A` → `A` → **`A`**（第 3 次 A 触发） |
| 命中那一帧实际执行的帧数 | `1 / 8` |
| **r0** | **`0x08049E76`** = 场景 54 的剧情脚本指针 |
| r7 | `0x020311D4` = 剧情 flag 状态块基址 |

### 2.2 剧情调度器入口 `0x0808F544`（辅证）

| 项 | 值 |
|---|---|
| 断点地址 | `0x0808F544` |
| 命中时的 PC | **`0x0808F546`** |
| 命中时的 LR | `0x00000000`（从主循环直接调用，不是嵌套返回） |
| 命中的按键序列 | `START` → `A` → `A` → **`A`**（第 3 次 A 触发） |
| 命中那一帧实际执行的帧数 | `1 / 8`（断点在第一帧就命中） |

### 2.3 命中时的寄存器（剧情调度器）

| 寄存器 | 值 | 含义 |
|---|---|---|
| **r0** | **`0x00000036`（= 54）** | **场景号（函数的唯一入参）** |
| r1 | `0x00000030` | |
| r2 | `0x00001279` | |
| r3 | `0x00000170` | |
| **r4** | **`0x020311D4`** | 剧情 flag 状态块基址（与 `notes/story-vm-opcodes-20261020.md` 的指令 `0x37`/`0x38` 一致） |
| r5 | `0x00000100` | |
| r6 | `0x00000010` | |
| r7 | `0x00000000` | |

### 2.4 消费者代码（`0x0808F544`）

```
0808F544  push {r4, r5, r6, r7, lr}
0808F546  mov  r7, sb
0808F548  mov  r6, r8
0808F54A  push {r6, r7}
0808F54C  sub  sp, #0x18
0808F54E  lsls r0, r0, #0x10      ; 场景号只取低 8 位
0808F550  lsrs r4, r0, #0x10      ; r4 = 场景号
0808F552  ldr  r1, [pc, #0x5c]    ; 0x020311D4（flag 块）
0808F554  movs r2, #0xc2
0808F556  lsls r2, r2, #5
0808F558  adds r0, r2, #0
0808F55A  strh r0, [r1]
...
0808F594  ldr  r7, [pc, #0x1c]    ; 状态块
0808F598  ldr  r0, [pc, #0x1c]    ; 0x08060C74  <- before 根表
0808F59A  mov  sb, r0
0808F59C  ldr  r2, [pc, #0x1c]    ; 0x08060D54  <- after 根表
0808F59E  mov  r8, r2
0808F5A0  ldrb r1, [r6, #0x18]
0808F5A2  cmp  r1, #0
0808F5A4  beq  #0x808f5c0
0808F5A6  lsls r0, r4, #0x10
0808F5A8  asrs r0, r0, #0xe        ; r0 = 场景号 * 4
0808F5AA  add  r0, sb              ; + before 根表基址
0808F5AC  ldr  r0, [r0]            ; 取该场景的脚本指针
...
0808F5C0  lsls r0, r4, #0x10
0808F5C2  asrs r0, r0, #0xe
0808F5C4  add  r0, r8              ; + after 根表基址
0808F5C6  ldr  r0, [r0]
...
0808F5D0  bl   #0x80977b8          ; -> VM 解释器入口
```

→ **消费者地址 = `0x0808F544`**：它同时取 `before` 根表（`0x08060C74`）和
`after` 根表（`0x08060D54`），并用 `场景号 * 4` 索引。

## 3. 运行时值与结构字段的唯一对应

### 3.1 VM 入口采样（主证据）

命中的 `r0 = 0x08049E76` = 文件偏移 **`0x49E76`**。
用 `tools/decode_story_script.py` 的根表反查：

| 根表 | 文件偏移 | 场景 54 的条目 |
|---|---|---|
| `before` | `0x060C74` | **`0x49E76`** |
| `after` | `0x060D54` | `0x49E76` |
| `logic` | `0x060E34` | `0x4FACD` |
| `events` | `0x060EF0` | （空） |

`0x49E76` 处的字节 `15 00 0E 01 57 B9 04 08 ...` 是合法的 VM 指令流
（`0x15` 长度 8、`0x0E` 长度 3、其后是指针 `0x0804B957` 一类）。

→ **运行时读到的脚本指针与「场景 54 的 before 根表条目」逐位相等**，
  且该条目是四个根表里唯一指向这个脚本的项 —— 对应关系唯一。

### 3.2 调度器采样（辅证）

命中的 `r0 = 0x36 = 54` = 场景号；`0x0808F544` 内部就是用
`场景号 * 4` 去索引 `before` 根表（`0x08060C74`）和 `after` 根表
（`0x08060D54`）。两条采样首尾相接：
`r0 = 54` → 根表第 54 项 → 脚本指针 `0x08049E76` → 交给 VM 入口 `0x080977B8`。

> 顺带更正一条旧结论：先前笔记把 `0x0808F698` 的字节 `0x36` 当成
> 「起始场景数据字节」。实际那是 `movs r0, #0x36` 的**立即数操作数**
> （`0x0808F698` 在指令流里）。**场景号 54 确实正确**，但它来自
> **运行时入参 r0**，不是来自一张数据表。证据见
> `notes/mgba-probe-runtime-20261020.md` §4.2。

## 4. 判死检验

| 结论 | 能推翻它的检验 |
|---|---|
| `0x080977B8` 是剧情脚本的消费者 | 在该地址下断点，命中时若 `r0` 不落在任何一根根表的条目里（184 个指针之一），则「VM 入口」这个读法作废 |
| 运行时脚本指针 = 场景 54 的 `before` 条目 | 用 `tools/decode_story_script.py` 重算四张根表的第 54 项；若 `before[54] != 0x49E76`，本采样作废 |
| `0x0808F544` 是剧情根表的消费者 | 在该地址下断点，命中时若 `r0` 落在 1..55 之外，或四张根表的 `r0*4` 处不是合法脚本指针，则「场景号索引」这一读法作废 |
| `before[54] == after[54] == 0x49E76` | 用 `tools/decode_story_script.py` 重算；若两者不相等，则根表反查有误 |
| 断点机制本身有效 | `0x0806112E` 是本会话早先验证过的热地址断点，可作对照 |
