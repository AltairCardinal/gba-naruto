# 事实：战斗地图怎么画出来（2026-10-22）

> 这份笔记是「战斗地图可视化 + 就地布置编辑」的事实依据。
> 全部用仓库自己的工具实测（`tools/probe_battle_map.py` / `tools/probe_battle_map_tiles.py`），
> 渲染算法取自仓库里 vendored 的第三方编辑器 `third_party/konoha-workshop/editor/features.js`
> （与本仓库**同一份 ROM**，SHA-256 一致）。

## 1. 地图表布局（`0x53D910`，每条 32 字节）

| 偏移 | 内容 | 实测 |
|---|---|---|
| +0x00 | u16 原始宽 | 地图 0 = 92 |
| +0x02 | u16 原始高 | 地图 0 = 64 |
| +0x04 | ptr 图块图形（LZ77） | 解压 = 672 个 4bpp 8×8 图块（21,504 字节，32 字节/块）|
| +0x08 | ptr 调色板（LZ77） | 解压 = 384 字节 = **192 个 BGR555 色值**（12 组 × 16 色）|
| +0x0C | ptr 图层 0（LZ77 tilemap） | 解压 = 1,472 个 u16 |
| +0x10 | ptr 图层 1（LZ77 tilemap） | 同上（可为 0）|
| +0x14 | ptr 组合图块表（LZ77） | 解压 = 6,160 字节 = **770 项，每项 8 字节** |
| +0x18 | ptr 通行值表（LZ77） | 解压 = 1,472 字节 = **每格 1 个 u16** |
| +0x1C | u8 剧情底图 id | 指向底图表 `0x59903C` |

## 2. 尺寸与坐标单位

- **一「格」= 原始宽 ÷ 4 × 原始高 ÷ 2**（地图 0 = 23×32 格，地图 1 = 15×15，地图 2 = 9×18 …）
- **通行值表每格 1 个 u16** ⇒ 长度 = 格宽 × 格高 × 2 ✔（47 张地图全部吻合）
- **tilemap 每格 2 个 u16** ⇒ 长度 = 格宽 × 格高 × 4 ✔
- **坐标单位是「格」**：角色出生点 x ∈ 0..13、y ∈ 0..26；战场物件 x ∈ 0..14、y ∈ 0..28
  （地图 0 是 23×32 格 ⇒ 同量级，**不是像素**）

## 3. 渲染算法（照抄第三方 `features.js::renderMap`，可逐行对照）

```
图宽 = 格宽 × 32 像素      图高 = 格高 × 16 像素
每像素 (x, y)：
  tx = x >> 3            ty = y >> 3              // 8 像素的图块坐标
  meta = u16(layer, ((ty>>1) × 格宽×2 + (tx>>1))  // 图层条目 = 组合图块号
  entry = u16(metatiles, meta×8 + ((ty&1)×2 + (tx&1))×2)  // 组合图块里的 4 个图块号
  index = tilePixel(gfx, entry, x&7, y&7)
  取**最后一个 index 非 0 的图层**（图层 1 覆盖图层 0）
```

`tilePixel(gfx, entry, x, y)`：

```
if (entry & 1024) x = 7 - x          // bit10 = 水平翻转
if (entry & 2048) y = 7 - y          // bit11 = 纵向翻转
p = (entry & 1023) × 32 + y × 4 + (x >> 1)      // 4bpp：每字节两个像素
c = (gfx[p] >> ((x & 1) × 4)) & 15
return c ? c + (entry >>> 12) × 16 : 0           // bits15-12 = 调色板组
```

`rgbaColor(pal, index)`：`v = u16(pal, index×2)`，
`R = (v & 31) × 255/31`，`G = (v>>>5 & 31) × 255/31`，`B = (v>>>10 & 31) × 255/31`（BGR555）。

**组合图块 = 2×2 个 8×8 图块**（8 字节 = 4 个 u16 图块号）⇒ 一格 = 32×16 像素。

## 4. 由此得出的三条结论

1. **地图可以画成真实像素**（不需要逐字节一致的压缩器 —— 我们只**读**载荷，不改它）。
2. **能就地改的是「布置」**：`battle_map_objects` 与 `battle_actors` 的 x/y/type/target
   都是定长字节，改它们是原地写。
3. **地形与图层不能就地改**：terrain / layer 是 LZ77 压缩块，改了要重新压缩
   （仓库只有 `tools/lib/lz77.py::compress_literal` 的字面量编码器，体积会变大），
   必须「搬到 ROM 尾部 + 改指针」—— 那是第三方编辑器的「重新生成整个 ROM」模型，
   与本仓库的「就地改 + 补丁」模型不同，**本轮不做**。

## 5. 复现

```
python tools/probe_battle_map.py        # 尺寸、terrain/tilemap 字节数、坐标范围
python tools/probe_battle_map_tiles.py  # tilemap 指的是组合图块、gfx 是 4bpp、调色板 192 色
```
