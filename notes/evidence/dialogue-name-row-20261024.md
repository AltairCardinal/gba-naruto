# `0x20` 是消息框的**名字行**：一条消息 = 名字行 + 正文（2026-10-24）

> 用户反馈：**「这两句在游戏中是组合在一起，在这显示为了第一句只有头像、第二句只有文字」**
> （附截图：对白查看器里场景 54 的第 1、2 行 —— 第 1 行只有「漩涡鸣人」，
> 第 2 行只有「“呜哇！果然还是一乐的拉面最好吃呀！！”」）。

**结论**：**一条消息 = 一个对白框 = 名字行 + 正文**。
名字行有两个来源，**画在同一处、用同一套颜色**：

| 来源 | 指令 | 内容 |
|---|---|---|
| 说话人名表 | `0x08` | 名字表 `0x085A57C4` 里的名字（12 字节内联字形码） |
| **内联文本** | **`0x20`** | **这条指令自带的一段文本**（正文从 +2 起） |

`0x20` 后面那条 `0x01` 是**同一条消息的正文** —— 编辑器原来把它们拆成两行，
所以第一行「只有名字」、第二行「只有正文」。

---

## 1. 证据

### 1.1 全 ROM 扫描：`0x20` 的下一条文本指令**全部**是 `0x01`

`tools/probe_dialogue_name_row.mjs`：

```
0x20 共 190 处；下一条文本指令：
  op=0x01  190 处
中间夹的指令：
  op=0x11  104 处        ← 只夹「清立绘」，与消息框无关
```

⇒ **190/190**：`0x20` 与其后那条 `0x01` 属于**同一条消息**；
中间只可能夹 `0x11`（清立绘），不影响消息框。
（`0x13` 双段文本、`0x05` 菜单**从不**跟在 `0x20` 后面。）

### 1.2 真机画面：名字行 + 正文行在**同一个框**里

抓帧命令（**正常按键**，没有改任何内存）：

```powershell
python tools\mgba_probe\render_screen.py build\scene54-a1.png --live --rom rom\base.gba `
    --press START --press A
```

⇒ 画面：**紫色名牌「漩涡鸣人」**（名字行）+ **“呜哇！果然还是一斯的拉面最好吃呀！！”**（正文行），
**一个消息框**。画面存进仓库：`notes/evidence/scene54-first-message-20261024.png`。

逐行量墨迹（`tools/probe_dialogue_name_row.mjs --shot …`）：

```
名字行: x=24..55  y=105..119   #7321ff(185) #bdadde(155)
正文行: x=27..179 y=120..135   #394239(674) #adb59c(654)
```

⇒ 名字行在 **x=24、y=104** 起（= 编辑器的 `NAME_X0/NAME_Y0`），
颜色 **#7321ff / #bdadde** —— 与 `0x08`（名字表）来源的名牌**完全同色**
（对比 `notes/evidence/story-scene-l3.png`：名字行 `x=24..47`，同样 `#7321ff/#bdadde`）。

### 1.3 脚本字节（场景 54 的第 1 条消息）

```
0x8049EAB  op=0x20 len=17
  20 01 99 68 97 cd 92 98 94 c8 81 40 81 40 81 40 00
  → 漩涡鸣人 + 3 个全角空格（+1 那个字节 handler 并不读）

0x8049EBC  op=0x11 len=2      ← 清立绘（不影响消息框）

0x8049EBE  op=0x01 len=81
  01 81 67 … 81 40 0a 81 40 … 00
  → “呜哇！果然还是一乐的拉面最好吃呀！！” + 换行 + 18 个全角空格（把框填满）
```

⇒ `0x20` 的正文与 `0x01` 的正文**都带填充空格** —— 它们是同一个框里的两行，
只是**名字行那行短、正文那行长**。

### 1.4 逐像素复核（门禁）

`rom-editor/tools/verify_dialogue_view.mjs` 第 7 组（2026-10-24 新增）：

```
[PASS] 名字行（0x20 的内联名字，x=24 起、名牌色）：与真机画面逐像素相同 — 相同 680 / 不同 0
[PASS] 正文行（第 1 条消息的 0x01 正文）：与真机画面逐像素相同 — 相同 2624 / 不同 0
```

## 2. 改了什么

| 文件 | 改动 |
|---|---|
| `rom-editor/js/dialogue.js` | 名字行变成**粘性状态**（`NAME_ROW_TABLE` / `NAME_ROW_TEXT`）；`0x20` **不再单独成行**，它只是把名字行填上；行对象新增 `nameKind/nameText/nameCodes/nameSegments` |
| `rom-editor/js/stage.js` | 名牌绘制改用 `line.nameCodes`（名字表与内联文本统一），位置/颜色不变 |
| `rom-editor/js/modules/dialogueview.js` | 列表**一行 = 一条消息**：名字行（内联时）有独立的输入框 + 「名字行」标签；行头显示名字行文字；界面口径从「句」改成「消息」 |
| `rom-editor/js/modules/scriptview.js` | `0x20` 那段的标注从「说话人 #N」改成「名字行（0x20 内联文本）」并说明依据 |
| `rom-editor/css/dialogue.css` | `.dlg-row-name` / `.dlg-row-name-tag` 样式 |

**界面口径的连带变化**（都是「一条消息 = 一个对白框」的直接结果）：

| 原来 | 现在 |
|---|---|
| 场景 54 有 **135 句** | **134 条消息**（`0x20` 不再单独占一行） |
| 真机那句是**第 5 句** | **第 4 条消息** |
| 「这一场 N 句」/「上一句 / 下一句」 | 「这一场 N 条消息」/「上一条 / 下一条」 |

## 4. 连带更正：L3 笔记的句子编号

`notes/evidence/story-scene-l3-20261020.md` §3 的表格**漏了 `0x20` 那一行**
（它把 `op=0x02 portrait` 记成第 1 句），所以那句「按 A 推进到第 5 句」是按
「文本指令条数」数的。**按消息框数是第 4 条**（名字行与正文同属一条）。
那条笔记的结论本身（屏幕文字 = 场景 54 的「是啊，是我这个班主任所承认的嘛！」）
**不变** —— 它本来就是对的，只是编号口径要改。

## 5. 还没做的

- **消息框的其它状态**（`0x03` 关框 / `0x21` 放置消息框与行格 / 双框模式）
  在编辑器里仍然没有建模 —— 现在按「一条 `0x01` = 一条消息」处理，
  这对**单框剧情**是对的；带 `0x21` 的双框/分行场景还需要单独取证。
- 名字行的**行/格位置**（`0x21` 写的 obj+0x02/0x03）在编辑器里也还没画。
- `0x20` 的 +1 字节（恒为 1）仍**未被原生代码读取** —— 本轮没有推翻这一条，
  只是确认它**不是**名字的来源（名字是那段内联文本）。
- **真浏览器里的视觉复核没做完**：这一轮后半段，桌面内置浏览器的下载开始卡住
  （330 KB 的内容包能下，393 KB 就下不完；编辑器自带的 6 MB ROM 完全下不动），
  页面停在「正在取内容包…」。**功能正确性不受影响** —— 门禁在 Node 里跑，
  逐像素比较的是**同一套渲染代码**（`js/stage.js`）的输出，
  两条新断言 680/680、2624/2624 全等。欠的是**肉眼看一下新加的「名字行」那行排版**。
  复现方式（换个浏览器/新开会话即可）：
  `node rom-editor\tools\serve.mjs 8000` → 打开
  `http://localhost:8000/rom-editor/#story/dialogue/before/54` → 载入内置 ROM →
  看第 1 行是不是「名字行 + 正文」两个输入框。
  （`rom-editor/tools/qa-scene-select.html` 的 `?rom=<路径>` 参数可以指定别的 ROM，
  例如一份只含脚本段的截断副本 —— 列表够用，字库就够不着了。）
