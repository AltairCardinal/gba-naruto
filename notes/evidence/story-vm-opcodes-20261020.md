| 项 | 结果 |

## 1. 方法

1. **找 handler → helper 的调用点**：`python tools/story_vm_ops.py rom/base.gba --disasm 0x08097930 --count 40`
   得到六个 handler 全部在 `0x08097930`–`0x08097990` 这一段。
2. **逐条反汇编 helper**：本轮自写了一个带**字面量池解析**与**递归下降**的 Thumb 反汇编器
   （临时脚本 `build/_vm_helper_disasm.py`，用 `tools/story_vm_ops.py` 的 capstone 装载逻辑），
   避免把数据当成指令。等价的核对方式（用仓库自带工具，无需额外脚本）：
   `python tools/story_vm_ops.py rom/base.gba --disasm 0x080967E8 --count 40`。
3. **追到共享子程序**：`0x8096138`（台词表下标）、`0x8096168` / `0x8096238`（画台词与边框）、
   `0x80965F0`（建消息框）、`0x8096DD4` / `0x8096D8C`（画/清头像）、
   `0x8096B74`（0x17 的 9 项分发表，交叉验证消息框字段用途）。
4. **判定 `0x809C14C` 到底是什么**：它是「表查找」还是「除法」直接决定 0x18 的第三个操作数含义。
   把 `0x0809C14C` 的整段 Thumb 指令**逐条翻译成 Python 精确模拟**（模拟器源码见 §4.7，**自包含**），
   用 15 组输入与 `a//b`、`gcd` 对照，结果与**有符号整除（向零截断）**完全一致、与 gcd 不一致。
5. **运行时取证**：用无头 mGBA 探针在 helper 入口下断点，命中瞬间读寄存器与脚本字节
   （新工具 `tools/mgba_probe/story_vm_capture.py`）。

## 2. 关键结构（三张表 + 一个对象）

### 2.1 消息框指针表 `0x03005E50`

六个 helper 全部通过 `0x03005E50 + 槽号*4` 取消息框对象指针。槽号只有 **0 和 1** 两个：

- `0x8096668`（0x03）显式访问 `[0x03005E50]` 与 `[0x03005E50+4]`；
- `0x80968EC`（0x12）显式循环 `槽 = 0..1`；
- `0x8096D8C`（清头像）显式循环 `槽 = 0..1`。

运行时实测（`build/story-vm-capture-003.json`）：`0x03005E50` = `7C 59 00 03 | 04 59 00 03`
→ 0 号框对象在 `0x0300597C`，1 号框对象在 `0x03005904`。

### 2.2 台词/头像表 `0x085A4DEC`

`0x8096138(行, 格)` 是唯一的下标入口：

```
0x08096138: push {lr}
0x0809613A: lsls  r0, r0, #0x18
0x0809613C: lsrs  r2, r0, #0x18      ; r2 = 行 (u8)
0x0809613E: lsls  r1, r1, #0x18
0x08096140: lsrs  r1, r1, #0x18      ; r1 = 格 (u8)
0x08096142: cmp   r1, #5
0x08096144: bne   #0x8096150
0x08096146: ldr   r0, [pc, #4]       ; = 0x085A4DE4   (格==5 的特例)
0x08096148: b     #0x809615E
0x08096150: lsls  r0, r2, #2         ; 行*4
0x08096152: adds  r0, r0, r2         ; 行*5
0x08096154: lsls  r0, r0, #3         ; 行*40
0x08096156: lsls  r1, r1, #3         ; 格*8
0x08096158: ldr   r2, [pc, #8]       ; = 0x085A4DEC
0x0809615A: adds  r1, r1, r2
0x0809615C: adds  r0, r0, r1         ; 入口 = 0x085A4DEC + 行*40 + 格*8
```

所以表结构是 **行距 40 字节、格距 8 字节**；每个 8 字节单元是 `{台词指针, 头像图指针}`：

| 单元内偏移 | 用途 | 证据 |
|---|---|---|
| +0 | 台词指针 | `0x080961CC: ldr r0, [r1]` 后 `bl 0x809C0EC` 拷进 `0x02002880` 缓冲 |
| +4 | 头像图指针 | `0x08096DFA: ldr r0, [r0, #4]` 后 `bl 0x80635B8(..., 0x80)` 搬 0x80 字节到 `0x05000200+obj[0x33]*32` |

实测该表有 61 行（行号 1..0x3D），行 0 全 0；第 4/5/6/9..19/22..35 行整行 5 格相同（同一套台词+头像复用于 5 格）。
**行号 = 「台词组」，格号 = 「组内第几格」**（0..4，格 5 走特例指针 `0x085A4DE4`）。

### 2.3 消息框对象字段

对象本体由 `0x80965F0` → `0x80626B4` 建立，`0x80626B4` 写的通用 UI 头占用 `+0x00..+0x28`
（`+0x28` 是回调指针 `0x08096325`），**剧情脚本自己用的字段从 `+0x2C` 开始**：

| 偏移 | 宽度 | 含义 | 证据 |
|---|---|---|---|
| +0x2C | byte | 消息框状态：`0x00` 空闲 / `0x02` 淡入 / `0x10` 已收起 / `0x20` 已关闭 / `0x30` 忙 / `0x40` 复位 / `0x50` 已摆位 | `0x0809663A: strb r1,[r0]`(建框清 0)、`0x08096B68: strb r0,[r4]`(=0x50) |
| +0x2D | byte | 本框的槽号 | `0x0809663E: strb r1,[r0,#1]` |
| +0x2E | byte | **台词行号** | `0x080962BA`/`0x080968A8`/`0x08096790` |
| +0x2F | byte | **台词格号** | `0x080962C2`/`0x080968AC`/`0x08096794` |
| +0x30 | byte / u16 | 暂存的行号；被 0x21 覆盖成 u16「样式码」 | `0x0809685E`、`0x080967C2: strh r2,[r4,#4]` |
| +0x31 | byte | 暂存的格号（处理完置 0xFF） | `0x08096860`、`0x080968B4: orrs r0,r2` |
| +0x32 | byte | 头像待重画标志 | `0x08096E06: strb r0,[r5,#6]` |
| +0x33 | byte | 头像的 OAM/图块基址 | `0x08096DEA: ldrb r0,[r5,#7]` → `0x05000200 + obj[0x33]*32` |
| +0x34 | u16 | 文本区左/上标（0x17 的 9 项分发表与 0x18 都写 0） | `0x08096B58: strh r1,[r4,#8]` |
| +0x36 | u16 | **缩放系数** = `0x1000 / 除数` | `0x08096B60: bl 0x809C14C` → `0x08096B64: strh r0,[r4,#0xa]` |
| +0x38 | u16 | 文本区尺寸之一（= 对象自身的 u16 `+4`） | `0x08096B54: strh r0,[r4,#0xc]` |
| +0x3A | u16 | 文本区尺寸之二（0x18 的第 2 操作数；0x17 分发表写 0x50/0x40/0x60/0x90/0x10） | `0x08096B56: strh r3,[r4,#0xe]` |

> `+0x38 / +0x3A` 的 UI 语义（宽/高）**没有**在 ROM 里找到自解释字段，本文件只按「尺寸/缩放」记录，
> 不在工具的 label 里断言是宽还是高。

## 3. 操作数 → 字段映射表（六条）

下表中「实参」列是 handler 传给 helper 的寄存器；「落点」列是该实参最终写进消息框对象的字段。

### 0x02 —— 选择消息框台词行/格（槽@+1, 行@+2, 格@+3）

| 操作数 | 值域 | → 实参 | → 落点 | 作用 |
|---|---|---|---|---|
| +1 | 0 / 1 | r0 | `0x03005E50[槽]` | 选 0 号或 1 号消息框 |
| +2 | 1..0x3D | r1 → `sb`/`r6` | obj+0x30（暂存）→ **obj+0x2E** | 台词**行号**（表 `0x085A4DEC` 的行） |
| +3 | 0..4 | r2 → `r7` | obj+0x31（暂存）→ **obj+0x2F** | 台词**格号**（组内第几格） |

handler：`0x08097930: ldrb r0,[r7,#1]` / `0x08097932: ldrb r1,[r7,#2]` / `0x08097934: ldrb r2,[r7,#3]` / `0x08097936: bl #0x80967e8`

### 0x03 —— 关闭消息框（槽@+1；0xFF = 两个都关）

| 操作数 | 值域 | → 实参 | → 落点 | 作用 |
|---|---|---|---|---|
| +1 | 0 / 1 / 0xFF | r0 → `r1` | `0x03005E50[槽]` | 0/1 = 关一个框；0xFF = 两个框一起处理（`r6` 先取 `0xFFFF` 作哨兵，再依次落到 0 / 1） |

关框动作 = 消息框 `+0x2C` 状态置 `0x20`（普通模式）或 `0x30` 并置 `obj[0]|=0x20000`（按模式）。

### 0x04 —— 切换消息框台词行/格并立即重画（槽@+1, 行@+2, 格@+3）

| 操作数 | 值域 | → 实参 | → 落点 | 作用 |
|---|---|---|---|---|
| +1 | 0 / 1 | r0 → `r4` | `0x03005E50[槽]` | 选框 |
| +2 | 1..0x20 | r1 → `r8` | **obj+0x2E** | 台词行号 |
| +3 | 0..4 | r2 → `r7` | **obj+0x2F** | 台词格号 |

与 0x02 同义，但走 `0x8096238`（多一个 `0x02002880` 边框缓冲参数），随后 `0x8096DD4` 重画头像。

### 0x12 —— 同时设置两个消息框的台词行/格（框0 行@+1 格@+2, 框1 行@+3 格@+4）

| 操作数 | 值域 | → 局部暂存 | → 实参 | → 落点 |
|---|---|---|---|---|
| +1 | 1..0x2C | sp+4 | r1（0 号框的行） | 0 号框 obj+0x2E |
| +2 | 0..4 | sp+8 | r2（0 号框的格） | 0 号框 obj+0x2F |
| +3 | 1..0x2C | sp+5 | r1（1 号框的行） | 1 号框 obj+0x2E |
| +4 | 0..4 | sp+9 | r2（1 号框的格） | 1 号框 obj+0x2F |

`0x80968EC` 把 4 个操作数摊成两组 `(行,格)`：框 0 用 sp+4/sp+8，框 1 用 sp+5/sp+9；
随后对每个槽调 `0x8096168(槽, 行, 格, 0, 0)`。

### 0x18 —— 设置消息框文本区尺寸与缩放（槽@+1, 尺寸@+2, 缩放除数@+3）

| 操作数 | 值域 | → 实参 | → 落点 | 作用 |
|---|---|---|---|---|
| +1 | 0 / 1 | r0 → `×4` | `0x03005E50[槽]` | 选框（`0x08096B42: lsrs r0,r0,#0x16` = 操作数×4） |
| +2 | u16（12..230） | r1 → `r3` | **obj+0x3A** | 文本区第二尺寸（u16，原样写入） |
| +3 | 10 / 15 | r2 → `r1` | **obj+0x36** = `0x1000 / 除数` | 缩放系数；除数经 `0x809C14C` **有符号整除** |

同时：`obj+0x38 = obj+4`（对象自身的 u16）、`obj+0x34 = 0`、`obj+0x2C = 0x50`。

### 0x21 —— 放置消息框并选中台词行/格（槽@+1, 行@+2, 格@+3, 样式@+4）

| 操作数 | 值域 | → 实参 | → 落点 | 作用 |
|---|---|---|---|---|
| +1 | 0 / 1 | r0 → `r8` | `0x03005E50[槽]`（不存在则 `0x80965F0` 新建） | 选/建框 |
| +2 | 1..0x33 | r1 → `r5` | **obj+0x2E**（另暂存到 obj+0x30 低字节） | 台词行号 |
| +3 | 0..3 | r2 → `r6` | **obj+0x2F**（另暂存到 obj+0x31 低字节） | 台词格号 |
| +4 | 0x50 / 0xFF | r3 → `sl` | **obj+0x30（u16）** | 样式码；取 0xFF 时按槽给默认值：0 号框 `0x10`、1 号框 `0x90` |

## 4. 六个 helper 的反汇编（关键片段）

### 4.1 `0x80967E8`（0x02）

```
0x080967E8: push {r4, r5, r6, r7, lr}
0x080967F2: lsls r0, r0, #0x18 ; lsrs r0, r0, #0x18   ; 槽
0x080967F8: lsls r1, r1, #0x18 ; lsrs r6, r1, #0x18   ; 行 -> r6
0x080967FC: lsls r2, r2, #0x18 ; lsrs r7, r2, #0x18   ; 格 -> r7
0x08096800: ldr  r0, [pc, #0x2c]                     ; = 0x0300000E (按键状态)
0x08096808: movs r0, #1 ; mov r1, r8 ; ands r1, r0   ; r8 = (u16@0x0300000E >> 1) & 1
0x08096810: ldr  r1, [pc, #0x20]                     ; = 0x03005E50
0x08096816: adds r5, r0, r1                          ; r5 = 0x03005E50 + 槽*4
0x08096818: ldr  r0, [r5]                            ; 已有框?
0x0809681C: bne  #0x8096838
0x0809681E: mov  r0, sb ; adds r1, r6, #0 ; adds r2, r7, #0
0x08096824: bl   #0x80965f0                          ; 没有就建
...
0x0809685E: strb r6, [r4, #4]                        ; obj+0x30 = 行
0x08096860: strb r7, [r4, #5]                        ; obj+0x31 = 格
0x0809688A: bl   #0x8096238                          ; 带边框的画法
0x080968A0: bl   #0x8096168                          ; 普通画法
0x080968A8: strb r1, [r4, #2]                        ; obj+0x2E = 行
0x080968AC: strb r0, [r4, #3]                        ; obj+0x2F = 格
0x080968B0: orrs r1, r2 ; strb r1, [r4, #4]          ; obj+0x30 |= 0xFF
0x080968B4: orrs r0, r2 ; strb r0, [r4, #5]          ; obj+0x31 |= 0xFF
0x080968B8: strb r3, [r4]                            ; obj+0x2C = 0
0x080968BC: bl   #0x8096dd4                          ; 重画头像
```

### 4.2 `0x8096668`（0x03）

```
0x08096668: push {r4, r5, r6, lr}
0x0809666A: lsls r0, r0, #0x18 ; lsrs r1, r0, #0x18   ; 槽
0x0809666E: ldr  r0, [pc, #0x3c]                     ; = 0x0300000E
0x08096672: lsrs r3, r0, #1 ; movs r0, #1 ; ands r3, r0 ; 模式位
0x08096678: cmp  r1, #0xff                           ; 0xFF = 两个都关
0x0809667C: ldr  r6, [pc, #0x30]                     ; = 0x0000FFFF (哨兵)
0x0809667E: ldr  r0, [pc, #0x34]                     ; = 0x03005E50
0x08096692: movs r6, #0                              ; 关 0 号框
0x08096698: movs r0, #0x30 ; strb r0, [r4]           ; 模式: 状态=0x30
0x080966B8: movs r0, #0x20 ; strb r0, [r4]           ; 普通: 状态=0x20
0x080966CC: movs r6, #1                              ; 关 1 号框
0x080966E8: lsls r0, r6, #0x10 ; asrs r1, r0, #0x10  ; r1 = (int16)r6
0x080966F0: cmp  r1, r0                              ; r6==-1 -> 没有要关的框
0x080966F8: ldr  r0, [r0] ; adds r4, r0, #0 ; adds r4, #0x2c
0x08096734: ldrb r0, [r4] ; cmp r0, #0x30 ; bne #0x809672e  ; 等框空闲
```

### 4.3 `0x8096A04`（0x04）

```
0x08096A04: push {r4, lr}
0x08096A08: adds r4, r0, #0 ; lsls r4,r4,#0x18 ; lsrs r4,r4,#0x18   ; 槽
0x08096A0E: lsls r1,r1,#0x18 ; lsrs r1,r1,#0x18    ; 行

0x08096A1E: adds r0, r4, #0 ; movs r3, #0

### 4.4 `0x80968EC`（0x12）

```
0x080968EC: push {r4, r5, r6, r7, lr}
0x08096900: add  r4, sp, #4
0x08096902: strb r0, [r4]                          ; sp+4 = 操作数+1 (0 号框的行)
0x08096906: strb r2, [r0, #1]                      ; sp+5 = 操作数+3 (1 号框的行)
0x0809690A: strb r1, [r2]                          ; sp+8 = 操作数+2 (0 号框的格)
0x0809690C: strb r3, [r2, #1]                      ; sp+9 = 操作数+4 (1 号框的格)
0x0809690E: ldr  r0, [pc, #0x50]                   ; = 0x0300000E
0x08096926: movs r7, #0                            ; 槽循环 0..1
0x0809692C: ldr  r1, [pc, #0x34]                   ; = 0x03005E50
0x08096980: ldrb r1, [r5]                          ; r5 = &sp[4+槽] -> 行
0x08096988: ldrb r2, [r6]                          ; r6 = &sp[8+槽] -> 格
0x0809698E: bl   #0x8096168                        ; 0x8096168(槽, 行, 格, 0, 0)
0x0809699A: strb r0, [r1, #2]                      ; obj+0x2E = 行
0x080969A0: strb r0, [r1, #3]                      ; obj+0x2F = 格
0x080969A6: strb r0, [r1, #4]                      ; obj+0x30 = 0xFF
0x080969AE: strb r0, [r1, #5]                      ; obj+0x31 = 0xFF
0x080969BE: cmp  r4, #1 ; ble #0x809692c            ; 槽循环到 1 结束
```

### 4.5 `0x8096B34`（0x18）

```
0x08096B34: push {r4, lr}
0x08096B36: lsls r0, r0, #0x18
0x08096B38: lsls r1, r1, #0x10 ; lsrs r3, r1, #0x10 ; r3 = 操作数+2 (u16)
0x08096B3C: lsls r2, r2, #0x18 ; lsrs r2, r2, #0x18 ; r2 = 操作数+3
0x08096B40: ldr  r1, [pc, #0x2c]                   ; = 0x03005E50
0x08096B42: lsrs r0, r0, #0x16                     ; 操作数+1 * 4
0x08096B44: adds r0, r0, r1
0x08096B46: ldr  r0, [r0]                          ; 框对象

### 4.7 `0x809C14C` —— 有符号整除（决定 0x18 第 3 操作数的含义）

整段 Thumb（`0x0809C14C`–`0x0809C1D2`）翻译成 Python 精确模拟后，
结果与 `int(a/b)`（向零截断）**完全一致**，与 `gcd` 不一致：

| a | b | 本函数 | `int(a/b)` | `gcd(a,b)` |
|---|---|---|---|---|
| 6 | 3 | 2 | 2 | 3 |
| 100 | 7 | 14 | 14 | 1 |
| 1000 | 60 | 16 | 16 | 20 |
| 4096 | 3 | 1365 | 1365 | 1 |
| 4096 | 16 | 256 | 256 | 16 |

所以 0x18 的第 3 操作数是**除数**，obj+0x36 = `0x1000 / 除数` 是**缩放系数**（不是查表，也不是 gcd）。

判定用的模拟器是**自包含**的（不依赖任何额外脚本），把下面这段存成 `emu.py` 即可复现：

```python
M = 0xFFFFFFFF
def s32(v):
    v &= M
    return v - 0x100000000 if v & 0x80000000 else v

def func(a, b):                      # 0x0809C14C 的精确翻译
    r0, r1 = a & M, b & M
    if r1 == 0:
        return None
    ip = (r0 ^ r1) & M
    r3, r2 = 1, 0
    if r1 & 0x80000000: r1 = (-r1) & M
    if r0 & 0x80000000: r0 = (-r0) & M
    if r0 < r1:
        return 0
    r4 = 1 << 28
    while True:
        if not (r1 >= r4) and not (r1 >= r0):      # 0x809c170
            r1 = (r1 << 4) & M; r3 = (r3 << 4) & M; continue
        r4 = (r4 << 3) & M                        # 0x809c17e
        if not (r1 >= r4) and not (r1 >= r0):
            r1 = (r1 << 1) & M; r3 = (r3 << 1) & M; continue
        if r0 >= r1:                              # 0x809c18e
            r0 -= r1; r2 |= r3
        for k in (1, 2, 3):                       # 0x809c196 / 0x809c1a2 / 0x809c1ae
            r4 = r1 >> k
            if r0 >= r4:
                r0 -= r4; r2 |= (r3 >> k)
        if r0 == 0:                              # 0x809c1ba
            break
        r3 = r3 >> 4
        if r3 == 0:
            break
        r1 = r1 >> 4
    return s32(-r2 if ip & 0x80000000 else r2)

import math
for a, b in [(6, 3), (100, 7), (1000, 60), (4096, 3), (4096, 16)]:
    got, trunc, g = func(a, b), int(a / b), math.gcd(a, b)
    print(a, b, got, trunc, g, "DIV" if got == trunc else "NOT-DIV",
          "GCD" if got == g else "")
```

（`0x0809C14C` 的原指令也可以直接用仓库自带的工具反汇编核对：
`python tools/story_vm_ops.py rom/base.gba --disasm 0x0809C14C --count 40`。）

## 6. 运行时捕获

### 6.1 抓取原理

新工具 `tools/mgba_probe/story_vm_capture.py` 在 **helper 入口的第一条指令**下断点。
mGBA 的断点判定是 `PC - 指令长度 == 断点地址`（`mgba/src/arm/debugger/debugger.c:202`
`ARMDebuggerCheckBreakpoints`），命中时 CPU 停在**该指令之后**。
六个 helper 的第 1 条指令都是 `push {...}`，不动 r0..r3，也不动 r7，
所以命中瞬间读到的寄存器**就是 handler 传进去的实参**；
而 handler 是用 `ldrb rX, [r7, #k]` 取操作数的、调用前从不改 r7，
所以同一时刻读到的 **r7 就是当前脚本指令的地址** —— 于是
「脚本字节 ↔ 寄存器实参」可以逐字节对表。

### 6.3 抓取时踩到的三个坑（方法记录）

1. **按 A 不推进剧情，按 B 推进**。开场后连按 A 只会被标题/教学界面吃掉；
   实测 `B` 才能让对话前进（`build/vm-adv-*.png` 记录了 1/4/10/20 次 B 的画面）。
2. **宿主 `frames` 命令在窗口结束才松键**，下一个窗口立刻又按下，
   中间**没有一帧是松键状态**，所以游戏只认到**第一次**按键沿；
   必须每次按键之间插 `frames N 0x000`（工具的 `--press-gap`，默认 2 帧）。
   少了这一步，无论按多少次 B，剧情都停在第一句。
3. **断点命中会吃掉那一次按键沿**：命中那一帧游戏已经看到键是「按下」，
   下一帧再按同一个键就被判成「没松开」而不再触发。
   解决：命中后先 `frames 6 0x000`（工具的 `--gap-frames`）再 `delete` + 重新 `b`，
   并用 mGBA 的 `frame` 命令把被打断的那一帧跑完（`--frame-recover`，默认开）。

## 7. 没有闭合的部分（明确边界）

### 7.1 `0x12` / `0x18` / `0x21` 本轮**没有**运行时捕获

- 无头探针能到达的场景是**第 54 号场景的片头**（`0x08049E76` 起的脚本）。
- 该脚本在**可导航窗口内**能执行到的 opcode 只到 `0x04`（最后一次命中在 `0x0804A92B`）。
  `0x12`（该场景在 `0x0804AFAA`）、`0x18`、`0x21` 在这条路径上没被执行到；
  按 B 4000 次也没有推进到（见 `build/story-vm-capture-012.json` 等的 `hits: []`）。
- 全 ROM 里 `0x18` 只有 6 处、`0x21` 只有 16 处，分别落在场景 7/17/28/44 与
  3/7/8/9/27/28/31/52/53（用 `tools/story_vm_ops.py` 的根表走查统计），
  要触达必须先打通前面的剧情 —— 本轮没有做到。
- **因此这三条的 `proved` 依据只有静态代码级证据**（§3 的字段表 + §5 的可证伪指令）。
  静态证据本身是完整的：handler 传参、helper 落点、下标算术三条链都能逐条对到 ROM 的指令上，
  且工具每轮自动复核。

### 7.2 `obj+0x38 / obj+0x3A` 的 UI 含义仍未命名

`0x08096B54` 把对象自身的 u16（`+4`）写进 `+0x38`，`0x08096B56` 把操作数 +2 写进 `+0x3A`，
`0x8096B74` 的 9 项分发表往 `+0x3A` 写 `0x50 / 0x40 / 0x60 / 0x90 / 0x10`。
这些常数像「文本区高度」，但 ROM 里没有能自证「宽/高/坐标」的字段，
因此工具 label 只写「文本区尺寸与缩放」，**不断言是宽还是高**。

### 7.3 `obj+0x30`（u16）的取值语义

0x21 的第 4 操作数在脚本里只出现 `0x50` 与 `0xFF` 两种；
`0xFF` 被翻译成 `0x10`（0 号框）/ `0x90`（1 号框）。
这三个常数与 9 项分发表写进 `+0x3A` 的常数同源，
但「它是位置码还是样式码」在 ROM 里没有定论 —— 故 label 写「样式码」，note 里标注了取值来源。
