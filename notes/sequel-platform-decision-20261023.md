# 续作技术底座决策：Butano 重制 vs 静态重编译（2026-10-23）

**问题**：为《木叶战记》做续作、要加**大量新机制**，底座选「Butano 重制」还是「静态重编译版」？

**结论**：**续作主线用 Butano 重制**。静态重编译版不做续作底座，改任
「行为对照真值 + 独立产品线（原生复活/宽屏/Mod 分发）+ Butano 缺引擎能力时的兜底」。
逆向线不收口——它是 Butano 线的**规格来源**，但当前有一笔必须先还的债（见 §4）。

## 1. 决定性理由：新机制的写法与底座形态是绑定的

| | Butano 重制 | 静态重编译版 |
|---|---|---|
| 加一个新机制的动作 | 加一个 C++ 头/源 + 接线 | 写 native plugin 去**驱动一台 2003 年的机器码游戏** |
| 能不能重构原版战斗系统 | **能**（代码是自己的） | **不能**——13,271 个函数是不可读的降级汇编（`gf_afunc_080000C8` / `_r_08000234`），重构 = 重写 |
| 新机制会不会被原版结构顶住 | 不会 | **会**——单位数组只有 12 槽（`0x020240C0`）、动作表 60 项（`0x0806C478`）、机制表 13 项（`0x0808136C`），全是原版写死的接缝 |
| 成本可估性 | **已有实测模型**（§2） | 无可比成本：一旦要动原版内部，估算模型不成立 |

**今天这一轮就是活证据**：把「影分身一次造 5 个分身」变成现实，需要绕开
12 槽上限、绕开冷却计数与候选位交互（`notes/evidence/battle-action-system-20261023.md` §8b）。
在 Butano 里这是「一个新系统」；在重编译版里这是「动原版战斗核心」。
**「大量新机制」与「静态重编译」在架构上是冲突的**——重编译的价值是
「原样复活 + 在外面挂东西」，不是「在内部重构」。

## 2. Butano 线已有的实测数字（不是估算，是跑出来的）

| 证据 | 数字 | 出处 |
|---|---|---|
| 五个内核微基准 B1–B6 | 1,262 行 C++（含测试）+ 真实 ROM wiring，**29.34 分钟** | `butano-sequel/docs/butano-konoha-systems-cost.md` |
| **scenario 41 完整纵切片** | **7.9869 小时**；战前菜单→四回合胜利→结算→升级→11 页战后对白→世界地图→5 首 BGM→14 个音效；组合拳 264 帧在真实 mGBA 中 **264/264 normalized RGB 一致** | 同上 §「Goal 实测」 |
| 13 个基础系统总成本 | **80.9 / 121.3 / 191.2 Codex 连续墙钟小时**（乐观/基准/保守），推荐规划值 **121–191** | 同上「Codex 成本总表」 |
| 现有代码规模 | `butano-sequel/game/include/konoha/` **134 个头文件 / 6.42 MB**（battle_ai 54KB、battle_action_system 82KB、battle_scene_controller 86KB、battle_player_action_flow 66KB…）+ 4 个源文件 330KB | 工作树实测 |

**关键：重制 ≠ 丢手感。** scenario 41 的 264/264 逐帧一致已经证伪了
「复刻必然丢原版手感」这个担忧——这原本是选重编译版最强的反驳理由。

## 3. 静态重编译版的正确定位（不是废品，是位置不同）

已跑通的部分：静态覆盖 100%（`dispatch_misses=0`、`interpreted_insns=0`）、
中文画面与参考截图 SHA-256 逐字节相同、端到端构建 100 秒（`recomp/README.md`）。

它该干的：

1. **行为对照真值**：原版跑在 PC 上、可以下断点/改内存/看内部状态——
   比 mGBA 探针更细的对照台，用来判「Butano 复刻的这个行为对不对」。
   （`notes/static-recompilation-native-port-20261020.md` §6 已写明：
   逆向成果与移植工具「互补而非重复」。）
2. **独立产品线**：把原作在 PC/移动端复活、宽屏、内部分辨率、Mod 分发
   （框架的 adaptive widescreen + `.gbamod` 生态被明确写为「可直接借鉴的产品形态」）。
3. **引擎能力兜底**：Butano 做不到的（mod 分发、多人、诊断回放、foreign overlay），
   框架侧已经现成（`notes/recomp-modification-surfaces-20261020.md` 层 4）。

它不该干的：**当续作底座**。它没有任何「新机制」的承载能力。

> ⚠️ **2026-10-23 更新（前提变更）**：Butano 重制版的存在意图已被明确为
> **「获得一份与原版完全一致并且可进行任意修改的源码」**——
> 这不是续作，是**复刻**。⇒ 静态重编译版的地位**从"可选并行线"升级为
> "1:1 路线不可省的真值台"**：它是 100% 静态覆盖、确定性（每帧 `final_pc`/`cycles` 一致）、
> 540–600 fps、可 hook 的**可执行原版**，
> 正是"逐帧状态对拍"需要的 oracle。
> 完整路线见 `docs/butano-fidelity-roadmap.md`；
> 反编译选型的重裁见 `notes/recomp-modification-surfaces-20261020.md` §6.5/§6.6。

**今天这一轮挖出来的东西正是这一类**（属于尚未接进 Butano 构建的逆向成果）：

* 每个战斗单位带**两张 8 字节动作表**（`unit+0xD4` 源 / `unit+0x154` 生效）；
* 动作 id 由 **60 项跳转表 `0x0806C478`** 分派（`case = (id & 0x3F) - 4`）；
* 每个角色 5 个忍术槽 = action id **14/15/21/61/62**；
* 记录 +2 是**蓄力/冷却计数**（`fn 0x0806C308` 递减，归零才装弹）；
* 「选分身位置」= 候选表里挑一个**下标**（计数 @ `0x02025E00`、候选 @ `0x02025E02`）。

⇒ **续作加新机制之前，先按 M0–M7 把这些接进 Butano 构建**，
否则新机制会建立在「猜的行为」上，越往后返工越贵。

## 5. 决策表：什么目标选什么底座

| 目标 | 底座 | 理由 |
|---|---|---|
| **新故事 + 大量新机制 + 新数值体系 + 跨平台** | **Butano 重制** | 机制是代码不是数据；已有 7.99 h 的真实纵切片与 121–191 h 的成本模型 |
| 在原版基础上加内容（文本/地图/角色/章节），不碰机制 | **ROM 数据注入**（现有主线） | 工具链齐全，分钟级出包 |
| 在原版基础上加机制，且要保住原版手感与存档兼容 | **ROM patch / 静态重编译 + data injection** | 机制仍受原版结构约束；重编译只加外围 |
| 把原作在 PC/手机上复活（不叫续作） | **静态重编译版** | 已跑通，100% 静态覆盖 |
