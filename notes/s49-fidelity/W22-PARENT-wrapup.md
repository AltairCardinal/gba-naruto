## 4. ⭐⭐ D6：黑场的 4bpp 化**可行且零失真**（待接线）

### 4.1 ⭐⭐ 原版本来就是 **4bpp**（硬证据）

| 证据 | 内容 |
|---|---|
| 原版战场帧寄存器 | `DISPCNT = 0x1940`（**Mode 1**）；`BG0CNT=0x0000` / `BG1CNT=0x0009` / `BG2CNT=0x00A0` / `BG3CNT=0x0007` 的 **bit14（色深位）全部 = 0 ⇒ 4bpp** |
| 逐块 PRAM 回查 | 480 块中草地地图区 **100% 单调色板组**，跨组块与精灵位置逐一对应，**未映射像素 0** |
| 逆向线普查 | 79 描述符 / 300 层 = **4bpp 225 层、8bpp 75 层**；战斗描述符层位深 `[4,4,8,4]` |
| ⭐ **重制侧的 8bpp 是硬编码的** | `generate_butano_battle_runtime_assets.py:194` ⇒ **不是原版事实** ⇒ 改 4bpp 是**向原版看齐** |

### 4.2 ⭐⭐⭐ Butano 自己的量化器 ⇒ **像素 0 变化**

| 资产 | 槽数 | 像素变化 |
|---|---:|---:|
| `battle_14_map_chunk_0` | **5** | **0**（262,144 px 全同） |
| `battle_ui_dialogue_background` | **2** | **0**（65,536 px 全同） |
| `battle_preparation_background` | **1** | — |

⇒ **5 + 2 + 1 = 8 ≤ 16** ⇒ **两张全屏 BG 可同时在场** ⇒ **黑场的「16 槽瓶颈」被解开**
⇒ ⚠️ **但「图块重定位延迟」仍在**（C3：来方 718 块的搬迁延迟 = B2 +4、B4 +6）
⇒ ⇒ **实测前不能承诺 0 帧**。

### 4.3 前置条件（**接线时必须一起做**）

* ⚠️ 两张 BMP 的调色板**有重复颜色** ⇒ Butano 直接抛 `two used identical colors`
  ⇒ 必须先**无损去重**（256 → 47 / 256 → 29 项，**RGB 像素 0 变化**）
* ⚠️ **去重要写进生成器**，否则下次跑会被冲掉
* ⇒ **接线请求 R-D6-1**（共享树资产）：sidecar `"bpp_mode": "bpp_8"` → **`"bpp_4_auto"`** + 先去重
  ⇒ **R-D6-2**（生成器）：去重逻辑进生成器
  ⇒ **R-D6-3**：更正 C3 §3.0/§5.1 的「0 帧不可达」措辞
