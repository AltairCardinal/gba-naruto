## 2. F · 覆盖层规则判定（**关键路径**）

**问题**：原版覆盖层点亮的格到底是「可达范围高亮」还是「不可达范围压暗」？
（导出器自己的 `overlay_semantics` = unknown。）

**为什么现在能解**：探针有 `keyseq`/`framedump`，可以**把原版自己的状态逐帧导出来**
（原版存档 `artifacts/runtime-checkpoints/scenario-49-battle-14-entry.ss9` 在，
sha256 `a3628723…`），把「原版点亮的格」与「原版当时的游戏状态」对上。

**做法**
1. 载入原版存档，`keyseq`/`framedump` 导出原版**每帧**的覆盖层 map 与 EWRAM
   （`0x02000000` 起 ≥ 0x8000 字节，覆盖战斗状态区）。
   ⚠️ **读 I/O 块会扰动模拟**（读 VCOUNT 有副作用）⇒ **VRAM 与 I/O 必须分两次运行**。
2. 用 `tools/overlay_cell_diff.py` 定位原版那四个时刻的帧。
3. 把「亮区」与「原版 EWRAM 里的单位位置/可达集合/受阻集合」关联，判定规则，
   并写成**可执行判据**（输入：单位格坐标 + 地形属性；输出：每格该画哪个族）。
4. 顺带判定六族语义：`solid` / `edge` / `hatch` / `line_alt` / `band` / `blank`。

**验收**：对**四个时刻**分别预测原版点亮的格集合，**逐格全等**。

**产出**：`notes/s49-fidelity/F-rule.md` + `tools/s49_rule_probe/`（可复跑判定器）。

## 3. H · idle 节奏与相位（**真产品差**）

**两个已量化的差**：
* 原版在命令菜单打开那一刻画 slot 0 **frame 010**，重制画 **frame 011**（1 帧）。
* ⭐ **重制侧 32 帧周期里最多只出现 3 张图，原版是 16 张（本机）/ 30 张（macOS）**
  ⇒ 重制侧**跟不跟得上原版的待机节奏**。
* ⚠️ **【已证伪，见文首订正】** 原判「本机模拟器把动画推进放慢了一倍」
  ⇒ 上面这些绝对计数**现在可以跨模拟器比**（本机采集帧数 ÷2）；仍按**内容定位**判。
  ⭐ **H 流的实测结论**：重制侧 32 帧周期只有 3 张图，**根因不是「跟得慢」**，
  而是**重制侧没实现逐帧调色板改写**（原版每 1 帧改 OBJ 调色板 index 15，重制从不改）。

**做法**
1. 用 PRAM/调色板序列测出**重制侧与原版各自的「每 N 帧换一帧」节奏**（相对量）。
2. 找出重制侧为什么只有 3 张图：是图集缺帧、还是状态机跳帧、还是相位偏移。
3. **不要**用「整体平移 8 帧」——第 26 轮实测推翻并回滚了。
4. 只改 idle 那一处。

**验收**：该帧逐像素 0 px 差；**相对节奏**与原版一致；周边帧不得变差（棘轮）。

## 4. J · 音频事件级对照（分析）

原版 **MP2K**（GBA 上的软件 PSG 合成器），重制侧 **Maxmod**。
**逐采样一致三天内做不到**（复现 MP2K 合成器 80–120 h）⇒ 本轮按**事件级一致**交付。

**做法**
1. 用 recomp（原版真值，可执行、确定性、**747 fps**）导出这场战斗的
   **音频事件序列**（cue、触发点、顺序、切换、时长、参数）。
2. 导出重制侧 Maxmod 的同场事件序列。
3. 逐事件比对：缺失 / 多余 / 顺序错 / 参数错。

**验收**：一份逐事件差异表 + 明确结论。
