## 2. ⭐ 任务 A：把黑场挪回原版的 walk 时间轴

### 2.1 ⭐ 根因（与任务书 §0.2 的说法不同）

任务书 §0.2 写的是「重制侧 walk 采到 0 个黑场帧（最暗一帧非黑 0.8541）」。
**那条结论是用 wave 6 的旧录制得出的**，对 Z1 接线后的 ROM 不成立。
本流重新量了 Z1 之后的 ROM（`build/s49-pairing/x2/z1-dense/capture-remake`，783 帧）：

| 录制 | ROM | 采集帧 | 最暗非黑占比 | 纯黑帧 |
|---|---|---:|---:|---:|
| `walk5/dense-remake` | wave 6（Z1 之前） | 783 | 0.8541 | **0** |
| `x2/z1-dense/capture-remake` | wave 7（Z1 之后） | 783 | **0.0000** | **13**（idx 70 / 307-310 / 318 / 461 / 468-473） |

⇒ **Z1 之后黑场帧是存在的**（13 帧），最暗的一帧就是纯黑。

**真正的根因**：黑场由**玩家按 A** 触发，而 walk 的一拍是
「按 A（保持 4 帧）→ 等 90 帧 → 采样」⇒ **A 键恰好落在拍尾那一帧**。
黑场从按下的那一帧开始、66 GBA 帧后结束，比下一拍（94 帧）**早 28 帧**
⇒ **拍尾永远落在黑场之外**。

**佐证（原版自己的时间轴，`walk5/dense-original`，拍尾 = 90 + 94×拍号）**：

```
拍尾 #11 (帧 1124) = 0.0079   ← 原版近黑帧（星光圈第 8 级，305 亮像素）
拍尾 #18 (帧 1782) = 0.0000   ← 原版全黑帧（黑场持到最后一帧）
```

⇒ 原版的黑场**落在拍尾上**：事件 1 的淡出在拍尾处只剩 305 个亮点，
事件 2 的黑场持到拍尾的那一帧。
（星光圈级别表：`battle_black_field_star::visible_pixels[8] = 305` ⇒ 305/38400 = **0.00794** ✔）

### 2.2 修复：给黑场加一段「前置过渡」

原版在「确认」与「黑场淡出」之间本来就有一段过渡（实测 78 / 47 GBA 帧）。
重制侧原来**在按下的那一帧就开始黑场**，于是整整早了 28 帧。

改动（`battle_runtime_scene.cpp`）：

```cpp
constexpr int battle_black_field_event1_lead_frames = 36;   // 场景帧
constexpr int battle_black_field_event2_lead_frames = 24;   // 场景帧
```

* 事件 1（部署场景 → 黑场）：在 `deployment.complete()` 分支里，
  `wait_for_deployment_release()` 之后、淡出之前，**多跑 36 个场景帧**（画面正常）。
* 事件 2（对话 → 黑场）：主循环里加一个 `black_field_lead` 倒计时，
  倒计时期间**黑场独占屏幕**（输入不到控制器），到 0 才 `black_field.begin(...)`。

⚠️ **只调时间、不调结构**：黑场的 **24/18/24 = 66 帧**结构一行未动
（`battle_black_field_timing.h` 未改）。

## 3. 打字机速率（顺带修）

**现象**：Z1 接线后，对话帧的残差从 28/0/0/344/0 变成 674/702/417/412/756，
**丢了 3 个全 0 帧** ⇒ 判定台「全 0 帧数」这一项红。

**根因**：**重制侧的场景逻辑是 30 Hz，1 场景帧 = 2 GBA 帧**
（黑场的 12 级淡出覆盖 24 GBA 帧，与原版逐项相同 ⇒ 场景帧 = 2 GBA 帧）。
而打字机的间隔常量（`battle_presentation_typewriter_glyph_interval = 4` 等）
是按 **60 Hz** 写的 ⇒ **重制侧的字打出来是原版的一半速度**，
拍尾拍到的永远是半行字。

**修法**（在 W1 独占的文件里，不动 Z3/W3 的常量）：
主循环里把打字机**每场景帧推进两次** ⇒ 节奏回到原版的 60 Hz。
实测效果：对话段整体前移 1 拍（重制侧 3 屏对话现在每屏正好一拍），
判定台残差 110,526 → **109,597**。

### 4.2 ⭐ 星光圈：**没有接**（W2 的 VRAM 硬约束未解）

Z2 的遮罩素材（25 级 × 40 块 = 640 块/帧）仍是「已转换、未链接」。
本流**没有**接它，原因是 W2 的硬约束没解，而且本流又发现**第二重**约束：

> **级别切换要同时驻留两级**：Butano 的图块回收发生在**下一次 `core::update()`**，
> 所以从第 L 级换到第 L+1 级时，第 L 级的 640 块**还没被回收**，
> 而第 L+1 级的 640 块已经要分配 ⇒ **瞬时需要 1280 块 > 1024 块的上限**。
> ⇒ 「一帧 640 块」这个账本身就是**不够**的，W2 的方案必须把
> **级别切换的瞬时占用**（2 × 640 = 1280 块）也算进去。

⇒ 判决台不受影响（纯黑帧已经够用，见 §2.4）。
