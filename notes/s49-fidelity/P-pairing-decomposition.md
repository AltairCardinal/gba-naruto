## 0. 一句话结论

**「配对差 8 帧」不是同一种东西，必须拆成三桶**：
**① 2 帧是原版独有的黑场过渡（重制侧根本没有黑帧）**；
**② 3 帧是重制侧「连续两帧完全相同」的静止帧**（原版 0 处）；
**③ 其余 3 帧是相机滚动/镜头过渡的中间态**。

另外挖出一条**独立的产品差**（原版 0 处 / 重制侧 3 处），
可直接当 **H2 流的验收门禁**。

## 1. 判定台的逐帧归因（自跑复现，`content_sha` = `a5cdf0d8…`）

`python tools/s49_fidelity_report.py --out build/s49-report/report-main.json` → exit 0

```
field px    : min 0  median 1940  max 27325  zeros 3/25
attribution : {'identical': 3, 'product_diff': 14, 'pairing_diff': 8}
confidence  : {'high': 15, 'medium': 8, 'low': 2}
```

判定台用三个信号投票判「是否同一游戏时刻」：
`structure_match s`（结构同构，阈值 0.70）、`diff_block_occupancy o`（差异块占比，阈值 0.40）、
`diff_row_spread r`（差异行占比，阈值 0.85）；**2/3 判同 ⇒ 同一时刻 ⇒ 产品差**，否则 ⇒ 配对差。

## 4. ⭐ 挖出的独立产品差：**重制侧有连续静止帧，原版没有**

逐帧 PNG 的 sha256 比对：

* **原版 25 帧：全部互不相同**（0 处重复）。
* **重制侧 35 帧：3 处连续两帧完全相同** ——
  `step-24 == step-25`（`6d9fad23…`）、
  `step-30 == step-31`（`48462ede…`）、
  `step-32 == step-33`（`37517dbf…`）。

⇒ 这三处是**按键没有产生任何画面变化**的步子 —— 原版在同样的步子下**每帧都有变化**
（原版逐帧改 OBJ 调色板 index 15 ⇒ 描边波每帧都在动）。

⇒ **这给 H2 流（逐帧调色板改写）提供了一条独立的、可复跑的验收门禁：**

```
判定：重制侧任意两次连续采样之间，不得出现**完全相同的整帧**
     （原版基线 0/24；重制侧当前 3/35）
```

**这条门禁不依赖判定台的归因逻辑，是纯像素事实**，且直接对应
「重制 32 帧周期只有 3 张图 vs 原版 16/30 张」这个产品差。

> ⭐ **2026-10-24 订正（wave 3 的 H2 流证伪了这条判据）**：
> **原版自己也会出现连续两帧完全相同** —— 每 100 个 GBA 帧 **4 次**，
> 且**恰好落在描边波形的平点**（相位 **9→10** 与 **25→26**）。
> ⇒ **绝对判据不成立**，正确判据是：
>
> ```
> 判定：只允许在**波形平点处**出现连续相同帧
>       （原版 100 GBA 帧 / 4 对，全部落在平点 ⇒ 合规；
>         重制侧 3 处异常重复 ⇒ 不在平点 ⇒ 违规）
> ```
>
> 工具：`tools/s49_idle_frame_repeat.py`（H2 已建，`--stride 2 --pose …original-sweep-pose.json`
> 可以按 GBA 帧定位相位）。
> 另：H2 测出**原版描边色是 7 级 5bit `[1,5,11,13,17,23,27]`，重制侧只有 1 级 `[1]`** ——
> 这才是「重制侧 3 张图 vs 原版 16/30 张」的根因。

## 5. 配对偏移在漂移 —— 说明两侧 walk 处在**不同的游戏时刻**

`best_match` 给出的（原版 step → 重制侧 step）映射：

```
step-00→04  01→05  02→06  03→07  04→08  05→09  06→10  07→11  08→12
09→12  10→12  11→16  12→16  13→14  14→14  15→15  16→16  17→16
18→16  19→17  20→17  21→11  22→07  23→18  24→19
```

偏移从 **+4** 一路漂到 **−15**，且在 `#21 / #22` 处**反向跳回**（重制侧匹配到更早的 step-11 / step-07）
⇒ **不是「同一步没画对」，而是两条 walk 走过了不同的游戏序列**。

⇒ **wave 4 必须做的不是「把配对差帧改到 0」，而是先把配对基准从「帧序号」换成「游戏时刻」**
（用**内容锚**：名册 HP、菜单开合状态、相机滚动位置、覆盖层格集合当锚点）。

## 7. 对 wave 4 的影响（交给父代理排期）

1. **配对基准必须换成「内容锚」**，不能继续用帧序号 —— 否则配对差永远收不掉。
2. **黑场过渡**要单独判定：原版在哪个相位淡出黑场？重制侧要不要实现？（**这是「玩家看得见的画面」的一部分**）
3. **静止帧门禁**已可复跑，应纳入 wave 4 的逐帧棘轮。
4. **配对差里的 3 帧「结构完全不同」**（#21/#22）很可能是 walk 序列问题而不是产品问题，
   换 walk（两边用**同一条按键语义序列**而不是各自的最优匹配）可能直接消掉。
