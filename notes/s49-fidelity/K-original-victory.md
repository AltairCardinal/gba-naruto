## 3. 观察到什么 —— 原版 battle-14 的战斗 UI 真值

这一节是本流的主要产出：**原版 S49 的战斗界面结构此前没人拆过**
（wave-1 只留下了「按 A 会出现菜单」这种黑箱式的按键序列）。

### 3.1 画面结构

| 画面 | 判定 | 证据 |
|---|---|---|
| 行动菜单（5 项竖排，左缘 x≈8–58, y≈16–133） | 边框列 x=8 上有 ≥70 行 `(107,156,90)` | `battle.menu()` |
| 紧凑菜单（2 项：`术·忍具` / `行動結束`） | 同列 25–70 行 | 同上 |

| 错误提示框（`请把对方设置在范围内` 等） | 填充色出现在 y≥71 的**宽**框 | 与确认框可判别（68 px vs 2265 px） |

### 3.2 菜单内容（原版中文）

* 行动菜单：`移動` / `术·忍具` / `查克拉` / `休息` / `行動結束`
* 忍术列表：`变身术` / `影分身术` / `忍者组合拳` / `十字手里剑`
  * `变身术`：消耗查克拉 1，距离 3，范围 1，成功率 100% —— **瞬间移动**
  * `影分身术`：消耗查克拉 1，距离 3，范围 1，成功率 100%
  * `忍者组合拳`：消耗体力 0，攻击力 10×1，距离 1，范围 1，成功率 98%
  * `十字手里剑`：消耗体力 0，攻击力 6×3，**距离 3 直**，范围 1，成功率 90%
* `查克拉` 菜单在查克拉已满时回答 `不能再蓄积查克拉了`（全员初始 5 点，木材丸 4 点）
* ⚠️ **忍术列表是按角色不同的**：鸣人是 `变身术 / 影分身术 / 忍者组合拳 / 十字手里剑`，
  而**佐助**的列表里是 `火遁术`（威力 15×1、距离 2 直、范围 1、成功率 95%）
  —— 采集帧 `build/s49-victory-capture/capture/attack-slice-sheet.png` 里两者的
  信息面板并排可见。⇒ 重制侧不能把忍术列表写死成一套。

### 3.3 战斗流程（一次「我方回合」）

```
回合横幅「回合 N 玩家 的行动」
  → 「请等待...」
  → 移动阶段（青色格子 = 可走范围）
  → 行动菜单（5 项）
       ├ 移動 → 移动阶段 → 紧凑菜单（术·忍具 / 行動結束）
       ├ 术·忍具 → 忍术列表 → 瞄准模式
       │      ├ 变身术 → 传送瞄准（橙色格子 = 合法落点）→ 可以嗎? → 是 → 位移
       │      └ 十字手里剑 → 瞄准（橙色十字 = 射程）→ 伤害预测 → 可以嗎? → 是 → 演出
       ├ 查克拉 → 蓄积查克拉
       ├ 休息 → 恢复体力
       └ 行動結束 → 可以嗎? → 是 → 结束该单位的行动
  → 下一个我方单位（玩家操作全体 4 名同伴）
  → 敌方阶段（蜜蜂「蜂刺」远程攻击，不移动）
  → 战斗对白 → 下一回合
```

### 3.4 关键规则

| 规则 | 内容 | 证据 |
|---|---|---|
| **玩家操作全体** | 每回合依次由玩家操作 4 名同伴；敌方 5 只蜜蜂由 AI 控制 | 名册 + 行动菜单逐个出现 |
| **十字手里剑的距离** | 目标必须与出手单位**同行或同列**且 ≤3 格；游标必须**落在蜜蜂身上** | 超出范围时游戏回答 `请把对方设置在范围内` / `请指明射范围` |
| **十字手里剑的伤害** | 实测 25 → 7（18 伤）、25 → 3（22 伤），**一发几乎能打死一只蜜蜂** | A4 / A5 |
| **变身术的落点** | 距离 3 的直线，落点非法时回答 `请选择其他的场所`；确认后**约 400 帧**才完成位移 | 隔离实验 `build/s49-victory-capture/teleport_test.py` |
| **EWRAM 地标** | 行动菜单光标 `0x0200A8BA`；菜单层级 `0x02026A8C`（3=行动菜单，4=忍术层）；瞄准/移动游标 `0x02026A78`(x) `0x02026A79`(y) `0x02026A7A`(有效位)；单位池 `0x020240C0`（stride `0x1D4`，x=+0xC4，y=+0xC5，acting=+0xC1）；HP 数组 `0x020242A0`（stride `0x1D4`） | 差分实测（§6 台账） |
| **HP 数组相对池下标错一位** | 池下标 p（1 起）对应 HP 数组下标 p−1 | A1：池 1 号记录在 (11,6) 且 HP 138 |

## 4. 采集仪器（`tools/s49_victory_capture/`）

### 4.1 一条命令

```powershell
python tools/s49_victory_capture/capture_victory.py --out build/s49-victory-capture/capture
```

产出：

* `frames/` —— 每次按键后的 PNG（帧序列，文件名带全局帧号）
* `ewram/` —— **逐帧**的战斗状态块（单位池 + HP，`0x02024000` 起 0x1300 B）
* `vram/` —— **逐帧**的整块 VRAM（`0x06000000` 起 0x18000 B），
  **单独一次运行**，且**只在终局（存活蜜蜂 ≤1）开始录**（一帧 96 KiB，
  全程录会到 GB 级；结算屏才是要的东西）
* `capture.json` —— 收据：ROM/存档哈希、路线（每一次按键带标签）、帧号、
  全部文件的 sha256 清单（**不含墙钟字段**，两次连跑逐字节一致）
* `runtime.json` —— 旁挂：本次运行的墙钟耗时（**唯一**不保证逐字节一致的文件）

> **VRAM 与 I/O 分两次运行**：读 VCOUNT 有副作用，所以本流**不读 I/O**，
> VRAM 单独一遍，EWRAM 单独一遍。

### 4.2 逐步复现任意一步

```powershell
python tools/s49_victory_capture/shoot.py --state <checkpoint> --out <dir> --keys "A,Down*3,A"
```

### 4.3 驱动器的判据（全部是内容驱动，不按帧号）

* 行动菜单 / 紧凑菜单 / 忍术列表 —— 屏幕像素签名（§3.1）
* `可以嗎？` 确认框 —— 确认框像素签名（与错误框可判别）
* 出手单位的位置 —— **进入瞄准模式时游标就落在出手单位身上**（实测）
* 目标的合法性 —— **让游戏自己判**：合法则弹 `可以嗎？`，非法则弹错误框
* 敌方/我方 HP —— EWRAM `0x020242A0`

### 4.4 驱动器实际跑出来的路线（第 1 个单位 = 鸣人，首个命中）

采集收据 `capture.json` 的 `ewram_pass.log` 里逐键记了整条路线。
第 1 个单位的 39 个按键是：

```
A A A A A A A A A A A A A A A A A A A A A   ← 开场演出 + 对白 + 回合横幅 + 移动阶段
Left Left Left                              ← 移动游标：鸣人 (11,6) → (8,6)
A                                          ← 确认移动 → 紧凑菜单（术·忍具 / 行動結束）
A                                          ← 术·忍具 → 忍术列表
Down Down Down                             ← 十字手里剑
A                                          ← 选中 → 瞄准模式
Left Left                                   ← 瞄准游标 → 蜜蜂 (6,6)
A                                          ← 开火 → 伤害预测 → 可以嗎?
A A A A A A                                ← 是 → 演出 → 结果
```

结果：**蜜蜂 8 号 HP 25 → 7**（`attacked {'slot': 8, 'hp': [..., 7, 25]}`）。

## 5. 卡在哪（诚实交代）

**未闭环**：从 battle-14 入口一路打到「胜利结算屏」的**完整自动路线**没有跑通。
卡点是**距离与地形**，不是机制：

1. 蜜蜂初始在 x=3..6，同伴在 x=8..11；十字手里剑要**同行/同列且 ≤3 格**。
2. 第 1 个单位（鸣人）**已经打通**了「移动 → 瞄准 → 开火」整条链（§4.4，命中 25→7）。
3. 但第 2 个单位（小樱 (8,14)）的移动落点**全部非法** —— 底边一行有地形阻挡，
   驱动器换过的每个候选格都被游戏拒绝（`请在移动范围内选择`），
   于是这一回合既没动也没打，回合不推进，驱动器的回合预算耗尽。
4. 同理，**变身术**的落点也受地形限制（第 3 个单位的 (4,14) 没落地）。

**已经验证可行的打法**（wave-1 的 artifact 链，本机重放成功）：

| 阶段 | 按键序列 | 效果 |
|---|---|---|
| 移动到射界 | `Down,A,A,Left,Left,Left,A`（变身术，左 3 格） | 鸣人 (11,6) → (8,6) |
| 瞄准开火 | `A,Down,A,Down,Down,Down,A,<方向>,A,A` | bee-4 25 → 3 |
| 打完一回合 | `A,A,A` | 结束行动 |
| 跳过同伴 | `A,Down*4,A,A,A,A` | `行動結束` + 确认 |
| 敌方阶段 | `A` + 长等待 | 蜜蜂「蜂刺」 |

**下一步该做什么**（留给续跑的会话）：

1. **把「合法落点」从游戏里读出来**，不要再用坐标猜：移动阶段与传送瞄准阶段
   都把**合法格子画成青色/橙色**，游标画成绿色框 —— 在屏幕上找出橙色格子，
   用「游标像素位置 → 目标像素位置」换算成 D-pad 次数，就能保证一次选到合法格。
   这一条会同时消掉「非法落点 → 错误框 → 卡死」和「落点不落地」两类问题。
2. 攻击分支已经能稳定命中（§4.4），只差「先把单位拉到射界」这一步。
3. 木叶丸 40 血 → 建议**前两回合集中保护木叶丸**（让他站在后排、跳过他的行动），
   否则第三回合他就会死，输出从 4 人降到 3 人。
