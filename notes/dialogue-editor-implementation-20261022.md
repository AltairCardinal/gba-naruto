# 可视化对白编辑器 —— 实现笔记（2026-10-22）

**用户要求**：「制作可视化对白编辑器，要做到能将对白显示在背景上，并正确显示立绘与对白框中文字，
并提供对白的快速跳转、实时播放等功能」

**范围**：`rom-editor/js/dialogue.js`（模型）、`rom-editor/js/stage.js`（整幅画面）、
`rom-editor/js/portraits.js`（立绘）、`rom-editor/js/dialoguefont.js`（字形与对白框）、
`rom-editor/js/modules/dialogueview.js`（视图）、`rom-editor/css/dialogue.css`、
`rom-editor/tools/verify_dialogue_view.mjs`（门禁）、`rom-editor/tools/{domstub,png}.mjs`（工具）、
`tools/probe_story_{dialogue,portrait}.mjs`（探针）。

---

## 0. 一句话

把一场剧情脚本**按游戏里的样子**画成 240×160 的画面（背景 + 立绘 + 对白框 + 名牌 + 正文），
右边列出这一场的每一句对白，点一下就跳过去，也能连续播放；正文**可以就地改**（仍然必须等长）。

**画面不是「用系统字体显示解码后的文字」** —— 背景、立绘、对白框、正文、名牌
**全部按 ROM 里的原始数据画**，所以看着就是游戏里的样子。

---

## 1. 走过的路

### 1.1 先把三段「像素链」查清（并行派了三个子代理）

| 链 | 结论 | 考证 |
|---|---|---|
| **背景** | 剧情底图是 **256×80**（32×10 图块），放在 BG0 的 32×32 屏幕块里，`BG0VOFS=-8` 把它**往下挪 8 像素** ⇒ 真正的画面落在屏幕 **y=8..87**；底图表条目 `+0x0C` 的 `bpp_flag`：0=4bpp，非 0=**8bpp** | `notes/evidence/story-background-chain-20261022.md` |
| **立绘** | `0x02/0x04` 选 `<槽> <头像ID> <表情>` → 表 `0x085A4DEC` 的项 `(LZ77 8bpp 图形, 64 色调色板)`；100 张图块按**拼块表顺序连续消费**拼成 80×80；贴在 (16,8) / (144,8) | `notes/evidence/portrait-render-chain-20261022.md` |
| **字形** | 汉字字形就在 ROM 的 `0x0853D644`，但格式被旧笔记记错：实为 **8 宽 × 16 高、2bpp、32 字节/字形**；屏幕上一个汉字 **8×16 px、字距 8 px、1:1 不缩放** | `notes/evidence/dialogue-font-render-20261022.md` |

### 1.2 三处「旧笔记错了」

1. **对白调色板的文件偏移**是 `0x9C877`，不是笔记里写的 `0x9C87E`（偏了 7 字节）。
   颜色 8–11 那一段在 `0x9C887`，反推基址 = `0x9C887 − 16 = 0x9C877`。
2. **字形格式**：旧笔记写「8×8 4bpp」，实为「8×16 2bpp」；旧笔记的「16×16 / 字距 12 px / 标点 8 px」
   三条测量全错。
3. **`0x02/0x04/0x08/0x0E/0x11` 的语义**被推翻（见 `notes/story-vm-opcodes-20261020.md` §7
   的更正表）：`0x02/0x04` 是**设立绘**，`0x08` **只设名字**，`0x11` **清立绘**。

### 1.3 顺带查出并修掉一个**内容包导出的 bug**

`tools/export_content_pack.py` 里 `SPEAKER_NAME_COUNT = 32`（注释写「记录数未确证」）。
实测这张表**有 64 条**（id 0..63；id 0..62 是角色名，id 63 是「没有」；id 64 起是别的数据），
而剧情 VM 的 `0x08` 指令按 id 取名 —— 于是**伊鲁卡、阿斯玛、红、阿凯、惠比斯、伊那里、卡多、
红豆、伊比喜、手内、志治、蜜蜂、津美……这 31 个角色名在编辑器里根本查不到**。

⇒ 改成 64 并重新导出（`python tools\export_content_pack.py`，`--check` 通过）。
**这个 bug 是做可视化对白编辑器时才暴露的** —— 场景 54 的第 5 句在真机上是伊鲁卡在说话，
而编辑器查出来是「鸣人」。

## 2. 界面

```
┌────────────────────────────────┬──────────────────────────┐
│  舞台（240×160，两倍放大）        │  这一场 135 句             │
│  ┌──────────────────────────┐  │  #1  漩涡鸣人  0x0804…    │
│  │  背景 + 立绘 + 对白框      │  │  [正文输入框 + 字节预算]  │
│  │  + 名牌 + 正文（原字形）   │  │  #2  …                   │
│  └──────────────────────────┘  │  …                       │
│  [播放][上一句][下一句] 每句 N 毫秒  第 5 / 135 句          │
└────────────────────────────────┴──────────────────────────┘
```

- **舞台**：整幅画面是**像素**（背景、立绘、框、名牌、正文都是）。
  DOM 里另存一份文字（屏幕阅读器能读，也方便自动化检查）。
- **对白列表**：一行 = 一句。序号 + 说话人 + 正文输入框 + 字节预算。
  点序号那一块 → 舞台跳到那一句（当前句在列表里高亮并滚到可见）。
  **整张卡都能点**（见 §3.1），只有正文输入框与「跳到原始字节」保留自己的动作。
- **播放**：按**脚本顺序**一句一句推进，间隔可调（默认 2200 ms）。
- **就地改对白**：复用 `js/scripttext.js::textSegmentCell`（输入框 + 字节预算 + 跳到原始字节），
  **等长**规则与写回通路都是同一套 —— 长度对不上当场拒收并回滚。
- **深链接**：`#story/dialogue/<before|after|logic|events>/<场景>`。

## 3. 写回

**没有新开任何通路**：改对白仍走 `pack.setBytesAt`（`js/scripttext.js::commitSegment`），
撤销、构建时的「原字节必须匹配」校验全都是既有机制。

### 3.1 「整块可点」（第十四轮加的）

用户反馈：**「对白列表中能让这条对白作为当前对白显示的点击区域只有第一行，
应当扩大范围到整个卡片没其他点击功能的区域都能作为选中的点击。
也检查其他功能做同样修改」**

做法：新增 `js/ui.js::clickableArea(node, action)` ——

- 给整块挂一个点击处理；
- 但**自带别的功能的地方不抢**：按钮、链接、输入框、下拉框、标签，
  以及标了 `data-no-area-click` 的元素（还有 `xref-link` 这类「自己就是入口」的标记类）；
- 顺带加 `.area-clickable` 类（鼠标显示手型）。

套用到了：

| 地方 | 整块的动作 |
|---|---|
| 对白列表的每一句（`modules/dialogueview.js`） | 把这一句设为当前句 |
| 域首页「本域可编辑内容」的每一行（`modules/common.js`） | 打开那张表（与点「打开 / 编辑」按钮同一个动作） |
| 素材域的同类表（`modules/assets.js`） | 同上 |
| 奖励列表的每一行（`modules/item.js`） | 跳到这条奖励（另一个链接「在奖励表里打开」保留自己的动作） |

**没改的**：详情面板内部的 `xref-link`（「跳到忍具 #N →」这类）——
它们本来就**不是列表行**，链接本身就是自然目标；改成整行反而说不清该跳哪儿。

门禁：`verify_dialogue_view.mjs` 第 10 组（点行里的普通元素会选中；
点正文输入框**不会**切换）+ `verify_views.mjs`（点整行与点入口按钮打开的是同一个地方）。

## 5. 已知与真机画面**对不上**的两处（不是 bug，是仓库还没查清）

1. **左边那个金发人物** —— 它**不是**消息框立绘：脚本在那一帧前已经用 `0x11` 清了槽 0。
   它是过场 / 场景人物精灵，**复用了同一份图块数据但有自己的调色板**，
   那套调色板的来源**未闭合**（`notes/evidence/portrait-render-chain-20261022.md` §6.6）。
2. **对白框的边框花纹与左右装饰** —— 那是 BG3 的一组**图块图形**，
   仓库还没定位到那组图块。所以框是**用同色系画出来的等效框**：位置与配色对，**花纹不对**
   （框内底色 `#E7F7D6`、边框 `#63BD73`/`#6B9C5A`、两条黄线 `#E7D663` ——
   全部是从真机画面逐行扫描量出来的）。

## 6. 还没做的

- **加对白 / 加分支**：那要搬迁整段脚本并重写所有绝对分支目标，本轮不做。
- **不等长改写**：会移位后面的指令、让分支失效，做不了。
- **立绘的表情选择**：`0x02/0x04` 的表情字节已经在模型里，但界面上还不能换。
- **对白框的 BG3 图块**：没定位到，所以框是等效画法。
- **场景 47/48/49 的底图**：按 `0x0808F4D4` 的规则会读到**越界的垃圾条目**（96/36/214），
  界面上会照实画不出来（不是本轮引入的问题）。
- **游戏侧行为**：改完真的改变触发吗？**没有跑模拟器验证** —— 写回通路是字节级验的
  （补丁 before/after 等长、构建无错、指令偏移不变）。
