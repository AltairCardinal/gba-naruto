> "原生拾取分派只有 7 个处理程序，对方那 13 种机关是叠加命名"。

## 0. 结论摘要

|---|---|---|

## 1. 配置矩阵里的物件记录

```
战斗配置基址  0x085461C4
  + stage * 0x1AAC      (48 组)
  + sub   * 0x8E4       (3 变体)
  + 0x8A4               16 条 × 4 字节物件记录
```
每条 4 字节 = `type, target, x, y`（`type` 在 +0，`target` 在 +1）。

**战场只有 stage 1..46**（`tools/event_queue_budget.py` 用 `range(1, 47)`）。
stage 47 的 `+0x8A4` 区**不是物件记录**（实测出现 type=8/12/34/35/55/56/84/239
这类非法值），stage 0 全 0。**扫描范围必须限制在 1..46**，否则分布会被垃圾数据污染。

### 1.1 建立期分派（表 A，`0x0806E868`）

代码在 `0x0806E810` 起的循环里：对第 `r6` 条记录取 `record[0]`(=type)，
`type-1` 查表 A，每支分支决定"要不要生成这个物件"以及"生成什么运行时类型"。

```
0806e836: ldrb     r0, [r4]        ; record[0] = type
0806e838: strh     r0, [r1]        ; 存成 u16 放进 sp[0..1]
0806e83a: ldrb     r0, [r4]
0806e83c: subs     r0, #1
0806e840: cmp      r0, #6
0806e842: bls      #0x806e846
0806e844: b        #0x806e946      ; type 不在 1..7 → 跳过该条
0806e846: lsls     r0, r0, #2
0806e848: ldr      r1, [pc, #0x18] ; = 0x0806E868
0806e84c: ldr      r0, [r0]
0806e84e: mov      pc, r0          ; 跳进 type 分支
```

表 A（`0x0806E868`，7 项）：

| type | 表 A 目标 | 分支做了什么 | 运行时类型 |
|---|---|---|---|
| 1 忍具 | `0x0806E884` | 直接建槽 | **3**（`0x0806E88E movs r0,#3`） |
| 2 强化素材 | `0x0806E884` | 与 type1 **共用同一支** | **3** |
| 3 专属修行卷轴 | `0x0806E898` | `bl 0x0806D658(target)`；非 0 → **不生成**；为 0 再到队伍表 `0x02022E30`（步长 `0xBC`，字段 +4 = 角色 ID）里找同号人物，找到才建 | **4**（`0x0806E92E movs r0,#4`） |
| 4 认识卡 | `0x0806E8C8` | `bl 0x08068EA4(target)`；非 0 → **不生成**（该角色已取得） | **3**（`0x0806E8E0 movs r0,#3`） |
| 5 机关宝箱 | `0x0806E8E4` | 直接建槽 | **3**（`0x0806E8EE movs r0,#3`） |
| 6 特殊机关 | `0x0806E8F8` | 直接建槽 | **4**（`0x0806E902 movs r0,#4`） |
| 7 剧情物件 | `0x0806E90C` | `target == 9` 走一支，否则另一支 | **5 / 6**（`0x0806E91A movs r0,#5`、`0x0806E93C movs r0,#6`） |

> 运行时类型由 `tools/mechanism_map.py` 的 **CFG 走查**（不是线性扫描）自动读出：
> 分支代码是互相穿插的，线性扫描会串到别的分支去。

条件生成的判据（可判死）：

* `0x0806D658(char_id)` = 0x0806D658 在队伍表 `0x02022E30 + n*0xBC` 里找 `+4 == char_id`
  的项；若该项 `+0x54+i*4` 的字节 ≤ `0x17`（已解锁）→ 返回 1（**不生成卷轴**）。
* `0x08068EA4(char_id)` 查位图 `0x020240AC + (id>>5)*4` 的第 `id&31` 位；
  置位 = 1。→ **认识卡取得过就不再生成**。

### 1.2 运行时物件槽（16 字节 × 32 槽）

```
WRAM 0x02026604 + slot*16      (32 槽；0x02026604+512 = 0x02026804 = 战斗控制块，边界自洽)
  +0x00 u8  运行时类型 3/4/5/6   (0 = 空槽)
  +0x01 u8  x
  +0x02 u8  y
  +0x04 u16 **记录 type**（表 A 分支里 `strh r0,[sp]` 存的就是 record[0]）
  +0x06 u16 **记录 target**
  +0x0C u32 附加字（建槽时清 0）
```

建立函数 `0x08081024`：

```
08081036: ldr      r2, [pc, #0x38]   ; 0x02026604
08081038: lsls     r0, r4, #4        ; slot*16
0808103c: ldrb     r1, [r0]          ; 该槽是否已占
08081042: strb     r3, [r0]          ; +0 = 运行时类型
08081044: strb     r6, [r0, #1]      ; +1 = x
08081046: strb     r5, [r0, #2]      ; +2 = y
0808104e..08081056: 复制 4 个 u16（sp[0..3]）到 +4,+6,+8,+0xA
08081068: bl       #0x8080fc8        ; 把槽号写进地图格表
```

地图格表 `WRAM 0x02021E2C`（u16/格，宽度取自 `0x0201BE2A`）的 **bit6..10 = 物件槽号**：

```
08080fd4: ldr      r4, [pc]          ; 0x02021E2C
08080fd8: ldrb     r3, [r3]          ; 地图宽
08080fda: muls     r2, r3, r2        ; y*宽
08080fdc: adds     r1, r1, r2        ; +x
08080fe2: lsrs     r0, r0, #0x12     ; 槽号 << 6
08080fe6: orrs     r0, r2
08080fe8: strh     r0, [r1]          ; 写回格表
```

**结论**：配置里的 `x,y` 是"物件放在地图哪一格"，`type/target` 是"它是什么、做什么"。
运行时槽的 `+4` 就是配置的 type 字节，`+6` 就是配置的 target 字节。

## 2. 拾取期分派（表 B，`0x080815E4`）——7 个处理程序

拾取入口 `0x08081544`：

```
0808155a: ldr      r0, [pc, #0x74]   ; 0x020240C0
08081558: muls     r1, r0, r1        ; 0x1D4(468) * 单位槽号
08081562: ldr      r1, [r0]          ; 单位 +0xC0 标志
08081566: ands     r1, r0            ; &0x0E
08081568: cmp      r1, #2 / #4 / #6  ; 等于 2、4、6 就放弃
0808159a: ands     r0, r1            ; 格表 bit6..10 = 槽号
080815aa: adds     r7, r1, r0        ; r7 = &槽(0x02026604 + slot*16)
080815ac: ldrb     r0, [r7]          ; 运行时类型
080815ae: subs     r0, #3            ; (type-3) & 0xFF
080815b4: cmp      r0, #3
080815b6: bls      ...               ; 只有运行时类型 3/4/5/6 继续
080815ba: ldrh     r0, [r7, #4]      ; **配置 type**
080815bc: subs     r0, #1
080815be: cmp      r0, #6
080815c0: bls      ...               ; type 必须 1..7
080815c4: lsls     r0, r0, #2
080815c6: ldr      r1, [pc, #0x18]   ; 0x080815E0 → 0x080815E4（表 B）
080815ca: ldr      r0, [r0]
080815cc: mov      pc, r0            ; 尾调用
```

**表 B（`0x080815E4`）= 按"记录 type − 1"分派**：

| 索引 | 记录 type | 地址 | 原生行为（一句话） |
|---|---|---|---|
| 0 | 1 忍具 | `0x08081600` | 读忍具名表 `0x599634` 显示名称 → 记拾取 → 弹窗 → 登记"已持有" |
| 1 | 2 强化素材 | `0x0808173C` | 读素材名表 `0x5A7E8C` 显示名称 → 记拾取 → 弹窗 → 登记"已持有" |
| 2 | 3 专属修行卷轴 | `0x0808180C` | 在队伍表 `0x02022E30` 找同号人物 → **解锁其专属修行** → 显示人物名 + 修行名 |
| 3 | 4 认识卡 | `0x080818E4` | 读人物名表 `0x599280` 显示人物名 → 置"人物已遭遇"位 |
| 4 | 5 机关宝箱 | `0x08081984` | 机关总入口：`target==9` 走计数分支，否则走 13 项效果表 |
| 5 | 6 特殊机关 | `0x08081984` | 同上（同一地址） |
| 6 | 7 剧情物件 | `0x08081984` | 同上（同一地址） |

> 第 8 项起不再是 ROM 指针（`0x080815FC` 之后是代码/字面量池）。

## 3. 7 个处理程序的逐个证据

所有 handler 开头都一样：

```
adds r0, r4, #0 ; adds r0, #0xc0 ; ldr rX, [r0]   ; 单位 +0xC0 标志
movs r0, #1 ; ands rX, r0
cmp rX, #0 ; beq <继续> ; b #0x08081B60           ; 标志 bit0 置位 → 放弃
```
（`0x08081B60` 是所有 handler 共享的出口：`add sp,#0x10; pop {r3,r4,r5}…`）

紧接着每支都会算当前战场配置并读 `config[0]` 播音效：

```
08081610: ldr      r3, [pc, #0x94]   ; 0x085461C4 配置矩阵
08081612: ldr      r2, [pc, #0x98]   ; 0x02026804 战斗控制块
08081614: ldrb     r1, [r2, #2]      ; battle_sub
08081618: muls     r0, r1, r0        ; *0x8E4
0808161a: ldrb     r2, [r2, #1]      ; battle_stage
0808161e: muls     r1, r2, r1        ; *0x1AAC
08081622: adds     r0, r0, r3
08081624: ldrb     r0, [r0]          ; config[0]
08081626: bl       #0x8061e88        ; 播音效（m4a 引擎入口 0x809AB8C）
```
`config[0]` 全 46 战场取值只有 `{0,6,8,10,11,12,14}`（0 = 默认），
是**每个战场的 1 字节场景/音乐 id**。

### 3.1 [0] `0x08081600` — 忍具

```
0808162a: ldrb     r0, [r7]          ; 运行时类型
0808162c: bl       #0x80814fc        ; 按类型取音效并等待播完
08081642: ldr      r1, [pc, #0x78]   ; 0x08599634  忍具名表（93 条）
08081644: ldrh     r0, [r7, #6]      ; target = 忍具 id
08081646: lsls     r0, r0, #2
0808164a: ldr      r0, [r0]          ; → 名字文本指针
08081654: bl       #0x8066758        ; 打印名字
08081666: bl       #0x808fa34        ; 记一次拾取
0808166e: bne      #0x08081672       ; 返回值非 0 才继续
08081670: b        #0x08081a50       ; 返回 0 → 直接收尾
08081684: bl       #0x8066ae8        ; 建窗口
0808168c: bl       #0x8092e80        ; 画窗口内容
080816a0: ldrb     r0, [r7, #6]
080816a2: bl       #0x808fa88        ; 登记"已持有"
```
* `0x080814FC` 的类型→音效映射（**运行时类型**，不是记录 type）：
  3 → `0x6B`，4 → `0x6A`，5 → **无音效**，6 → `0x75`；播完用 `0x8061E98` 轮询等待。
* `0x0808FA34(id)`：把 `0x02023FD5+id`（每 id 一个计数）与总数 `0x02023FD4` 各 +1，
  **总数 > 0x62(98) 时返回 1，否则返回 0**；H0 拿到 0 就直接结束、拿到 1 才弹窗并登记。
  ⚠️ 这个 98 阈值的设计意图**未证**，只记录代码事实。
* `0x0808FA88(id)`：读同一张 `0x02023FD5+id` 表 → "是否已持有 / 标记已持有"。

### 3.2 [1] `0x0808173C` — 强化素材

与 [0] 同构，差别只有名表：

```
08081784: ldr      r2, [pc, #0x78]   ; 0x085A7E8C  强化素材名表（16 条）
08081788: ldrh     r0, [r7, #6]
080817a6: bl       #0x808fca0        ; 另一张计数/上限表
```
> 0x599634 / 0x5A7E8C 两个字面量分别在 `0x080816BC` / `0x08081800`，
> 可直接 grep ROM 字节复核。

### 3.3 [2] `0x0808180C` — 专属修行卷轴

```
0808184a: ldr      r1, [pc, #0x88]   ; 0x02022E30 队伍/修行表（步长 0xBC）
0808184e: adds     r0, r1, #0 ; adds r0, #0xbc
08081850: ldrb     r0, [r0, #4]      ; 队伍项 +4 = 角色 ID
08081852: ldrh     r2, [r7, #6]      ; target = 角色 id
08081854: cmp      r0, r2            ; 找同号人物（r6 从 2 扫到 0x17）
08081874: ldrh     r0, [r7, #6]
08081876: bl       #0x806d5f8        ; **解锁该角色的专属修行**（返回修行槽号）
08081880: ldr      r0, [pc]          ; 0x08001671 剧情脚本入口
08081882: bl       #0x8067158
08081886: ldr      r1, [pc, #0x54]   ; 0x08599280 人物名表
080818ae: ldrb     r0, [r4]          ; 队伍项 +0x54+槽*4 = 修行技能 id
080818b2: ldr      r0, [r0]          ; 0x085A7060[技能id*4] = 修行名文本
080818be: bl       #0x8066758        ; 打印修行名
```

`0x0806D5F8(char_id)` 的解锁动作（**可判死**）：

```
0806d620: adds     r0, #0x54         ; 队伍项的修行槽数组
0806d622: ldrb     r0, [r0]
0806d624: cmp      r0, #0x17
0806d626: bls      #0x806d634        ; 已解锁 → 跳过
0806d62c: strb     r5, [r0]         ; 清 +0x55 处的"未解锁"字节（写 0 = 解锁）
0806d64c: bl       #0x8068e80       ; 顺带置"人物已遭遇"位（0x020240B4 表）
```
`0x08068E80` 置的是 `0x020240B4 + (id>>5)*4` 的第 `id&31` 位，
与认识卡判定用的 `0x020240AC` **不是同一张表**（别混）。

### 3.4 [3] `0x080818E4` — 认识卡

```
080818f4: ldr      r0, [pc, #0x70]   ; 0x085461C4
0808192e: ldr      r1, [pc, #0x4c]   ; 0x08599280 人物名表（62 条）
08081930: ldrh     r0, [r7, #6]      ; target = 人物 id
08081934: lsls     r0, r0, #2
08081936: ldr      r0, [r0]
08081940: bl       #0x8066758        ; 打印人物名
0808194a: ldrb     r0, [r7, #6]
0808194c: bl       #0x8068e5c        ; 置"人物已遭遇"位
```

### 3.5 [4][5][6] `0x08081984` — 机关 / 剧情物件（共用一支）

```
08081984: ldrh     r0, [r7, #6]      ; target
08081986: cmp      r0, #9
08081988: beq      #0x0808198c       ; **target == 9 → 计数分支**
0808198a: b        #0x08081a8c       ; 否则 → 通用分支
```

**(a) target == 9：甘薯计数分支**

```
080819b8: ldr      r7, [pc, #0x68]   ; 0x0202680C
080819c4: movs     r0, #0xed ; lsls r0, #2   ; 948
080819c8: adds     r5, r7, r0        ; 计数区 0x02026BC0
080819ca: adds     r1, r1, r5        ; 按单位标志 bit0 选 0x02026BC0 / 0x02026BC1
080819cc: ldrb     r0, [r1] ; adds r0,#1 ; strb r0,[r1]   ; 计数 +1
080819da: ldr      r1, [pc, #0x4c]   ; 0x0200A88C
080819dc: ldrb     r0, [r5]
080819de: str      r0, [r1]          ; 计数存到 0x0200A88C
08081a06: adds     r1, r4, #0 ; adds r1, #0xce
08081a0a: ldrh     r0, [r1] ; adds r0, #0x19 ; strh r0, [r1]   ; 单位 +0xCE += 25
```
→ **target 9 = 收集计数型**：计数器 +1、单位的一个 u16 字段 +25。
第三方叫它"甘薯（收集计数）"。
（2026-10-20 补：该分支还会跑两段**剧情 VM 脚本** `0x080016C3` /
`0x08001725`；但**不跑**效果表那 13 套里的任何一条原版关卡脚本，
因为该分支内没有 `bl 0x0808A638`。详见 §4.1(a)。）

**(b) 通用分支 `0x08081A8C`**

```
08081ade: ldrb     r0, [r7, #6]
08081ae0: bl       #0x80812dc        ; **13 项效果表**
08081ae4: ldrh     r0, [r7, #6]
08081ae6: cmp      r0, #3 ; beq ...
08081aea: cmp      r0, #6 ; bne #0x08081b60    ; 只有 target 3 / 6 继续
08081af2: …        ; 扫 12 个单位槽 (0x020240C0 + n*468)
08081b08: ldrb     r0, [r0]          ; 单位 +0xBC
08081b0a: cmp      r0, #0x23         ; == 35 的单位
08081b1c: bl       #0x806c204        ; 单位槽操作(slot, 0x3F, 0, 0)
08081b24: bl       #0x806a8c0        ; 单位槽操作(slot, 0x30)
08081b32: movs     r0, #0x87 ; bl #0x8061e6c   ; 音效 0x87
```
→ **target 3 / 6 = "停止傀儡的机关"**：除跑效果脚本外，还对全场
`单位+0xBC == 0x23` 的单位做槽操作（0x806C204 / 0x806A8C0）。
⚠️ 这两个函数的精确语义（删除还是冻结）**未证**。

## 4. 13 项机关效果表（表 C，`0x0808136C`）

入口 `0x080812DC`：

```
080812e0: lsls r0,#0x18 ; lsrs r5,r0,#0x18    ; r5 = target
080812e8: bl #0x8064700                      ; 关窗/淡出
08081306..08081328: bl #0x8065404            ; 建消息窗口
08081330..08081344: 算 &config[stage][sub] ; r4 = config[0]
08081346: subs r0, r5, #1
08081348: cmp r0, #0xc ; bls ...             ; target 必须 1..13
0808134e: lsls r0, r0, #2
08081350: ldr r1, [pc, #0x14]                ; = 0x0808136C（表 C）
08081354: ldr r0, [r0]
08081356: mov pc, r0                         ; 跳到效果分支
```

表 C（`0x0808136C`，索引 = target − 1）：

| target | 分支 | 脚本指针 | 脚本首指令 | 第三方命名 | 对上？ |
|---|---|---|---|---|---|
| 1 | `0x080813A0` | `0x080058A4` | `0x36` 指定人物在场（角色 1） | 开门机关 | ✔ 结构相符 |
| 2 | `0x080813B0` | `0x080057F4` / `0x0800584C` | `0x36` ×2 | 空箱 / 开门分支 | ✔ **原生就是两支** |
| 3 | `0x080813E4` | `0x08005E80` | `0x36` | 停止傀儡的机关 | ✔ 见 §3.5(b) |
| 4 | `0x080813F4` | `0x08005E28` | `0x36` | 开门机关（另一组） | ✔ 与 1 同形不同脚本 |
| 5 | `0x08081404` | `0x08005D78` / `0x08005DD0` | `0x36` ×2 | 空箱 / 开门分支（另一组） | ✔ 两支 |
| 6 | `0x08081438` | `0x0800646B` | `0x36` | 停止傀儡的机关（另一组） | ✔ 与 3 同形 |
| 7 | `0x08081448` | `0x08006413` | `0x36` | 密书 | ✔ 结构相符 |
| 8 | `0x08081458` | `0x08006363` / `0x080063BB` | `0x36` ×2 | 空箱 / 密书分支 | ✔ 两支 |
| 9 | `0x080814CC` | — | — | 甘薯（收集计数） | ✔ **被 `0x08081986` 拦截，表项是死代码**；真正的实现是 §3.5(a) 的计数分支 |
| 10 | `0x080814C0` | `0x08006B24` | `0x02` 头像/对话框 | 发现奖励（强化剂剧情） | ✔ 对话脚本 |
| 11 | `0x080814CC` | — | — | 空事件 | ✔ 原生就是空操作（通用端点） |
| 12 | `0x08081498` | `0x0800699C` | `0x12` 场景对象操作 | 宝箱教学 | ✔ |
| 13 | `0x080814A8` | `0x08006A1E` | `0x12` 场景对象操作 | 认识卡教学 | ✔ |

每个效果的收尾都一样：

```
080814ae: adds     r2, r4, #0        ; r2 = config[0]
080814b0: bl       #0x808a638        ; 执行原版关卡脚本
080814b4: b        #0x080814cc
```
`r0` = `byte[0x02026805]`（= 当前 battle_stage），`r1` = 上表的脚本指针。

**"空箱 / 开门分支" 的原生实现（可判死）**：target 2/5/8 的分支里有一个
**计数字节**，第一次拾取走一个脚本、之后走另一个脚本：

```
080813b0: ldr      r0, [pc, #0x14]   ; 0x0202680C
080813b2: movs     r1, #0xee ; lsls r1, #2   ; 952
080813b6: adds     r5, r0, r1        ; 计数字节 0x02026BC4
080813b8: ldrb     r0, [r5]
080813ba: cmp      r0, #0
080813bc: bne      #0x080813d4       ; 非 0 → 走第二个脚本（0x0800584C）
080813be: b        #0x0808146c       ; 为 0 → 走第一个脚本（0x080057F4）
...
0808146c: adds     r2, r4, #0
0808146e: bl       #0x808a638
08081472: ldrb     r0, [r5]
08081474: adds     r0, #1
08081476: strb     r0, [r5]          ; 计数 +1
```
→ 第三方"空箱 / 开门分支"的命名**直接对应原生代码的两条路径**。

**脚本内容**：这些脚本是剧情/关卡 **logic VM 字节码**（见 `notes/story-script-vm.md`）。
例如 target 1 的脚本 `0x080058A4`：

```
36 00 00 01 | C4 58 00 08 | 36 00 00 02 …
^ op 0x36 = 指定人物在场：a=0, 阵营=0, 角色ID=1, 指针=0x080058C4
```
→ **机关效果本身是"指定某角色在场时触发什么"的脚本**，与第三方
"效果依赖原关卡，不能当通用道具搬走"的说明完全一致。

### 4.1 target 9 / target 11 / type 5-6-7 的裁决（2026-10-20 补）

地址级证据见 `notes/evidence/mechanism-sprite-background-20261020.md` §1。
要点：

**（a）target 9 永远进不了效果表。**
`0x080812DC` 这个 13 路分派器**全 ROM 只有一个 `bl` 调用点** `0x08081AE0`，
而表基址 `0x0808136C` 作为字面量**全 ROM 只被引用 1 次**（`0x08081368`）。
唯一的调用点在拾取处理程序 `0x08081984` 里，而它先做：

```
08081984: ldrh     r0, [r7, #6]    ; target
08081986: cmp      r0, #9
08081988: beq      #0x0808198c     ; ← 计数分支
0808198a: b        #0x08081a8c     ; ← 其余 target 才去效果表
```

⇒ 效果表第 9 项（`0x0808138C` → `0x080814CC`）是**不可达的死代码**。

计数分支 `0x0808198C..0x08081A6A` 里**全部** `bl` 目标为
`0x08061E5C / 0x08061E6C / 0x08061E88 / 0x08067158 / 0x08081084 / 0x080814FC`，
**没有 `0x0808A638`** ⇒ 它**不跑**效果表那 13 套里的任何一条原版关卡脚本；
它跑的是两段**剧情 VM 脚本**（`0x080016C3` 首字节 `0x01` = 文本、
`0x08001725` 首字节 `0x04`），外加计数 +1（`0x02026BC0/1`）与单位 `+0xCE += 25`。

**（b）target 11 = 通用空操作端点。**
`0x08081394` 里存的就是 `0x080814CC`，即所有效果共用的收尾
（关窗 → 播 `config[0]` BGM → 等按键），**不含** `bl 0x0808A638`，
所以 target 11 **不触发任何原版关卡脚本**。
原版 46 个战场里 target 11 **一次都没被使用**。

**（c）type 5/6/7 不各自绑定关卡脚本。**
拾取分派表 `0x080815E4` 的 `[4] [5] [6]` **三项都是 `0x08081984`**；
建立期分派 `0x0806E868` 决定的是**运行时物件类型**：

| 记录 type | 建立期分支 | 运行时类型 | 拾取音效（`0x080814FC`） |
|---|---|---|---|
| 5 机关宝箱 | `0x0806E8E4` | 3 | `0x6B` |
| 6 特殊机关 | `0x0806E8F8` | 4 | `0x6A` |
| 7 剧情物件 | `0x0806E90C` | 5（target≠9）/ 6（target==9） | 无 / `0x75` |

⇒ **关卡脚本完全由 target 决定**（见 §4 的表）；
type 只决定地图上物件的外观与拾取音效。
原版实际组合：type 5 → target 1..8/12/13；type 7 → target 9（计数）与 10（对话）；
type 6 → 0 条。

## 5. 13 种命名 ↔ 原生结构的对应结论

**对上的（结构可验证）**

1. 13 这个数字是**原生**的：`0x0808136C` 就是 13 项（`cmp #0xc` 卡死上限 13）。
2. 第三方把机关挂在 **type 5/6/7 的 target 上**（`features.js` 的
   `objectChoices` 对 type 5/6/7 返回 13 个名字），与原生
   "type 5/6/7 → 同一个 handler → target 选效果" 完全一致。
3. "空箱 / X 分支"（2、5、8）**原生就是两条路径**（计数字节分流）。
4. "停止傀儡的机关"（3、6）**原生额外扫全场单位**（`+0xBC == 0x23`）。
5. "密书"（7）、"发现奖励"（10）、"宝箱教学"（12）、"认识卡教学"（13）
   分别是"在场条件脚本"、"对话脚本"、"场景对象操作脚本"。

**对不上 / 需要修正的**

6. **"13 种机关"不是 13 个拾取处理程序**：原生拾取处理程序只有 7 个，
   而且 5/6/7 三种 type **共用同一个** `0x08081984`。
7. **target 9 在原生里不走效果表**：handler 先拦下 target==9 走计数分支，
   表 C 的第 9 项是空操作。第三方"甘薯（收集计数）"这个名字是对的，
   但它的实现不在 13 项效果表里。
8. **target 11 = 空事件**：原生表 C 第 11 项确实指向出口 `0x080814CC`（空操作），
   第三方命名与原生一致。
9. **"开门"无法从静态证据证实**：target 1/4 的脚本第一条是"角色 1 在场"，
   之后是分支指针，具体是不是开门要看脚本内容 —— 属于**推测**。
10. **type 6「特殊机关（卷轴外观）」在原版 46 战场里一次都没出现**
    （实测 count = 0），它是编辑器可写但原版未用的槽位。

## 9. 复现

```powershell
$env:LIBCAPSTONE_PATH = 'D:\Shell\Github\gba-naruto\build\python-deps\capstone\capstone\lib'
python tools\mechanism_map.py rom\base.gba --stats          # 全量报告
python tools\mechanism_map.py rom\base.gba --json build\mechanism_map.json
python tools\mechanism_map.py rom\base.gba --stage 1 --sub 0 # 单个战场的物件清单
python tools\mechanism_map.py rom\base.gba --disasm 0x08081984 --count 60
python tools\mechanism_map.py rom\base.gba --callers 0x08081024
python tools\mechanism_map.py rom\base.gba --verify          # 机械复核 target 9/11 等 5 项断言
```

工具要点：
* `capstone` 通过 `LIBCAPSTONE_PATH` 加载；工具会自动在
  `build/python-deps/**/capstone.dll` 里找并设置该变量，找不到才报错。
* 建立期分派与效果表的结论都是 **CFG 走查**（基本块级）得出的，
  不是线性反汇编 —— 那几段代码是互相穿插的，线性扫会串分支。
* 所有字面量（`ldr rX,[pc,#imm]`）都解析成实际值并标注
  ROM / WRAM / 常量，便于逐条复核。
* 输出文件一律 LF（`tools/lib/io.write_text`）。
