# 木叶战记 GBA 续作的逆向进度与工作方向

评估日期：2026-10-11。

**项目已经积累了足以启动原创章节纵切的逆向成果，当前阶段应转向成果整合、内容生产和完整游戏流程验收。** 全 ROM 逆向仍未完成，但将所有未知字节归零作为续作开发的统一前置条件，已经不能很好地反映下一步投入的价值。

这项判断以最终运行于 GBA 的续作为目标。建议以现有 Butano 工程承载新内容，按章节需求补充原作规则和资源证据。Butano 同样生成 GBA ROM；是否沿用原作引擎与是否面向 GBA，是两个不同选择。若坚持直接扩展原 ROM，地图重定位后的自然运行、章节索引扩展和原作存档兼容需要更高优先级。

## 已经能支撑续作的成果

**内容与战斗规则已经有实质基础。** 单位、主动动作、忍具、成长、状态、伤害、反应、目标、AI、章节流程和存档均有既有记录与实现入口。已生成内容包含 63 个单位模板、87 个主动动作和 94 个忍具。它们应接入现有 loader、controller、resolver、AI、presentation、campaign 和生成器，继续使用原有架构。

**资源提取已具规模。** 逆向提交态的角色视觉 manifest 含 62 个视觉角色、250 个资源、2,004 个去重源空间帧，源空间帧静态验证为 2,004/2,004。63 个单位模板与 62 个视觉角色是不同分母；帧数也不证明所有屏幕构图、相机、混合效果与逐技能演出完整。

**资源修改已有真正的构建闭环。** 10 月 2 日地图候选覆盖 166 个去重内容、217 个物理槽与 249 个引用。四个固定批次通过真实构建和完整重读，包含 96 个原槽容量不足的变异资源迁移；输出为 16 MiB ROM，另五类负例拒绝发布。该工作只证明固定批次、空 fixture 父分配账本和对齐指针分母，尚未证明修改地图的自然游戏运行，也不是完整项目的可重复发布。

**现有二进制具有可信的单关玩家流程证据。** `artifacts/butano-battle-s49-complete-ui-runtime-20260730-363/` 记录战前准备、战斗、胜利、结算、升级、新术摘要、保存并进入 S50。JSON 显示 round 9、五敌击倒、任务友军存活、125+100=225 EXP、保存验证成功，控制器与玩家错误均为 0。

本次独立计算当前 `butano-sequel/butano-sequel.gba` 与该历史 `runtime.gba`，二者 SHA-256 均为 `785757697b9d0e4b657c644ccf38fbca289afa93fca30b1301f7f2c4ae2f5e26`。这证明当前二进制身份一致；没有证明当前源码可以重建它。该收据运行静音，且相关源码、说明和 artifact 仍有未提交部分，不能宣布音频验收或稳定发布完成。

## 当前最影响续作推进的缺口

1. **成果与可复现版本脱节。** Butano 已提交 `main.cpp` 只进入 S41，当前候选已接入 campaign、SRAM、准备和结算。大量工作有价值，但复用和交付必须冻结为可复验的来源闭包，不能依赖另一工作树或散落的实验文件。
2. **原创内容生产尚缺完整示范。** 复建原作 S49 已证明系统可运行；还需要证明新增章节定义、地图和对白可以经现有生成链进入游戏，并走到结算与下一章，避免每章新增专用逻辑。
3. **玩家连续流程仍有边界。** 当前默认入口是 S49，早于它的存档会被入口策略排除；九段 route 表不等于新游戏九关均可玩。进入 S50 不等于 S50 通关；complete 分支目前只持续 core update，完整章节结束交互仍待设计和验收。
4. **发布质量没有统一验收面。** 声音开启后的完整路线、资源与帧时预算、坏存档与版本迁移、失败重试、冷启动续玩、实体 GBA，需要围绕同一版本集中验证。

## 推荐顺序

| 里程碑 | 工作内容 | 玩家或作者能验证的结果 |
| --- | --- | --- |
| M0 固定可复现基线 | 收束 S49 候选的源码、生成输入、逆向来源 commit、工具链、测试与运行收据；审查已有改动后再按单独授权提交 | 在新目录按文档生成 GBA ROM，完成战斗、结算、保存并冷启动续玩；明确默认入口、结束页与错误反馈 |
| M1 原创章节纵切 | 做一章约 10–15 分钟的原创任务：一张地图、现有队伍和少量已支持技能、战前后剧情；新增机制最多一项 | 从新游戏进入原创任务，至少两种合法战术能胜利；失败可重试且不推进；胜利结算、保存并进入下一章入口 |
| M2 补齐该章节的逆向缺口 | 按实际内容需求闭合地图碰撞、脚本触发、目标、技能和资源消费；原 ROM 路线优先做地图迁移后的自然 A/B | 修改一项内容后，构建产物和游戏行为按预期改变；缺资源、非法指令、容量不足明确拒绝且不发布损坏产物 |
| M3 形成可交付版本 | 对同一固定 ROM 做非静音完整流程、跨关生命周期、存档恢复与真机 smoke | 玩家可连续完成该章、听到正确音频，重启后进度一致；实体硬件证据另行验收 |

M1 和 M2 是同一章节的迭代闭环：遇到必要缺口先补证据，再继续内容集成。不要为了等 M2 全部完成而再次扩大成全 ROM 预先逆向。

本次建议与旧“逆向全部完成再生产内容”的执行顺序不同，原因是现有可玩与资源成果已经显著改变了条件。此处提出的是目标导向的工作建议，**不改写严格 100% 证明政策，也不把候选自动晋升到正式账本**。完整网页编辑器仍可后置；先用已有内容文件和生成器验证作者工作流。

## 下一轮逆向应如何选择

优先调查新章节实际要使用、且缺失会阻断玩家体验的机制。近期最接近闭环的是地图：集中复验 map41 两类自然视觉旧证据、47×9 字段分母、快照恢复与零输入对照，再做新迁移的自然运行验证。若选择 Butano 主线，直接验证抽取地图、碰撞和相关资源在 Butano 中的行为；原引擎分配器的全域证明不应成为所有 Butano 内容的前置条件。

按需推进动画 flags、slot、callback、counter 生命周期，以及 AI 配置索引、单位池复制与继承。它们有真实机制价值，但只有当首章实际需要或已经出现行为差异时，才进入关键路径。未闭合状态保持未知，不能用局部 may-read 或单样本填满证明矩阵。

可暂缓与首章无关的短洞清零、原作所有关卡完全等价、所有动作逐帧复刻、完整旧运行时调度器复原和大型网页编辑器。本次排名重算中，17 个大段占未知字节 42,880 B，约 48.9%；1,349 个不足 16 B 的小段只占 5,465 B，约 6.2%。即使单独保留字节线，也应按消费者和共同依赖成组推进，避免靠大量小包获得微小百分比提升。

后续每个工作包应回答：它解锁哪个玩家操作或作者能力、复用哪条已有链、什么测试和运行结果算完成、何种结果需要停止调查。建议同时记录内容闭环数、代表性玩法通过数、稳定构建和运行状态；字节覆盖率继续作为独立研究指标。

## 复用与任务模式

1. 覆盖盘点直接复用登记表中的“固定覆盖账本的只读缺口聚类与证据依赖规划”，运行既有 `analyze_rom_unknown_clusters.py`；不另建 canonical 或评分体系。
2. 产品侧只读核查与覆盖账本独立，交由一个只读子代理审查已有入口与运行收据。脚本能提取计数和哈希，但不能独立裁决玩家流程就绪度；当前 collaboration schema 没有 GPT-5.6 Luna 或 Terra，未声称调用它们，使用可用的继承模型。主代理独立复查入口、运行 JSON 与 ROM 哈希。
3. 后续能力追加到既有导入、构建、战斗和存档链。只在既有合同无法表达明确的新能力时抽取共用组件；本次没有发现另建一套战斗、章节运行时或 allocator 的必要。
