# 对话字体全量图集导出（2026-07-29）

## 结论

熊组汉化版 base ROM 的两条对话字形查找链已静态全量导出并由独立验证器
逐字节复核：

- SJIS 表：`0x0853D644`，26×8 字节，4410 个逻辑字形。
- 单字节表：`0x0853D73C`，2×8 字节，192 个逻辑字形。
- 合计：4602 个逻辑字形、4602 个唯一源记录、9012 个物理 8×8 半字形，
  无地址别名。
- 章节开场已有的 517 条 SJIS 映射全部重新按 ROM 表公式核对通过。
- group0 的 20 个双字节码全部落在同一 SJIS 表中，并已绑定源地址与源记录
  哈希；其中 19 个保留历史截图 OCR 字符标签，`0x8B62` 的字符语义仍未确认。

成果位于 `artifacts/dialogue-font-v2/`，包含四张诊断图集、原始 2bpp
二进制、按 `0x080894A8/0x080894DE` cache 调用参数展开的 4bpp 诊断二进制以及完整 manifest。
该展开不是所有 consumer 的唯一 palette group；例如世界地图使用 `arg1=0`。
导出器为
`tools/export_dialogue_font_atlases.py`，独立验证器为
`tools/verify_dialogue_font_atlases.py`。

## 被纠正的错误假设

第一版曾把 `0x53D644` 的每个 32 字节记录直接解释成单个 8×8 4bpp
字形。图集视觉检查显示其为噪点，随后对 Thumb 消费链复核，确认该解释
错误；未把错误的 v1 图集保留为成果。

2026-07-29 的第二次消费者审计又纠正了 v2 初版的“源记录固有为 16×8 水平字形”
结论。`0x08065F84` 写入的是调用者提供的临时 tile-ID pair，不是最终 tilemap；
`0x0808942C` 只是始于 `0x08089310` 的 enclosing function 内部 basic block；
该路径只展开/缓存两块 tile，同样不决定屏幕几何。正确格式如下：

- SJIS 源记录：32 字节 packed 2bpp，由两个有序的 16 字节、8×8 half-tile
  组成；源记录本身不定义左右或上下布局。
- 单字节源记录：16 字节 packed 2bpp，几何为 8×8。
- 每个源字节按低位优先拆分：
  `bits 1:0, 3:2, 5:4, 7:6`。
- 运行时 4bpp 输出索引：
  `source_2bpp + (((arg1 & 1) + 2) << 2)`。
- `0x080894DE` 的 cache 调用对 SJIS 传 `arg1=1`，输出索引 12-15；
  对单字节分支传 `arg1=0`，输出索引 8-11。
- 已枚举的三个最终 tilemap consumer `0x0806626C`、`0x0808CE8C` 和
  `0x0808CF08` 都把 half 0 写入当前行、half 1 写入下一行，水平前进一格，
  因而实际字形布局为 8×16。

代码证据：

- `0x08065E80`：26 项 SJIS 表查找。
- `0x08065EB8`：SJIS 2bpp→4bpp 展开。
- `0x08065F84`：向临时 pair 返回两个有序 tile ID。
- `0x0806606C`：2 项单字节表查找。
- `0x080660A4`：单字节 2bpp→4bpp 展开。
- `0x08066302..0x080663A5`：通用文本 parser 的 8×16 垂直 tilemap 排布。
- `0x0808CE8C..0x0808CF07`、`0x0808CF08..0x0808CFA9`：另外两个
  8×16 垂直 consumer。
- `0x08089310`：enclosing function；其中 `0x080894A8` 和 `0x080894DE`
  分别调用单字节/SJIS 展开器，`0x0808942C` 只是内部 cache-path 锚点。

因此 v2 中两张 SJIS 组合图集按已证明消费者的垂直布局重新生成；
`sjis-full-source-2bpp.bin`、`chapter-intro-used-source-2bpp.bin`、全部
half-tile 与展开后的 4bpp 二进制均保持逐字节不变。

## 汉化字形的静态身份

base ROM 不是未修改的日版 ROM。CP932 只描述文本码位的名义字符；熊组已在
同一张字形表中替换像素。例如：

| SJIS | CP932 名义字符 | ROM 源地址 | 实际像素字形 |
|---|---|---|---|
| `88CF` | 委 | `0x080A2754` | 什 |
| `8FC2` | 渉 | `0x080ACD94` | 么 |
| `9A6A` | 嗚 | `0x085B1620` | 真 |
| `9B45` | 妣 | `0x085B2920` | 拿 |
| `9298` | 著 | `0x080B1054` | 你 |
| `94C8` | 畔 | `0x080B4654` | 没 |
| `96E2` | 問 | `0x080B7994` | 办 |
| `92D7` | 潰 | `0x080B1834` | 法 |

`0x08065EB8` 从这些地址直接读 packed-2bpp 并写展开后的 VRAM tile，
没有已知或必要的第二层运行时中文字形替换。group0 是文本指针组；其 20 个
双字节码全部复用 `0x53D644`，不是另一套字体。

字符标签和源记录证据必须分层理解：ROM 查表独立证明码位、源地址与像素
记录；19 个字符标签来自历史截图 OCR 对齐。原映射曾把 `0x8B62` 错标成
换行，但原始流实际为 `... 92D7 8B62 0A 95C4 ...`，`0x8B62` 对应非空
  字形记录 `0x080A6194`，随后独立的 `0x0A` 才是换行。现已把 `0x8B62`
  降级为显式未确认项，并由测试与独立验证器解析 41 字节原始流防止回归；
  旧的 `decode_dialogue_record.py` 也改为按 `0x0A` 分段，不再丢弃该字形。

## 表结构与边界

SJIS 表记录为 `<HBBI>`：

| 字段 | 含义 |
|---|---|
| `lower` | SJIS 范围下界 |
| `range_size` | 范围长度 |
| `aux` | entries 0-24 为 0，entry 25 为 4 |
| `source_ptr` | packed-2bpp 源记录基址 |

单字节表记录为 `<BBHI>`。其两段源数据分别为
`0x0809CD54..0x0809D354` 和 `0x0809D354..0x0809D954`；SJIS 首段从
`0x0809D954` 开始，因此三段连续且互不重叠。

## 视觉与范围边界

四张 PNG 使用源索引 0-3 的诊断灰阶，仅用于确认字形排列和像素
可读性；它不是游戏运行时 RGB 调色板，也不声明透明色。视觉检查已确认：

- `byte-full-atlas.png` 可读地显示数字、ASCII、假名和符号。
- `chapter-intro-used-atlas.png` 以 8×16 垂直布局显示章节实际使用的汉化字形。
- `sjis-full-atlas.png` 的标点、ASCII、假名和汉字矩阵连续一致；末行空白
  来自表内全零记录，并非图像截断。

本成果覆盖汉化版 base ROM 的全量静态对话字形及代码可证的 4bpp 展开。
仍不包含：

- 运行时 RGB 调色板；
- 4410 个 SJIS 字形到 Unicode 的完整语义标注（当前只静态绑定 20 条
  源记录，其中 19 条带历史 OCR 标签、1 条显式未确认）；
- 其他 UI/OBJ 消费链可能使用的独立字体。
