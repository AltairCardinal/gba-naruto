# 覆盖层的真正机制：**烘焙布局图 + 加权混合**（第 26 轮，机制闭合）

## 1. 结论（一句话）

原版的移动网格覆盖层 **不是**「一层画着青色的网格」，而是
**一张进入战斗时烘焙好的战场布局图（BG2 的 32×32 tilemap），
以 8×8 像素格为粒度、按 `(BG2 + BG0) × 10/16` 的加权混合叠在地图上**：
其中「族 0」格（本体 = 调色板 index 0 = 黑）**把地图压暗到 62.5%**，
「族 2..10」格**再加上自己的颜色**。

⇒ 「暗化罩」「dither mask」「覆盖层」这三种旧说法**统一为同一件事**：
覆盖层 = 布局图 + 混合（既压暗又上色）。

## 2. 证据

### 2.1 混合参数（第 20 轮已修正 IO 偏移后测得）

| 寄存器 | 值 | 含义 |
| --- | --- | --- |
| `BLDCNT` @0x50 | `0x1744` | effect = alpha；**1st target = BG2**；2nd target = BG0+BG1+BG2+OBJ |
| `BLDALPHA` @0x52 | `0x0A0A` | **EVA = EVB = 10/16** |

⇒ GBA 的 alpha 混合结果 = `(第二目标 × EVA + 第一目标 × EVB) >> 4`
= `(上层 × 10 + 下层 × 10) >> 4` = **`(BG2 + BG0) × 0.625`**。
（这**不是**「半透明覆盖」，而是**加权求和** ⇒ BG2 的黑色格把地图压暗 37.5%。）

### 2.2 BG2 在这一屏上到底画了多少（第 26 轮实测）

原版同帧收据：`BGCNT2 = 0x0202`（屏幕基址 block 2 ⇒ tilemap 在 VRAM `0x06001000`），
滚动寄存器 `bg_hoffs[2] = 240`、`bg_voffs[2] = 24`。

按 GBA 的取模规则换算
（`screen_x = (map_x*8 - hoffs) mod 256`，`screen_y = (map_y*8 - voffs) mod 256`）：

| 收据 | 可见 BG2 格 | 其中**被真正绘制**（图块 ≥ 262） | 非空格屏幕范围 |
| --- | --- | --- | --- |
| `field-frame-v1` | **600 / 1024**（30×20 格） | **322** | x 0..232、y 0..152 |
| `movegrid-frame-v1` | **600 / 1024** | **430** | x 0..232、y 0..152 |

⇒ **原版在整屏范围内都有覆盖层**（不只移动范围那一块）。

### 2.3 像素侧独立验证

基线重制录像 `step-20-A.png` vs 原版 `step-19-A.png`（战场区 240×128）：

| 区域 | 差异像素 |
| --- | --- |
| x 0..111 | **2,068** |
| x 112..239 | 849 |
| 合计 | **2,917**（= 基线） |

⇒ **x < 112 也有差异** ⇒ 原版在那里也在压暗地图 ⇒ 与 §2.2 一致。
（⇒ 顺带否证了代理笔记里「x=0..111 逐像素完全相同」那句。）

## 3. 实现规格（据此推翻前几版方案）

| 步 | 内容 | 与旧方案的区别 |
| --- | --- | --- |
| ① | 覆盖层按 **8×8 像素格**写格（不是 4×2/格点） | 旧：每个 32×16 px 的格点写 4×2 块 |
| ② | 每一格的颜色 = **布局图那一格的图块**（查表，屏幕格 → 布局格的映射：`(col,row) = (((sx+240)//8) mod 32, ((sy+24)//8) mod 32)`） | 旧：用「角色 → 族 → 变体」的规则算 |
| ③ | 图块 = 原版的 **32 块**（4bpp → 展开成 8bpp，像素 = 224 + bank 12 相对索引） | 同旧 |
| ④ | 混合 = **EVA=EVB=10/16**（与原版一致，重制侧**已经**是 10/16） | 旧：想关混合（**已否证**） |
| ⑤ | 覆盖层 = **可见 30×20 格**的布局图切片，随镜头平移 | 旧：整张 32×32 铺满（**已否证**，那正是 13,338 的来源） |

⇒ ⇒ **不再需要任何「选块规则」**：布局图就是答案，规则只用来生成那张图（原版的，逆向侧已拿到）。
⇒ ⇒ **重制侧要做的是「把原版那 30×20 格照抄过来」**。

## 4. 仍然未确立

- 布局图在别的关卡/别的相机位置下怎么取（当前只闭合了 S49 的这一屏）；
- `族 0` 的细网格线在压暗后的实际观感（PNG 与 dump 不自洽的旧问题已被参考渲染器解决：
  从 dump 重建 = PNG 38,400/38,400 一致）。
