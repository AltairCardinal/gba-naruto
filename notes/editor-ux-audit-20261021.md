# 审计：每一项编辑功能的交互流程都迭代过了吗？（2026-10-21 夜）

> 目标原文：**「当前版本非常不直观，检查每一项可编辑内容，为每一项编辑功能用一个单独的
> 子代理去重新设计用户的操作流，然后以此重新进行交互设计，最终将所有编辑功能的交互流程
> 都重新迭代一遍。」**
>
> 这份文件是那个目标的**逐条对照账**。判据只有一条：
> **作者要改某个东西时，第一眼看到的是「改这个东西该怎么做」，而不是「这堆数字是什么」。**

## 1. 审计方法

1. **以内容包为分母**：`tools/editor_inventory.py` 把包里**每一项可编辑内容**
   （40 张结构表 / 11 张文本表 / 原始字节 / 剧情脚本操作数 / 全局流程）摊成清单。
   没在清单里的东西不算「编辑功能」。
2. **以「入口 → 控件 → 反馈」三段为判据**：每一项都要回答
   - 从哪儿进（域首页 / 侧边栏 / 深链）？
   - 改的是什么东西（控件形态对不对）？
   - 改完作者知道什么（标记 / 计数 / 提示 / 撤销）？
3. **每项都要有机器可查的证据**：无头自检的断言，或内容包里的一条元数据。

## 2. 逐项对照

### 2.1 通用编辑能力（40 张结构表 + 11 张文本表共用）

| 能力 | 第一轮的毛病 | 现在的操作流 | 证据 |
|---|---|---|---|
| 进入一张表 | 域首页的表清单是手写白名单，**战斗域 7 张表 + 字宽表根本够不着** | 清单由内容包 `module` 字段推导，本域剩下的表一律追加 | `verify_views` 第 9 组 |
| 看懂一条记录 | 175 个字段摊成 175 行平表 | 按 `field.group` 拆成可折叠分区，默认只展开「基础属性」8 项，折叠标题写明有多少项 | `verify_views` 第 5 组 |
| 看懂重复槽位 | 忍术 15 个槽位是 15 个输入框 | `field.array`+`index`+`item` → 渲染成**一张表** | `verify_views` 第 6 组 |
| 看懂一个取值 | 阵营 0/1、条件类型 1/2/3 全是裸数字 | `field.enum` → 下拉 + 中文标签 | `verify_views` 第 4 组 |
| 看懂一个 id | 忍术 id 显示「37」 | `field.relation` / `structure.id_relation` → 显示**名字**并可点着跳过去，越界明确标出 | `verify_views` 第 5 组 |
| 改一个指针 | 列表 `0x0859F988`、详情十进制框 `140114312`，同一屏两种写法 | 详情也是十六进制框；旁边写「指向什么」；内容包 `derived.pointer_targets` 给出载荷判定 | `verify_views` 第 16 组 |
| 改一个字节 | 无从知道改了会动到谁 | `xref.backReferencesByPointer` 扫全包指针字段反查 | `verify_views` 第 16 组 |
| 改完知道改没改 | 「碰过就算改」 | 「已改」按**字节**判定，改回原值就不算；字段旁有 ↺ 单独恢复 | 既有 |
| 改错了怎么办 | 越界被静默截断（输入 999 写成 231） | 按字段类型当场**拒绝**并回滚 | 既有 |
| 撤销 | 没有撤销 | 撤销栈 100 步 + 顶栏「撤销（N）」+ Ctrl+Z + 字段级 ↺ | 既有 |
| 找一条记录 | 搜不出来（作者照着列表抄地址去搜，命中 0 条） | 搜索同时吃十六进制与十进制写法 | `verify_views` 第 16 组 |
| 表格太大 | 200 行上限是**假的**（476 行全画出来） | 真的只渲染前 200 行，页脚写明「另有 1216 条全零记录已隐藏」 | `verify_views` 第 15 组 |
| 复合下标 | 「第 12 关 · 变体 1 · 槽 3」要自己手算 id | `structure.index_scheme` 分解出可读的键 | `verify_views` 第 15 组 |
| 改一个没用的字节 | 改了原生根本不读的字节，白改 | `field.not_read` → 降级为只读并说明「原生代码不读这一字节」 | `verify_views` 第 15 组 |
| 改一位 | 位域要手算掩码 | `field.bits` → 已知的位给下拉，其余位原样保留并显示出来 | 既有 |
| 找回原文 | 「恢复原文」恢复的是字符串不是字节 | 字节级还原 | 既有 |
| 写回顺序 | 原始字节补丁会被结构化写回**静默覆盖** | 结构 → 文本 → 补丁；补丁最后写且对着当前字节校验，冲突时跳过并点名 | 既有 |
| 表说明 | 说明写在内容包里，界面一个字都看不到 | 说明摆在面板头上 | 既有 |

## 3. 明确没做的（诚实边界）

| 没做 | 为什么 | 什么时候做 |
|---|---|---|
| 音效 id → 代码级使用点（「L3」） | 「函数指针表第 k 槽 = 音效 #k」目前只是**静态推定**：已逐字节证明那 11 条 thunk 的第二条指令是 `movs r0,#k`、全 ROM 只有这 11 条 BL 调用者，但**没有运行时证据**证明 r0 就是音效号 | 下一轮用 `tools/l2_runtime_capture.py` 在 11 个 thunk 上各下一次断点，读 r0 与命中的表项 |
| 资源**载荷**的改写 | 仓库只有纯字面量 LZ77 编码器，没有与原版逐字节一致的压缩器 | 要改画面内容：走「原始字节」按字节改，或把指针接到另一份现成资源上 |
| 「本关剧情脚本里可改的操作数」并进路线工作台 | 战斗域与路线域改的是同一批字节，并进去会让一屏过长 | 下一轮把两处合并成一个「剧情脚本操作数」面板 |
| 掉落位下拉的懒渲染 | 8 位 × 3 个子奖励 ≈ 2300 个 option，现在一次性渲染 | 表变大时再做 |
| 编辑器内通用键盘层（↑↓/Enter/Esc/J/K//） | 路线域自己注册了关卡级按键；通用编辑器层还没统一 | 下一轮统一到 `editors.js` |
