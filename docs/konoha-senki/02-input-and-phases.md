# 原版输入与相位状态机

本文只记录**实测**出来的输入行为。测法固定为：固定入口快照、逐键探测、每键
留截图与快速存档，然后用 `tools/butano/capture_s49_pair.py` 与
`compare_frame_sequences.py` 做同索引全屏比对。

- 入口快照：`artifacts/runtime-checkpoints/scenario-49-battle-14-entry.ss9`
  SHA-256 `a3628723ac595f41b87d329f49d5422a7b9b397a8491379abb8c9620568a0aa1`
- ROM：`rom/base.gba` SHA-256 `1198ece7…`
- SRAM：`rom/base.sav`（**不进存档**，属于输入契约，见 README 铁律 4）

## 一、入口相位是不是「首次可操作」

**是。** 从快照直接录 2,400 帧（40 秒）零输入，全程零次 >3,000 像素的场景切换，
只有选中单位的待机动画在动。没有任何隐藏的对白或部署在等着输入。

> 这条结论推翻了「快照是部署预览、需要先推进对白」的旧说法。该说法在 2026-10-13
> 的笔记里出现过，但那些原始产物已随清理丢失，无法回溯。

## 二、入口相位的按键行为

一次只按一个键，settle 45 帧后再截；长等待用 settle 300/240 帧复核。

| 输入 | 行为 | 证据 |
| --- | --- | --- |
| **A** | 前进到下一个可控单位 | `original-keyprobe-A/` |
| **B** | **与 A 完全相同**（也前进，不是上一个） | `original-keyprobe-B/`、`original-bcycle/` |
| Up/Down/Left/Right | **无语义效果**，只有精灵待机动画变化 | `original-keyprobe-*/` |
| Start/Select | **无语义效果** | 同上 |
| 零输入 | 什么都不发生（2,400 帧验证） | `original-entry-timeline/` |

### 单位循环顺序

固定为 5 个，按 A 依次前进，相机跟随当前单位：

| 次序 | 状态栏 | HP/查克拉 |
| --- | --- | --- |
| 0（起始） | 漩涡鸣人 | 138 / 5 |
| 1 | 宇智波佐助 | 104 / 4 |
| 2 | 春野樱 | 110 / 3 |
| 3 | 木叶丸 | 40 / 2 |
| 4 | **蜜蜂** | 25 / 0 |

到第 4 个之后再按 A/B，状态栏仍是蜜蜂，但画面出现 `[ - ]` 光标并随按随移动——
此时已进入**移动相位**。在移动相位按方向键完全无效，只有 A/B 生效（让蜜蜂移动到
光标处）。

## 三、入口相位不弹命令菜单

这是本轮最重要的负结果。

- 逐键探测（A/B/四方向/Start/Select）都没有出现菜单。
- 长等待 300 帧后仍然没有。
- 连续按 A 共 8 次（两档 settle）从来没有出现菜单。

因此**「原版在入口按 A 会弹五命令菜单」是错的**。2026-10-13 的笔记写过
「step06 选人后五命令」，但那份笔记的原始产物已丢失，本轮用逐字节相同的快照
复现不出来；SRAM 差异、零输入帧数差异两个候选也都已实测排除（见交接文档 4.3.3）。

**影响**：重制在入口相位弹五命令菜单，本身就是分歧，不能当成「绑定反了、
菜单位置正确」。把 A/B 直接改绑到单位循环会让重制和原版一样永远进不去菜单。

## 四、尚未确定
