# Butano 重制版 1:1 保真路线图（2026-10-23 细化版 · 含可行性实测）

**目标**：拿到一份**与原版完全一致**、并且**可进行任意修改**的源码。

**本版与上一版的差别**：上一版是**计划**；本版每一阶段都先跑了
**可行性测试**，用实测的缺口大小推导工时，并给出**能看见成果的节点阶梯**。

**配套**：
- 可行性探针（可复跑）：`tools/butano_feasibility_probe.py`
- 探针收据：`build/butano-feasibility-v1.json`
- 现状盘点：`notes/butano-remake-utilization-audit-20261023.md`
- 本机工具链：`docs/local-toolchain-20261023.md`

## 0. 判定口径（不变）

> 给定**同一输入**（原版存档 + 同一按键序列 + 同一帧预算 + 同一随机种子），
> 重制侧与原版侧必须产生：
> **F1** 逐帧画面完全相同 · **F2** 逐帧音频完全相同 ·
> **F3** 逐帧可观测状态完全相同 · **F4** 存档字节完全相同 ·
> **F5** 边界行为完全相同（含原作 bug）。
>
> 明确不要求：C++ 类结构、成员布局、内存地址一致。
> ⇒ **可观测等价 = 完全一致 ∩ 可任意修改。**

## 1. 可行性实测结果（8 个子系统，逐个测过）

机器可查的五个由 `tools/butano_feasibility_probe.py` 复跑；
三个「逆向侧零成果」的只能人工取证，结论写进 §1.6–1.8。

### 1.1 F1 · 战斗状态机 —— ✅ 形状已在，缺运行时绑定

| 实测项 | 值 |
|---|---|
| 原版状态数 | **38**（`battle_controller_states.json`） |
| 已定名 / 未定名 | **26 / 12**（未定的只留码，不编造语义） |
| 映射表条目 | **24**（`direct` 11 · `sub_phase` 8 · `remake_only` 4 · `candidate` 1） |
| 映射覆盖的原版态 | **21**（去重） |
| **原版有、重制没有** | **17** 个 |
| 运行时实际跑的枚举 | `battle_scene_phase`，**24 值** |
| 生成头 | `battle_original_states.h` ✅ 已生成，带 `reverse-source` 血缘声明 |

**判定**：**可行**，且比预想的好——38 态的**规格层已经建好**（生成头 + 24→38 映射 + 12 个 unknown 只留码）。
**缺的只有「让它驱动运行时」这一层**。

**阻塞**：① 12 个 unknown 态语义未定（10/12 有具体闭合条件）② 17 态重制侧没有对应行为
③ 映射里 9 条只是 `sub_phase`/`candidate` ④ 运行时枚举仍是自造的 24 相。

### 1.2 F2 · 战斗动作系统 —— ⚠️ 形状不同，需重写

| 实测项 | 原版 | 重制侧 |
|---|---|---|
| 分派 id 数 | **60**（`case = (id & 0x3F) - 4`） | **37** |
| 缺失的 id | — | **24 个**（0、9、27、39–59） |
| 多出的 id | — | 1 个（63） |
| 5 个忍术槽（14/15/21/61/62） | 全部存在 | **缺 61、62** |
| 每单位动作表 | **两张 8 字节表**（`unit+0xD4` 源 / `unit+0x154` 生效） | **无对应物** |
| 槽位结构 | 每角色 **5** 个忍术槽 | **15 primary + 24 secondary** |

**判定**：**可行但不是"接线"而是"重写"**。重制侧的 `battle_action_system.h`（82 KB）
是一套**自己设计的动作抽象**，与原版的 60 项分派表**不同形**。
⇒ 这是 1:1 目标的**最大单块形状债**。

### 1.3 F3 · 寻路 / 碰撞 —— ⚠️ 可行，但属**新逆向**

逆向树的 264 个成果族里**没有**寻路/碰撞族（`map-*` 族全是视觉/资源类）。
`butano-sequel/docs/butano-scenario-41-battle.md` 明写：
「原作对这些部分属性的特殊递归处理与 AI 排序**仍需运行时差分闭合**」。

**判定**：**可行，但要从零逆向**。工具已就位（recomp 可执行原版 + 探针可对拍），
但没有现成规格可抄 ⇒ 计入新逆向工时。

### 1.4 F4 · RNG —— ⚠️ 可行，但属**新逆向**

逆向树**零** PRNG 成果（检索 `PRNG/伪随机/随机数/LCG/xorshift` 无命中）。
在 recomp 的 61 MB 生成码里按 LCG 常量模式检索**也没有命中**
（`41C64E6D` / `6C078965` / `3C6EF35F` / `00006073` 全为 0）
——因为生成码是**指令级降级**，不是可读的反编译。

**判定**：**可行**，但路径换一条：recomp 有 `--dump-state`，
⇒ **用「差分法」定位**：同输入跑两次 dump EWRAM，
再跑一次改一个按键的版本，**逐地址 diff** ⇒ 变动的字里就有 RNG 状态。

**已实测的 oracle 前提**（这一条不成立则整条路不通）：

| 项 | 实测 |
|---|---|
| recomp 在本机可跑 | ✅ `FULLY_STATIC dispatch_misses=0 interpreted_insns=0 healed_native=0` |
| 确定性 | ✅ 连跑两次 PNG 的 SHA-256 **逐字节相同**（`A84AA75C…E7BC25`），且与 macOS 参考值一致 |
| BIOS / ROM 身份 | ✅ SHA-1 全部对上（BIOS `300c20df…`、ROM `26f60795…`） |
| 吞吐 | ✅ **747 fps**（2000 帧实测） |

### 1.5 F5 · Butano 渲染底座 —— ⚠️ **三处加法式缺口**（2026-10-23 复核后降级）

> ⚠️ 本节第一版判成「❌ 必须改引擎」。**复核后该判定过重**，已更正。

原版与重制侧的实测用层：

| | 原版 | 重制侧（实测寄存器） |
|---|---|---|
| 地图 | **BG0** | **BG3**（`BGCNT3=0xCC83`：优先级 3、字符基址 `0x00000`、屏幕基址 `0x06000`、8bpp） |
| 覆盖层 | **BG2** | **BG2**（`BGCNT2=0x138A`：优先级 2、字符基址 `0x08000`、屏幕基址 `0x09800`、8bpp） |
| UI | **BG3** | **无第三个 BG**，UI 走 OBJ；BG0/BG1 空闲 |

⇒ 原版用 **3 个** regular BG，重制侧只有 **2 个** —— 这是**渲染路径差异**（原版 UI 是 BG，重制 UI 是精灵），
比"层号不同"更实，会影响 UI 调色板、与单位的优先级、精灵 8×8 限制。

Butano 21.7.1 的 `regular_bg_ptr` 缺三样（重制线 `01-battle-s49.md` 4.3.94.6 自己也列了）：

| # | 缺口 | 核实后的范围 |
|---|---|---|
| 1 | **能指定 BG 层号** | `case 0` 时 regular BG 从 **bg3 往下**分配 ⇒ 拿不到 bg0。**但 3 个 regular BG 装得下**（bg3+bg2+bg1） |
| 2 | **能运行时写 tilemap** | 只有整块 `set_cells_ref` + `reload_cells_ref`，**无逐格写** ⇒ 可行（改数组再重传，每帧 2 KB） |
| 3 | **能 4bpp + 独立调色板 bank** | `bpp_mode::BPP_4` **存在**，`hw::bgs::set_bpp()` **支持逐 BG 位深**；`bg_palette_item` 本就是「16 的倍数个颜色」⇒ **16 色调色板可用**。真正缺的是 **4bpp 图块的打包上传**（Butano 的 tile 是 8bpp 原生，一像素一字节） |

**两处更正（相对第一版判定）**：

1. **BG 层号不影响像素，只影响寄存器。** GBA mode 0 的分层由 **priority** 决定，
   字符基址/屏幕基址都可配。原版 BG0 地图(prio 3) + BG2 覆盖层(prio 2)，
   重制侧 BG3 地图(prio 3) + BG2 覆盖层(prio 2) ⇒ **优先级结构已经等价**。
   经验佐证：重制线自己的残差归因（2,317 + 600）**没有一项归因于 BG 层号**。
   ⇒ 真正被挡的只有「**寄存器逐字段相同**」（`DISPCNT` bit 8 vs bit 11、`BGCNT0` vs `BGCNT3`）。
2. **4bpp 调色板本来支持。** 那句 `BPP_4 palettes are not supported` 断言只在
   **palette bitmap 绘制**路径，重制侧不需要它。

**判定**：**2026-10-23 wave 1 实测后：这一块基本不需要做了。**

| 需求 | 核实结果 |
|---|---|
| 4bpp 图块上传 | ⭐ **不需要** —— 重制侧覆盖层**本来就是 8bpp**（`BGCNT2=0x138A`）；且原版 16 色调色板与重制侧索引 225–235 **逐项 RGB5 完全相同** ⇒ **8bpp 存出来的像素和 4bpp 逐像素一样** |
| VRAM 预算 | tile 区实测峰值 **30,935 / 65,536** ⇒ **空余 34,601 B**；覆盖层 char base `0x8000` 槽空余 11,086 B；8bpp 多占的 1,024 B 吃不完 |
| 逐格写 tilemap | 不需要（现状已能逐帧写） |
| 调色板 bank 指定 | ⭐ **wave 2 F 流查实 ⇒ 伪需求** —— GBA 的 BG 在 **8bpp 模式下只有一块 256 色调色板**，原版 bank 12 的 11 个已占用槽位（1–11）= 重制侧 **225–235**、**逐项 RGB5 相同**（角色已被完整承担）⇒ 只要地图背景**不占用 224–239**，输出像素就等价；**不需要改引擎也不需要改调色板内容** |
| BG 层号可指定 | **不需要**（2026-10-23 用户决定：**寄存器不关心**） |

⇒ **F5 从「必须改引擎」降为「零引擎改动」**；
**2026-10-24（wave 2 F 流）再降一档**：「覆盖层调色板改独立 bank」判为**伪需求**
（8bpp 下 BG 只有一块 256 色调色板，原版 bank 12 的角色已被重制侧 225–235 完整承担），
⇒ **F5 的真实剩余只有「UI 改走第三个 regular BG」一项接线活**。

> **但原版用 3 个 regular BG、重制侧只有 2 个**这一条，是真实存在的形状债：
> 1:1 复刻 UI 需要给重制侧加第三个 regular BG（bg1 可用）。

### 1.6 F6 · 音频 —— ⚠️ 功能等价已有，逐采样需重做

重制侧用 **Maxmod**（`AUDIOBACKEND := maxmod`），
原版用 **MP2K**（GBA 上的软件 PSG 合成器）+ DirectSound。
既有文档自己写着：「音频仍按原 PCM、事件和切换顺序做 Maxmod 功能等价，
**不要求 MP2K 逐采样一致**」。

**判定**：**功能等价已在**；**逐采样等价要绕开 Maxmod、在 Butano 里复现 MP2K 合成器**
（PSG 波形 + 包络 + 混音）⇒ 可行，但工作量集中且**不确定性最高**（唯一"不知道要写多少行"的一块）。

> **2026-10-24 wave 2（J 流）实测补记**：
> * **事件级**这一档已经在本机跑出对照仪器（`tools/s49_audio_probe/`，两次全流程逐字节一致）。
> * 事件级对照暴露出**三个真实缺陷**，且**都不是素材问题**：
>   战斗 BGM **ID 错**（原版 sound **10**，重制侧 sound **14** = S41 的战斗曲）、
>   12 个音效 cue **全静音**（`play_battle_sound()` 是 `(void) cue;`）、
>   cue 8 无调用点 / 146·152 连资产都没有。
> * ⭐ **两侧共有的 17 个 cue 时长差全部 0.000 s**（PCM_RATE = 15768）
>   ⇒ **坏的是接线，不是素材**；原版这场仗会响的 9 个 cue，重制侧「ID 正确且能出声」= **0 个**。
> * ⇒ **逐采样一致依然排除**（80–120 h，超出 72 h 窗口）；**事件级一致可在 72 h 内收口**。

## 3. 可见成果节点阶梯

**每一个节点都能"看见"**——不是百分比，是可以打开的产物或可以看的一帧。

| 节点 | 成果（看得见的东西） | 累计 h | 累计天(16h) |

**排序理由**（不是按工作量大小排，是按"解锁下游多少"排）：

* **V0→V1** 先把尺子建好。尺子没建好之前改的任何代码都无法判定对错
  （本项目的教训：20+ 条自我推翻几乎全部出自"边改边猜"）。
* **V2→V4** 是三块**形状债**，它们不解决，**后面每一场都在错的骨架上**。
* **V5** 插在 P2 之前——因为 **BG 层位次和 4bpp 是 P2 的前置**：
  原版的覆盖层是 BG2 + 4bpp，Butano 现在给不了 ⇒ 不改引擎就谈不上 1:1 覆盖层。
* **V6** 是第一个**肉眼可验证**的成果（像素归零）。
* **V7** 独立于画面：音频是另一条"完全一致"的轴，且**工作量最大**，早启动可以与 P2 并行。
* **V8** 之前不要铺量：单场 1:1 的模板没立住，铺 47 场就是铺 47 份返工。

## 4. 执行顺序与并行

```
V0 ✅ 工具链（已完成）
 └─► V1 对拍台 ──► V2 状态机 ──┐
                    V3 动作系统 ├──► V5 引擎改造 ──► V6 S49 归零 ──► V8 S41 样板 ──► V9 47 场
                    V4 寻路+RNG ┘        │
                                          └──► V7 音频（可与 V6 并行）      └─► V10 可改写性
```

* **V2/V3/V4 三块形状债互不依赖 ⇒ 可三线并行。**
* **V7 音频与 V6 渲染互不依赖 ⇒ 可并行。**
* **V5 引擎改造必须早于 V6**，且**早于任何"覆盖层 1:1"的尝试**
  （本项目已经在这上面失败过一次：第 26 轮施工把残差从 2,917 推到 16,533，已回滚）。
* **V9 铺量必须晚于 V8**：单场模板没立住就铺 47 场 = 铺 47 份返工。
