# 如何判断逆向工程是否已经全部完成

> 本文回答一个具体问题：**什么时候可以宣称"逆向已完成"**。
> 结论先行：**"逆向完成"不是一个 ROM 的客观属性，而是相对于「已声明范围」的、
> 可机器复核的断言。** 判断它成立，看三件事——
> ① 范围是否写死并可枚举；② 每一项是否有**独立证据**（不是"看起来合理"）；
> ③ 结论是否带**明确的边界**（明确不宣称什么）。
>
> 权威审计数据：`notes/completion-audit-20261020.md`（由 `tools/completion_audit.py` 生成）。
> 证据分级：`notes/runtime-verification-gates-20260710.md` §四级证据分级。
> 方法论来源：`notes/re-methodology-improvements-20261020.md`。

---

## 1. 先排除五种"假完成"（本项目都真实踩过）

| 假完成 | 为什么是假的 | 本项目的实例 |
|---|---|---|
| **元数据齐全** | 偏移 / 格式描述 / 条目数 / 文档引用 / 基准 ROM 字节一致 —— 全都齐了，也不代表这个结构被证明了 | 2026-07-11 审计得出 "32/32 完整"，但它自己在开头就写着 *"no runtime or write-back validation ... cannot prove runtime semantics"*。判据错了，不是数据错了 |
| **工具跑通** | 读写器彼此自洽，只证明"我们的格式假设没自相矛盾" | 合成夹具往返证明的是**格式**，不是"游戏如何使用该字段"。按四级分级只能记 **L1**，不能升 L2/L3 |
| **构建成功** | 补丁能写进 ROM ≠ 游戏读它时会按预期行为 | `tools/build_mod.py` 跑通、`change_radius.undeclared_change_count=0`，都不构成语义证据 |
| **全局门禁** | 把"全量逆向"当前置条件，会直接阻塞交付 | 2026-10-20 策略被推翻：对方在**未完成全量逆向**的前提下用「复制原生条目 + 只改已知字段 + hook 原生函数」产出了可用编辑器和 26 场可玩 DEMO；本项目走了 3.5 个月 / 105 次提交 / 32 结构全量静态入库，**可玩新内容为 0**（`notes/why-external-editor-shipped-20261020.md`）|
| **反向证明被当正证据** | 「基址在整个 ROM 里零引用」证明的是**基址无效**（身份问题关闭），不是格式被证明 | 12 个 legacy 基址：`notatable` 探针通过 = 身份已裁决，但格式证明仍为 ❌ |

> 结论：**每种"完成"都必须配一个反例清单**，否则默认会被最廉价的那层（文件存在 / 工具跑通 / 字节一致）冒充。

## 2. 本项目的三层判据

### 2.1 单结构「算完成」的六条（C1–C6）

| 编号 | 条件 | 机器核验方式 |
|---|---|---|
| **C1** | **身份唯一**：结构在 ROM 中有唯一地址；同址冲突必须已裁决（合并为一个结构，或明确拆分） | 地址去重 + `tools/table_registry.py` + `tools/alias_audit.py` |
| **C2** | **格式已证明**：存在一条**可复现**的证明，四选一 —— ①**合成夹具**（写入已知内容 → 用**生产读取器**读回 → 逐字节相等）；②**渲染可视证明**（渲染出来人工可辨，且"错一步就碎"）；③**字节级往返** `encode(decode(x)) == x`；④**原生代码定址**（反汇编里该地址出现在字面量池/立即数，且指令解释了字段） | `tools/completion_audit.py` 的 `fixture` / `render` / `roundtrip` / `codecite` 四类探针 |
| **C3** | **字段语义已知**：每个字段都有名字与含义；未解字段必须**逐条列出**并标"未解"，且写回路径**不碰**这些字节 | 逐结构笔记 + 探针 `need` 标记 + 写回探针的"未知字节原样保留"断言 |
| **C4** | **写回可用**：有写回路径，且有"回读 == 作者输入"的验收；**或**被显式声明为只读参考结构 | `tools/writeback_paths.py`（**真的跑一遍**） |
| **C5** | **有笔记**：地址、字段、证据文件、复现命令在 `notes/` 里有记录 | 笔记探针（文件存在 + 命中该地址） |
| **C6** | **无待裁决冲突**：涉及的所有地址复用 / 别名冲突都已裁决 | `tools/alias_audit.py` |

> **C2 的四类证明，没有一个是"数据看起来合理"。** 泛用提取器（`tools/extract_all_structures.py`）
> 把一段字节 dump 出来，**不构成 C2**。

### 2.2 项目级「逆向 100% 完成」的判据（P1 / P2 / P3）

三条**同时**满足才算 100%：

- **P1** —— 每一个结构都达到 **L1 或以上**（即 C1 / C2 / C3 / C5 全满足），或被显式裁决为"重复项 / 只读项"并记录在案。
  *等价于*：**"无独立证据"的结构数 = 0**。
- **P2** —— 三类**必测面**各至少一个结构达到 **L3（模拟器正常按键复现）**：
  地图与战斗配置、剧情脚本、文本编码。
- **P3** —— **阻塞缺口表清零**：每个结构要么有写回路径，要么被显式标为只读。

> P2 的三类必测面是**按需选定的**，不是"全 ROM 每一处都要动态证明"——
> 这正是 2026-10-20 策略反转后的口径：**全量门禁 → 按需动态证据**。

### 2.3 证据分级（L1–L4）

| 档 | 名称 | 含义 | 本仓库能否这样宣称 |
|---|---|---|---|
| **L1** | 编辑器 / 工具产出通过 | 数据检查、页面检查、导出流程自洽 | ✅ 可 |
| **L2** | 原生判定定点检查 | 断点命中消费者，寄存器/内存与字段对应 | ✅ 可 |
| **L3** | 模拟器正常按键 | 在模拟器里用**正常操作**复现该行为 | ✅ 可 |
| **L4** | 完整通关 | 全流程、全人物组合、全地图实际打通 | ❌ **不可宣称** |

L2 与 L3 是**两条独立的取证路线**（断点定点 / 模拟器按键），所以 **L3 不强制包含 L2**。
新增的**静态结论一律标 L1**，不因"推导严密"而升档。

## 3. 关键：把判断变成一条命令（防止自证）

`tools/completion_audit.py` 的价值不在于生成一张漂亮的表，而在于**四道防自证的闸**：

1. **证据必须是已提交的产物** —— 审计用 `git ls-files` 区分"仓库内持久证据"与"只在本地存在的产物"。
   `build/` 下未被跟踪的探针 JSON / 渲染 PNG **一律不作为证据**。
2. **证据绑定 ROM 指纹** —— `notes/evidence/consumer-evidence.json` 带 ROM 的 SHA-256，
   **换了 ROM 证据自动作废**（审计报 `stale`）。
3. **证据被删/被改，等级自动掉下来** —— 探针失配会让 `--check` **返回退出码 1**，
   可直接接进 CI。这条是"宣称不会随时间悄悄腐化"的技术保证。
4. **写回探针是可执行的** —— 不是 grep 到"写回"两个字就算，而是
   `tools/writeback_paths.py` **真的跑一遍**：回读 == 作者输入 **且** 未知字节原样保留 **且**
   该 case 声明的基址与结构基址交叉核对（一条路径不可能被记到别的表头上）。

> 「codecite」与「notatable」两类探针**按结构基址自动挂上**：
> 新增证据不需要改审计器，改完重新生成证据文件即可。

#### 另一条独立成果：剧情 VM 的「章节交接」链

剧情菜单的作答通道是 **`0x0200A880`（选中行）+ `0x0200A882`（完成标志）**
（旧笔记记的 `0x0200A898` 根本不在作答路径上），
详见 `notes/evidence/menu-answer-channel-20261021.md`：

```
场景 1 → op 0x0B 条件位补写 → 剧情菜单代答 row 1（「认识卡多」0x0800B849）
      → op 0x1A 0x08097C6C：state[0x16]=2, state[0x18]=1
      → 状态机 phase 0x30 的 0x0808F904 读 state[0x18]==1 → phase 0x100
      → phase 0x100 的 0x0808F928 → fn 0x08088F10（章节初始化）
      → 任务面板 fn 0x080884DC（0x080885C0 读同一个作答通道）→ 返回 1
      → r4 == 0x20 → 0x08089008 → bl 0x08075184 → bl 0x0807509C（关卡战斗）
```

**旧结论「`fn 0x0808F654` 是 `state[0x18]==1` 的消费者」作废**：
全 ROM 原始半字扫描（`build/probe_blscan.py`）证明它**没有任何 `bl`、
也没有任何 32 位指针**指向它 —— 它是**死代码**；
真正的消费者是 `0x0808F904`，而状态机 `fn 0x0808F73C` 本身是通过
**函数指针**（`0x0806107C` / `0x080859B4`）被调用的。

#### 第三条：关卡模式也真的进得去了

章节交接链打通后，可以在**关卡战斗设置之前**存一个存状态，
从它继续跑就进入**关卡模式**（`fn 0x0807509C`）。
那里 `fn 0x0806D964`（读全部角色表）、`fn 0x0806E1B4`（编成矩阵）、

`0x0806D9D8`（5 次）、`0x0806E1FE`（12 次）、`0x0806B770`（6 次）。
⇒ `character-stats` / `character-stats-b` / `battle-config` /
`sprite-animations` / `sprite-action-table` 拿到 **L3**。
详见 `notes/evidence/level-mode-l3-20261022.md`。

**顺带发现一张此前没登记的函数指针表 `0x0853ECB0`**：
8 字节/条，6 条 `{0x0807EE51, 0}` + 20 条 `{0x0807EF81, 0}` + `0x0807F1B1` + 终止符。
`fn 0x0807EE50`（**字宽表 `0x0853E596` 的唯一原生读者**）就是靠它被调用的 ——
这解释了它为什么「0 个 `bl` 调用者」，也是 `fonts` 缺口还差的那一步。

## 7. 剩余缺口的推进顺序（从审计表 §"距离 100% 的缺口"取）

阻塞缺口已为 0，剩下的全是**加固缺口**，按解锁价值/难度排序的前几项：

1. **对白文本写回（字形码）** 缺模拟器按键复现（价值 5 / 难度 2）—— 该结构是续作改文本的主入口。
2. **字形段表 / 文本编码** 缺原生定点证据（4 / 2）；且 8 个字符各有两个码位，
   「字符 → 码位」单值映射在字节级无法唯一还原，字节级精确路径是 token 流
   （`tools/text_codec.py::encode_tokens`）。
3. **战斗胜负条件表** 缺模拟器按键复现（5 / 3）+ `0x0202680C` 是否真在计回合未证（4 / 3）。
4. **战斗地图表（场景描述符）** 缺模拟器按键复现（5 / 3）。
5. **12 个基址无效结构** 需要用 `tools/consumer_locate.py` 的邻域探测重新定位真实基址。
6. **剩下的回调派发缺口**（26 L3 + 12 L2 里的其余部分，见 §5.2）——
   「缺一条能进关卡/过场模式的路线」这个说法**作废**：
   派发点就在**剧情战斗**里，入口是 `fn 0x0806DF88` 的门控。
   已经用「把单位槽 + 特性条目 + side 字节写到位」的方式打开了 5 个结构；
   剩下的结构（`fonts` / `items` / `skills` / `resource-pointers` /
   `data-table-a` / `tile-assets` / `ninjutsu-names` / `battle-encounters` /
   `mechanism-effects` / `mission-text` / `sprite-frame-descriptors` /
   `text-writeback`）的读者在**别的子系统**，需要各自的路线路径。
   已知条件：
   * 对象类型 id 必须有效（`0x0853EF30 + id*24` 的 +0x00 非 0，共 21 个有效 id）；
   * 实体类型号（命令字最高字节）必须落在 `0x0853F310` 的 1..13；
   * 门控要 `unit[0] != 0` 且 `unit[0xC0] & 1 == ctrl[10]`
     —— 而 `ctrl[10]` 战斗中是 `0x0E`/`0x0F`，**天然不相等**，
     所以要么改 `ctrl[10]`，要么改单位槽。

> **策略提醒（2026-10-20 反转）**：加固缺口**不是开工前置条件**。
> 按需推进——只为"本次改动涉及的结构"补动态证据。
> 把 L4 当成开工门槛，就是本项目已经付过学费的那个错。
