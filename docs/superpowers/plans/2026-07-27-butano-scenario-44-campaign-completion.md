# Butano 第 44 战完整纵切片实施计划

## 目标

把第 44 战从“加载地图与单位后沿通用胜负条件误判”的演示壳，推进为可由正式战斗控制器自然完成的两阶段战斗：

1. 三名第七班成员按正式角色数据、技能目录、移动与回合规则行动；
2. 先击败卡卡西；
3. 再由任一存活玩家角色在 `(4,3)` 面向下结束行动，取得 `(4,4)` 的铃铛；
4. 只有此时对象槽 1 才清空，既有条件解释器据此判胜；
5. 三名参战者各获得原版实证的 125 EXP，并进入既有升级、修炼、战役保存与第 45 战路由。

## 原版证据约束

- `notes/scenario-44-progression-runtime-20260718.md`
- `artifacts/runtime-checkpoints/scenario-44-progression-evidence.json`
- `notes/battle-objective-transition-bindings-20260723.json`

不可放宽的行为：

- 击败卡卡西本身不能胜利；
- `(3,4)`、`(4,4)` 不能取得铃铛；
- `(4,3)` 但非面向下不能取得铃铛；
- 未击败卡卡西时，即使位置与朝向正确也不能取得铃铛；
- 场景 44 的自然结果是三人各 125 EXP，不包含卡卡西记录中的 100 EXP。

## 复用判断

1. 直接复用现有 `battlefield_object_table` 作为目标对象真值来源。
2. 直接复用生成的 `object_slot_inactive` 胜利条件，不创建第二套胜负引擎。
3. 复用玩家行动的朝向/防御完成边界，在条件解释前原子解析目标交互。
4. 扩展既有 `battle_mission_rules`，用数据描述固定对象、交互点、朝向、前置敌方清空与奖励策略；控制器和回合流不按 battle ID 分支。
5. `battle_objectives.h` 的另一套目标谓词引擎暂不接入，因为生成条件表已经是关卡胜负的权威来源；并存会产生两个不一致的胜负真值。

## TDD 里程碑

### 红

- 使命规则测试要求第 44 战提供对象槽 1、类型 3、坐标 `(4,4)` 与精确交互规则。
- 加载集成测试要求对象在开战前存在；当前实现应失败。
- 行动边界测试覆盖：
  - 普通结束行动不会胜利；
  - 未击败敌人时精确站位也不会胜利；
  - 击败敌人后错误位置/朝向不会胜利；
  - 击败敌人后 `(4,3)` 面向下结束行动才胜利。
- 结果测试要求三名角色的 battle EXP 为 0、总 EXP 为 125。

### 绿

- 给对象表补充显式槽位放置能力。
- 加载 encounter 时按规则原子放置初始目标对象。
- 玩家行动完成前在事务副本中解析目标交互，成功后清空对象槽，再由既有条件解释器判胜。
- 结果预览读取使命奖励策略，场景 44 不计战斗 EXP。

### 重构

- 把目标配置、初始化、交互解析放入独立领域头文件。
- 保持控制器只传递使命规则，不包含第 44 战坐标或 battle ID 判断。
- 重跑对象、条件、回合、场景控制器、结果和战役路线回归。

## 运行时验收

- 主机完整控制器测试自然完成第 44 战并推进到场景 45。
- ARM ROM 构建成功。
- mGBA 脚本从第 44 战冷启动，完成两阶段目标、结果、成长、保存并冷启动第 45 战。
- 所有高开销 mGBA/构建验证经 `tools/run_guarded.py` 执行并保留唯一 run ID 证据。

## 边界

本里程碑建立可供后续关卡复用的“固定场景对象 + 精确行动交互 + 生成条件判胜”架构，并完成第 44 战纵切片。它不声称已经提取所有后续关卡的对象记录，也不以第 44 战规则推断其他关卡。
