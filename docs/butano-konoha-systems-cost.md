# 木叶战记基础系统 Butano 功能等价重建成本预研

## 执行结论

旧版按工程师人周给出的结论不再作为本项目排期依据，**人周估算已取代**。在以下前提下，由当前 Codex 模型单代理内联完成全部基础系统，三点估算为：

> **80.9–121.3–191.2 Codex 连续墙钟小时**（乐观 / 基准 / 保守）

这是模型从读取既有规格、TDD、编码、调试、Butano wiring、构建、回归到文档的实际等待时间，不是 CPU 时间，也不换算成人类工时。

| Codex 可运行强度 | 乐观 | 基准 | 保守 |
|---|---:|---:|---:|
| 8 小时/日 | 10.1 天 | 15.2 天 | 23.9 天 |
| 16 小时/日 | 5.1 天 | 7.6 天 | 11.9 天 |
| 24 小时/日 | 3.4 天 | 5.1 天 | 8.0 天 |

24 小时/日只是数学下限；服务中断、上下文压缩、工具资源锁和人工最终验收都会拉长真实日历。建议管理上采用 **121–191 Codex 小时**，完成第一个真实纵切片后重算。

## 估算口径与功能边界

- 当前逆向资料被当作已给定规格，**不计逆向补证**；AI、公式或章节条件如果资料缺失，补证另行计时。
- 包含当前 Codex 完成设计、红绿重构、实现、集成测试、错误处理、GBA 构建、资源预算检查和维护文档的时间。
- 不包含全篇剧情、所有地图、全角色/技能数值、最终美术、音乐音效内容生产及发行工作。
- 旧存档兼容不在范围内；默认只保证新 Butano 存档版本间迁移。若要求兼容原 ROM 存档，需要另做实测。
- “功能等价”要求玩家入口、规则结果、操作反馈、加载、空状态、错误和数据缺失行为等价，不要求逐帧动画、内存地址、随机序列或原作 bug 一致。

## 当前模型实测样本

六项任务全部由当前 Codex 主代理连续内联执行，没有调用子代理或其他模型。原始 JSON 位于 `build/butano-agent-benchmark-20260721-01/`，持久摘要见 `notes/butano-agent-timing-benchmark-20260721.md`。

| 样本 | 完成物 | 墙钟秒 | 墙钟分钟 | 实际返工 |
|---|---|---:|---:|---|
| B1 | 回合/行动状态机 | 171.651955 | 2.86 | 无 |
| B2 | 地图占位与确定性寻路 | 276.784552 | 4.61 | `assert` 宏与模板逗号冲突 |
| B3 | 事务式技能效果链 | 217.228009 | 3.62 | 无 |
| B4 | 有 step budget 的章节 VM | 296.066437 | 4.93 | `assert` 宏与 initializer list 冲突 |
| B5 | 版本化 CRC 双槽存档 codec | 200.416729 | 3.34 | 无 |
| B6 | 五内核 Butano 自检 ROM 集成 | 598.289769 | 9.97 | 两个 ARM warning；补回归测试后发现并修复未知 effect 被静默接受 |
| **合计** | 1262 行 C++（含测试）及真实 ROM wiring | **1760.437451** | **29.34** | 3 类返工均计入 |

B6 的干净 devkitARM 构建耗时 64.435 秒，ROM header、`run_self_tests` 符号和 `ALL PASS` 文本均由集成测试验证。当前 Homebrew Qt/Cocoa mGBA 无法用于无窗口 debugger 自动画面验收，因此不能把“已构建”表述为“已自动运行画面”。

### Goal 实测：scenario 41 功能等价压力样本

微基准之后，当前 Codex 主模型实际完成了 scenario 41 纵切片。最终全量回归完成后的 Goal 实测为 **28,753 秒（7.9869 小时）**；这包含 TDD、代码、图形与音频资产、ARM 构建、mGBA 双跑、返工和文档，不包含当前仓库已经提供的逆向取证成本。

该样本完成了战前菜单、四回合胜利路线、38 个稳定画面边界、`100/50/0=150` 结算、升级、11 页战后对白、世界地图、5 首阶段音乐和 14 个 UI/战斗事件音效；组合拳 264 帧在真实 mGBA 中达到 **264/264 normalized RGB 一致**。详细证据见 `notes/butano-scenario-41-one-to-one-runtime-20260722.md`。

这是一项比本报告目标更严格的功能等价压力样本：画面采用逐像素黄金帧，音频仍按原 PCM、事件和切换顺序做 Maxmod 功能等价，不要求 MP2K 逐采样一致。它揭示了微基准没有覆盖的成本：GBA 调色板与混合、长音频封装、陈旧 audio backend 缓存、实机路线和跨阶段回归。

用一个 7.7 小时单关直接乘全游戏会重复计算共享引擎，也会漏算 AI、任务目标、存档和内容转换的系统性复杂度。因此总估算仍采用 **80.9 / 121.3 / 191.2 Codex 连续墙钟小时**，推荐规划值仍是 **121–191 小时**。本次实测把 UI、图形演出和音频三项从“纯推断”提升为“有真实纵切片样本”，但不足以支持下调保守档。

## 外推公式

一个“逻辑单元”定义为与 B1–B5 相近的、带边界与错误测试的规则切片；一个“集成单元”定义为与 B6 相近的一次跨层 wiring、交叉编译与回归闭环。

- 逻辑基准 `K = median(B1..B5) = 217.228009 秒 = 0.060341 小时`。
- 慢逻辑基准 `Ks = max(B1..B5) = 296.066437 秒 = 0.082241 小时`。
- 集成基准 `I = B6 = 598.289769 秒 = 0.166192 小时`。
- 13 个系统共拆为 **900 个逻辑单元**和 **160 个集成单元**。
- 乐观：`L × K + W × I`。
- 基准：`乐观 × 1.5`，其中 30% 为跨系统调试、20% 为回归与文档。
- 保守：`(L × Ks + W × I) × 1.9`，其中 60% 为集成/调试、30% 为 GBA 资源与回归储备。

单元数量来自下面逐系统的规则分支、页面/资源 wiring 和验收边界拆分，不是把 29 分钟样本直接乘以 13。

## 分系统依据

### 核心循环与场景

入口是标题页，覆盖新游戏、继续、章节、战斗、结算和返回地图。加载时锁定输入，空存档禁用继续，错误数据回到稳定错误页。主要复用 B1 状态转移和 B6 wiring；50 个逻辑单元覆盖 scene lifecycle、路由、输入上下文和资源释放，14 个集成单元覆盖主要转场。估算 **5.3 / 8.0 / 12.2 Codex 小时**。

### 外围流程与部署

入口是世界地图和任务菜单，玩家查看目标、编队、放置单位并确认开战。空状态说明无可部署单位，阵容或位置非法时保留选择并显示错误。60 个逻辑单元覆盖解锁、任务条件和部署约束，18 个集成单元覆盖页面与战斗入口。估算 **6.6 / 9.9 / 15.1 小时**。

### 章节脚本与对白

入口是章节事件；对白、肖像、选择、flag、等待和战斗触发由 VM 驱动。文本缺失显示可定位占位符，非法 opcode/跳转进入错误状态。B4 已验证 VM 最小骨架；70 个逻辑单元用于完整 opcode、条件和分页，10 个集成单元连接 UI/音频/战斗。估算 **5.9 / 8.8 / 14.1 小时**。

### 地图、碰撞与寻路

入口是战斗地图光标，显示移动范围、路线和不可达反馈；地图为空或尺寸非法时阻止开战。B2 已验证固定容量 Dijkstra、地形成本和占位；80 个逻辑单元覆盖 metatile、动态阻挡、范围和缓存，12 个集成单元连接 BG、光标和行动提交。估算 **6.8 / 10.2 / 16.3 小时**。

### 单位与战斗实例

入口是部署列表和战斗 HUD，展示阵营、HP、查克拉、状态和行动性。角色数据缺失时禁止部署，队伍为空返回任务菜单。50 个逻辑单元覆盖定义、roster、模板、关卡覆盖和实例生命周期，10 个集成单元连接成长、UI、技能和存档。估算 **4.7 / 7.0 / 11.0 小时**。

### 回合与行动状态机

入口是单位选择；移动预览、菜单、目标、方向、提交、取消和敌方阶段必须有确定边界，演出中输入锁定，非法动作给出反馈。B1 只覆盖一个最小闭环；完整系统按 90 个逻辑单元和 16 个集成单元计入反击、MOVEDONE、异步演出和阶段切换。估算 **8.1 / 12.1 / 19.1 小时**。

### 技能、伤害与效果

入口是攻击/忍术菜单，展示范围、消耗、目标和结果；无目标为空状态，资源不足或免疫显示原因。B3 已验证事务效果链；110 个逻辑单元覆盖命中、伤害、状态、范围、反击、联携和召唤，18 个集成单元连接动画、AI、UI 和结算。估算 **9.6 / 14.4 / 22.9 小时**。

### AI 与任务目标

入口是敌方阶段和目标面板；AI 无合法动作时安全待机，目标配置错误不得静默判胜。110 个逻辑单元覆盖候选、评分、寻路、护送/生存/占点/击破谓词和脚本例外，18 个集成单元连接地图、技能、剧情和胜负结算。该项没有直接 AI 样本，误差最高。估算 **9.6 / 14.4 / 22.9 小时**。

### 成长、训练与奖励

入口是战斗结算、角色页和训练菜单；无奖励显示空状态，溢出或错误数据安全截断并记录。55 个逻辑单元覆盖经验、升级、属性、解锁、训练消费和奖励事务，10 个集成单元连接 roster、UI 和存档。估算 **5.0 / 7.5 / 11.8 小时**。

### 存档与恢复

入口是标题页继续和结算保存反馈；无存档建立默认新档，损坏槽回退到上一有效槽。B5 已验证 version、CRC、双槽选择和掉电式恢复；35 个逻辑单元和 8 个集成单元补齐 SRAM IO、迁移和各场景保存点。旧存档兼容排除。估算 **3.4 / 5.2 / 8.0 小时**。

### UI、文本与图形演出

入口覆盖标题、任务、部署、战斗 HUD、对白、结算和角色页；加载、空状态、错误、文字溢出与资源不足都要有安全显示。90 个逻辑单元覆盖 focus、列表、对话框、布局和资源预算，16 个集成单元覆盖主要页面。视觉判断自动化不足，因此保守档更可信。估算 **8.1 / 12.1 / 19.1 小时**。

### 音频转换与播放

入口是场景音乐和操作/战斗 cue；缺音频时继续运行并记错误，通道竞争有稳定优先级。Butano 官方 audio 示例已实编译；35 个逻辑单元覆盖 cue、切换和通道策略，6 个集成单元连接场景与战斗。内容制作排除。估算 **3.1 / 4.7 / 7.4 小时**。

### 内容转换、调试与验收

该系统的用户结果是内容缺失时仍有稳定错误页，而开发者可凭 ID、事件、ROM 哈希和 manifest 定位问题。65 个逻辑单元覆盖 schema、转换、黄金数据和预算检查，4 个集成单元覆盖最终流水线。网页编辑器与批量内容生产排除。估算 **4.6 / 6.9 / 11.4 小时**。

## 里程碑建议

1. **M0 工具链：已完成。** Butano、Docker、离线文档和资产示例已固定并验证。
2. **M1 真实战斗纵切片：已完成首个 7.9869 小时样本。** 当前样本从任务菜单到战后地图；标题、通用部署和真实存档仍归各自基础系统，不把单关完成误写为 M1 全范围完成。
3. **M2 规则覆盖：累计约 70–120 小时。** 第二类差异关卡证明技能、AI、目标和成长可复用。
4. **M3 基础系统完成：累计 80.9–191.2 小时。** 13 个系统通过单元、集成、GBA 资源预算和代表性回归。

## 可信度与使用方式

工具链、C++ 规则内核和 ROM wiring 的样本可信度高；UI、复杂 AI、多场景状态爆炸和长期上下文恢复未被直接测量，因此总工期可信度为中低。121.3 小时是当前最合理的规划基线，不是固定交付承诺。

最有效的校准方式不是增加更多微基准，而是让当前 Codex 真正完成 M1，并用前 10–20 小时的缺陷率、上下文恢复次数和集成吞吐重新计算。若实际基准速度比本次慢 50%，应直接用保守档，不应压缩验收范围。
